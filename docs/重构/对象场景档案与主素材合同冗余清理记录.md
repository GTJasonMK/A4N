# 对象/场景档案与主素材合同 BFS 冗余清理记录

日期：2026-08-12

## 搜索起点与覆盖范围

本专项从对象档案、场景档案和视频主素材三个用户功能入口做广度优先搜索，覆盖以下活跃调用闭包：

```text
ObjectProfilesTab / SceneProfilesTab / ImagesTab / VideoMaterialWorkspace
→ frontend/src/api/{objectProfiles,sceneProfiles,profileMaterials}.ts
→ generated Host contract / apiInvoke
→ Web command dispatch / Tauri invoke_host_command / CLI command manifest
→ a4n-server strict transport parsing
→ a4n-runtime profile record and material actions
→ a4n-orchestrator profile CRUD, conflict handling, prompt generation and material ownership
→ a4n-db object_profile / scene_profile / generated_image / profile_primary_material
→ PostgreSQL constraints and project deletion cascades
```

隐式依赖检查包括：Cargo crate 依赖与模块导出、serde/schemars 动态反序列化、command manifest 字符串调度、Server/Tauri/CLI 命令注册、`OrchestratorContext` 构造注入、档案接口的对象/场景分支、图片 metadata 身份解析、项目删除级联、生成目标映射和 migration 约束。仓库没有该路径对应的 XML、运行时反射、动态代理或 AOP 切面；框架隐式入口由 Host manifest、路由 dispatch、Tauri registry、serde schema 和数据库 migration 覆盖。

生产库只读核对结果：对象档案 53 条，其中 20 条类型或重要性为空、22 条为 `legacy_unknown`；场景档案 35 条，其中 20 条类型或重要性为空、7 条为 `legacy_unknown`；`profile_primary_material` 为 0 条；场景素材图 1 条、对象素材图 0 条。因此空类型、空重要性、`legacy_unknown` 和旧素材 `unknown` 状态仍属于活跃数据合同，没有作为死代码删除。

## 已完成优化

1. 将素材 kind、state、staleness、filter、sort 收敛为 `a4n-domain` 唯一枚举。
2. 删除素材列表的字符串 wildcard 解析，调用链统一传递 Domain 枚举。
3. 删除 nullable kind/filter/sort 合同及其默认分支，调用方必须显式表达查询语义。
4. 删除前端隐藏的 `image_limit_per_profile ?? 12`，限制值由请求合同显式提供。
5. 修复 `stale_first` 复用 `missing_first` 排名的分叉实现，分别保留唯一排序规则。
6. 将对象档案 create/update/delete 收敛为 `a4n-api-contract` typed input。
7. 将场景档案 create/update/delete 收敛为 `a4n-api-contract` typed input。
8. 从对象/场景档案内容 DTO 中删除无业务意义的 `downstream_strategy` 字段。
9. 创建档案不再携带或默认冲突策略；更新、删除在命令边界显式携带 typed strategy。
10. 删除前端默认 `"reject"` 和后端旧字符串策略解析器，避免静默选择冲突处理方式。
11. 删除前端对象/场景 CRUD 的手写 Host 参数形状，统一使用生成合同。
12. 删除严格命令中的重复 `userId`；认证身份只由 Web/Tauri 调度上下文提供。
13. Server 对档案、素材和提示词命令统一使用 strict typed input，拒绝旧拆分字段。
14. Runtime 的对象/场景素材查询统一使用 `ProfileMaterialKind`，删除字符串 kind 分叉。
15. 删除 orchestrator 本地重复的素材输入、输出 DTO，统一复用 API Contract。
16. 将素材排序所需私有字段留在内部 projection，避免泄漏为第二套公开 DTO。
17. 将 `GeneratedImageSummary` 收敛为 API Contract 唯一图片摘要，并由生成器导出前端别名。
18. 将对象/场景图片输入和提示词输出收敛为 API Contract 唯一合同。
19. 为档案、素材、提示词与预览命令补齐 manifest typed schema/result，删除 opaque 合同。
20. 将图片提示词命令收敛为 `read + immediate`，删除 task、secret、task reference 和图片能力元数据。
21. 上传素材的 `prompt_snapshot` 改为必填；缺失合同字段或空字符串均显式失败。
22. 删除上传时缺少快照后现场重建提示词的 fallback，提示词只由前端既有生成路径产生一次。
23. 删除仅服务于该 fallback 的 `ProfileMaterialUploadSource` 包装及场景/对象模型双分支。
24. 增加旧拆分字段、缺省筛选/排序、旧 task metadata 和缺失上传快照的合同拒绝检查。
25. 增加 `stale_first` 与 `missing_first` 行为区分检查，防止两套业务语义再次合并错误。

## 唯一事实标准

- 档案与素材公开输入/输出：`a4n-api-contract`。
- 素材业务枚举：`a4n-domain::profile_material`。
- 档案素材编排、状态与排序：`a4n-orchestrator::profile_material`。
- 图片持久化身份与主素材关系：`a4n-db` 的 generated image metadata 与 `profile_primary_material`。
- 前端类型：`frontend/src/api/generated/host.ts` 生成结果；业务 API 文件只做 ID 规范化和 transport 调用。

不存在为旧参数、缺省策略、缺失提示词或假设中的仓库外消费者保留的兼容、回退或别名路径。
