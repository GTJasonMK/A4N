# 项目导出与文件交付冗余清理记录

## 搜索覆盖范围

本专项从文本项目详情页的 TXT、Markdown、EPUB、PDF、批量导出、大纲 JSON 和角色 JSON 功能出发，按 BFS 追踪：

```text
Frontend ExportPanel / downloadFile
→ generated Host API contract / command manifest
→ Tauri invoke_host_command / CLI generic call / Web command route
→ Server dispatch + task registration + cancellation
→ Runtime export_files permission boundary
→ Orchestrator export application
→ a4n-db project / chapter / outline / profile queries
→ a4n-export-core EPUB / PDF renderer
→ ExportFileData base64
→ browser Blob / download anchor
```

额外横向覆盖：

```text
项目族包 / 派生项目包 / 视频画布包
Galgame WebGAL 包
全量配置 JSON
视频播放 Base64 解码
角色同步 required-task envelope
```

项目族包、视频画布包和 WebGAL 包具有不同数据合同与权限语义，未误合并到正文出版导出。显式依赖覆盖 Rust 调用、模块导入、DTO、Host command 清单、Server dispatch、CLI 通用命令、Tauri 统一分发与前端 API；隐式依赖覆盖 Serde/JSON Schema、任务取消令牌、任务进度事件、协作权限、SeaORM 查询和浏览器 Blob 下载。项目未使用 XML DI、反射、动态代理或 AOP 导出配置。

## 优化记录

1. `BatchExportFormat` 成为批量格式的唯一事实标准，删除 Orchestrator 字符串格式 DTO。
2. 删除 `md`、大小写和首尾空白等旧格式别名归一化逻辑，不保留兼容入口。
3. 删除 `Display` 字符串往返；生产逻辑直接匹配强类型枚举。
4. 将格式展示名和元数据需求收敛到 `BatchExportFormat`，避免 Server/Orchestrator 各自判断。
5. `ExportFileData` 统一复用 API contract，删除 Orchestrator 重复结果 DTO。
6. 删除只在孤立测试中使用的 `ExportMarkdownInput`。
7. 删除批量导出的 `title`/`author` 分叉字段，统一使用 `ExportPublicationMetadata`。
8. 删除 `required_batch_metadata` 二次门禁及旧 metadata rules 模块。
9. 删除 Server 强类型格式转字符串、Orchestrator 再解析的往返转换。
10. 删除 `EPUB_EXPORT_CANCELLED`、`PDF_EXPORT_CANCELLED` 及完全未使用的 `_cancel_message` 参数。
11. 删除 Runtime 七个格式专用 task-scope 包装和宏生成层。
12. 删除 `ExportTaskScope`，任务项目 ID 直接来自已解析的强类型输入。
13. Runtime 权限校验保留为每个 Host action 的唯一入口，删除 Server 注册前的重复权限查询。
14. Runtime 七个 action 收敛为单文件薄 Host 边界，删除六个仅含单次转发的子模块。
15. Runtime action 直接返回 `AppError`，删除七处 `error.to_string()` 再由 Server 包回 `InvalidArgument` 的错误降级。
16. Server 直接保留 `Forbidden`、`NotFound`、`Database`、`Cancelled` 等原始错误分类。
17. 删除 Orchestrator `ExportApplication` 及 context 双层单调用转发。
18. 删除 `ExportChapter.id` 未使用字段。
19. DB 将项目标题与可导出章节收敛为一次 `export_document` 读取，删除独立 TXT/Markdown 查询入口。
20. PDF 不再先查标题、再查项目和章节，避免重复确认同一项目存在。
21. TXT/Markdown 渲染共用 `ExportDocument` 章节集合，不再由 DB 同时拥有查询和格式入口。
22. 批量导出只读取一次项目标题与章节集合，TXT、Markdown、EPUB、PDF 复用同一快照。
23. 批量导出对嵌套 EPUB/PDF 只保留取消检查，不再反复改写外层任务总量。
24. 批量 Web 任务总量按实际格式数计算，删除固定 `4` 的伪进度。
25. 删除 `ExportProgress::progress` 的 `total.max(1)` fallback；所有生产 total 均由正数常量或非空格式数派生。
26. 删除 EPUB/PDF 固定正数进度上的 `checked_sub` 不可达错误分支。
27. JSON 文件包装收敛为一个 `export_json_file_data` 实现。
28. 前端下载合同要求后端标准 `mime_type`，删除可空 MIME 与 octet-stream fallback。
29. 前端 Base64 解码收敛到中立的 `utils/base64`，下载与视频播放复用同一字节转换实现。
30. 删除下载端对 data URL 的兼容拆分；所有生产返回合同均为原始 Base64。
31. 删除只做一次转发的 `downloadBase64File`，项目包和标准导出均复用 Blob owner。
32. required-task Host envelope 拒绝未声明字段；导出和角色同步请求删除重复 `userId`，身份只来自 Web 令牌或 Tauri 外层调用上下文。
33. 角色同步 required-task envelope 显式保留 `runtime_config_snapshot`，不因身份收敛破坏本地 provider 配置传递。
34. 导出项目 ID 校验复用项目层 `ensure_positive_project_id`，删除导出专用重复实现且保留非正数输入的 `InvalidArgument` 语义。
35. 批量格式 schema 明确最多五种规范枚举值，生产校验拒绝重复格式，避免伪造超大数组污染任务进度。
36. 视频播放 MIME 已由强类型合同保证必填，删除遗留的 `video/mp4` fallback。

## 清理后唯一事实标准

```text
Host 输入
→ a4n-api-contract::export 强类型格式、元数据和文件结果
→ Runtime export action 唯一权限校验
→ Orchestrator 唯一出版导出编排
→ a4n-db::export_document 一次读取项目标题与章节快照
→ TXT / Markdown / EPUB / PDF 唯一渲染函数
→ ExportFileData
→ frontend base64ToBytes → Blob → downloadBlob
```

- 批量格式只接受 `txt`、`markdown`、`epub`、`json`、`pdf` 五个规范枚举值。
- Markdown/EPUB 元数据只使用 `ExportPublicationMetadata`。
- 项目导出权限只在 Runtime Host action 校验一次。
- 同一批次的正文出版格式复用一个项目标题/章节快照。
- 项目族包、视频画布包、WebGAL 包继续保持各自业务 owner。
