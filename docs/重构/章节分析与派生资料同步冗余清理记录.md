日期：2026-08-12
编号范围：R-1997～R-2029

## BFS 搜索覆盖范围

1. 前端入口：写作台生成分析、继续同步、生成预览、恢复预览四个动作，以及任务进度、取消、章节列表刷新、章纲刷新和资料档案刷新消费者。
2. 前端 Transport：`apiInvoke`、运行时配置快照注入、Web Bearer 请求、Tauri `invoke_host_command` 桥接和生成 Host 类型。
3. CLI：通用 `a4n call`、command manifest 上下文注入、runtime config 透传和命令路由；四个命令没有第二套专用 CLI 实现。
4. Server：`/commands/{cmd}` 认证、总 dispatcher、章节分析 task/preview 宏、输入 serde、任务 ID 校验、任务注册、进度事件、取消和完成清理。
5. Runtime：生成/恢复 preflight、生成执行、失败后可恢复状态投影、两类请求预览、统一 workflow 恢复入口和 Host port 注入。
6. Orchestrator：章节内容门禁、分析请求构造、分析持久化、对象/角色/场景/章纲派生同步、checkpoint、来源指纹、业务键、恢复资格和终态持久化。
7. DB 与重启恢复：workflow run 的 `active_task_id`、章节作用域、应用重启中断标记和 `chapter_analysis` 可恢复规则。
8. 隐式依赖：command manifest、生成器、Tauri handler、Server 路由表、serde/schemars 注解、workflow kind 字符串、测试与文档。未发现 XML 注册、反射调用、动态代理、AOP 切面或第二套依赖注入容器。

横向核对确认：生成分析和继续同步共享输入、进度与 Host 返回合同，但前者会创建/替换分析，后者只恢复持久化 workflow；两者执行语义不能合并。Server 预检后 Runtime 再预检可覆盖注册任务与真正执行之间的状态/权限变化，未作为重复门禁删除。

## 清理前调用拓扑

```text
WritingDesk 四个动作
  -> 前端手写 { chapter_id } / ChapterAnalysisMutationResult
  -> 四处重复 caller userId + 本地 progress total=100
  -> opaque manifest + 错误的顶层 userId/chapterId context
  -> Server 宏解析 Runtime 手写 GenerateChapterAnalysisInput
       + 无用 success_message
       + 两个仅做返回值转发/投影的 response facade
  -> Runtime 手写结果 DTO + 重复 progress total=100
       + 无调用者 generate_and_sync_chapter_analysis_with_progress
       + prelude 重导出
  -> Orchestrator 分析持久化 / 派生同步 / checkpoint / resume
```

## 清理后调用拓扑

```text
WritingDesk 四个动作
  -> generated ChapterAnalysisInput
  -> generated CHAPTER_ANALYSIS_PROGRESS_TOTAL
  -> Web/Tauri 认证身份 + 可选 taskId + runtime_config_snapshot
  -> strict typed command manifest
  -> Server 直接解析 API Contract
  -> Runtime 返回 generated ChapterSummary / ChapterAnalysisMutationResult
  -> Orchestrator 唯一分析与恢复 workflow
       -> 分析持久化
       -> 派生资料同步
       -> checkpoint / warning / resume
```

## 唯一实现结论

- 四个 Host 命令共享一个严格章节分析输入合同，不再存在 Runtime/前端镜像 DTO。
- 生成结果、恢复结果和进度总量都来自 API Contract；Server 不再维护返回投影分叉。
- 用户身份只来自认证 Transport，章节 ID 只来自 `input.chapter_id`，CLI 不再注入伪顶层 context。
- 章节分析创建与同步恢复仍保留各自真实业务语义，但共同复用同一 Host 合同、任务进度和持久化 workflow owner。
- warning、checkpoint、来源指纹、权限复核和可恢复状态均有活跃数据完整性职责，未被误删。
