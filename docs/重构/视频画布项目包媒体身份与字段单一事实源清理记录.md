# 视频画布项目包媒体身份与字段单一事实源清理记录

## 入口与 BFS 覆盖范围

本专项从“视频画布项目包媒体文件索引”功能入口开始，沿生产调用路径逐层展开：

```text
Host/API 命令
  → Runtime video_studio_api
  → OrchestratorContext::export/import_video_studio_project_validated
  ├─ 导出：DB 画布行 → video_studio_export_media_files
  │       → VideoStudioProjectPackage → ZIP 媒体条目
  └─ 导入：ZIP reader → media payload 校验
          → manifest/owner/bytes 校验
          → DB 画布导入 → 媒体文件 writer

并行生产路径：
项目族包导出/校验/Runtime 解包/DB 媒体资产导入
  → 同一 media_asset.file_path / thumbnail_path 字段合同
```

BFS 逐层检查了以下节点及其显式、隐式依赖：

1. `crates/a4n-api-contract/src/command_manifest.rs` 中的视频画布导入/导出命令，以及 Runtime/Tauri/Server/CLI 的统一分发链；未发现 owner/field 常量的第二份入口。
2. `crates/a4n-runtime/src/actions/project_transfer/video_studio_package/` 的清单读取、媒体字节索引、ZIP 读写与 Host 适配。
3. `crates/a4n-orchestrator/src/context/video_studio_transfer.rs` 的权限、清单校验、事务导入和文件回滚边界。
4. `crates/a4n-orchestrator/src/project/video_studio_package/` 的 manifest 组装、媒体 owner 校验、payload 大小/checksum 校验、实体字段校验。
5. `crates/a4n-db/src/canvas/transfer/` 的生成图片、生成视频、媒体资产写入，节点配置路径 remap，及其 ID 映射和事务编排。
6. `crates/a4n-orchestrator/src/project/family_package/`、`family_transfer.rs`、Runtime family archive payload，以及 `a4n-db/src/project_family_import/` 的并行媒体资产导入链。
7. `a4n-core::models::media::media_asset` 与 `a4n-domain::CanvasNodeRefKind` 的共享合同 owner：前者已拥有 `file_path`/`thumbnail_path` 实体字段，后者已拥有 `generated_image`/`generated_video`/`media_asset` 规范值。
8. Serde 序列化结构、JSON manifest、ZIP entry 路径、模块导入和公开 re-export；未发现 XML、依赖注入容器、反射、动态代理或 AOP 配置参与该功能。

搜索覆盖使用 `rg` 检查了仓库源码、前端、脚本、文档与配置（排除生成的 `target/` 和 `node_modules/`），重点模式包括：

- `MEDIA_OWNER_*`、`MEDIA_FIELD_*`、`MEDIA_FILE_FIELD_*`
- `owner_kind`、`file_path`、`thumbnail_path`
- `VideoStudioMediaFileEntry`、`media_file_key`
- `video_studio_project`、`read_media_payloads_from_entries`

## 发现的冗余

- `a4n-db` 画布导入和 `a4n-orchestrator` 视频画布包各自声明同一组 owner 字符串。
- 视频画布包、项目族包、项目包规则和若干导入/remap 路径各自声明或直接写入同一组媒体字段字符串。
- Runtime 仅为测试转发的 `MEDIA_FIELD_FILE`、`MEDIA_OWNER_MEDIA_ASSET` 是无业务价值的二次别名。

## 已执行清理

1. 在 `a4n-core::models::media::media_asset` 建立 `FILE_PATH_FIELD` 与 `THUMBNAIL_PATH_FIELD` 唯一字段事实源；项目族包、视频画布包、DB 导入、节点 remap 和 Runtime family payload 均改为引用它们。
2. 删除 `a4n-db::canvas::transfer` 与视频画布包模块的重复 owner 常量。
3. 视频画布 owner 校验改用既有 `CanvasNodeRefKind` 解析和 `as_str()`，删除字符串 owner 的第二套身份实现。
4. 删除 `a4n-orchestrator::project`、family package 和 Runtime 中无消费者的字段/owner re-export 与测试别名；视频包 Runtime 的 mode/version 测试别名也直接移除。
5. 保持所有外部合同值不变；未新增兼容、默认、回退、吞错或占位逻辑。

补充清理：Runtime 的 `VideoStudioMediaFileEntry` 仅供 ZIP 测试构造，生产路径没有消费者；测试改为直接引用 Orchestrator 合同类型，删除 Runtime 测试专用转发别名。

补充清理：`a4n-db::media::bindings` 删除生成图片/视频 target 字符串常量，统一使用 `CanvasNodeRefKind` 的规范值。

## 未误合并的内容

`file`/`thumbnail` 是 ZIP 内部路径片段，仍与实体字段 `file_path`/`thumbnail_path` 分开；`generated_image_prompt:` 等提示词节点身份、媒体绑定 target kind 和错误消息标签也保持各自合同，未因字符串相似而强行合并。
