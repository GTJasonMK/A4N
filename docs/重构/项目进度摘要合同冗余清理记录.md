# 项目进度摘要合同 BFS 冗余清理记录

日期：2026-08-13

## 搜索起点与覆盖范围

本专项从“项目列表显示各项目族进度”和“文本项目详情页显示章节进度”两项生产功能出发，按广度优先顺序追踪完整调用闭包：

```text
ProjectLists / NovelDetail / ProjectOverviewCard
→ frontend 项目 API 与 generated Host contract
→ Web / Tauri / CLI 共用 Host commands
→ a4n-runtime project_records summaries
→ a4n-orchestrator project_read
→ a4n-db project/progress
→ text / comic / video / freeform / galgame 进度投影
→ novel_project / chapter_manga_prompt / chapter_video_prompt / generated_video
→ workflow_run / galgame_script / galgame_scene / galgame_line
```

横向覆盖以下活跃路径：

```text
项目列表与单项目详情查询
文本项目状态与章节目标
漫画页面提示词及 manga_pipeline
章节视频提示词、当前视频记录和失败记录去重
自由画布视频生成、裁剪与组装产物
Galgame 剧本、场景、台词和 galgame_pipeline
项目摘要的单查、批查、Host 序列化和前端展示
```

显式依赖覆盖 Rust/TypeScript 调用、模块导入和 `pub use` 链、SeaORM 查询、Serde/JsonSchema 及生成 TypeScript。隐式依赖覆盖 Host command manifest、Web/Tauri/CLI 字符串调度、AppState/OrchestratorContext/DbHandle 注入、workflow kind、视频 `video_type/workflow_mode`、项目族/source mode 组合、数据库状态字符串和前端 tooltip。

仓库不存在该功能相关的 XML DI、运行时反射注册、动态代理或 AOP 切面；框架入口均由 Host manifest、共用 dispatcher、生成合同和显式 context 注入覆盖。CLI 没有独立的项目进度实现，直接复用 `list_projects/get_project`。

## 生产数据与写入链核验

通过开发库只读查询及活跃写入链核对：

```text
project_kind: text=47, comic=1, video=2, galgame=1
source_mode: self=47, derived=4
项目族、source_mode、项目状态均为 canonical 值
文本 current_chapter/target_chapters 无负数
文本 current_chapter 无超过 target_chapters 的记录
```

自由画布当前无生产项目，但写入链确认进度相关的持久化视频类型为：

```text
canvas_video
trimmed_clip        （workflow_mode=canvas_trim）
canvas_assembly
```

旧查询错误地把 `canvas_reference_media`、`canvas_trim` 当成 `video_type`，会漏掉真实 `trimmed_clip`；现已按持久化事实修正。

## 已完成优化

1. 将领域 `ProjectProgressSummary` 收敛为前端实际消费的 `label + detail` 最小合同。
2. 删除全仓无人消费的 `ProjectProgressStatus` 枚举。
3. 删除进度摘要的 `kind` 字段；项目摘要已有强类型 `project_kind`。
4. 删除进度摘要的 `stage` 字段；无生产消费者或业务分支使用。
5. 删除进度摘要的 `current/total` 字段；各项目族只保留可展示的 detail。
6. 删除进度摘要的 `status` 字段及所有重复状态映射。
7. 删除 a4n-db 内第二份 `ProjectProgressSummary` DTO，直接复用领域/Host 合同。
8. 删除 Runtime 的 `contract_progress_summary` 逐枚举适配器，DB、Orchestrator、Runtime、Host 传递同一类型。
9. 删除 API 生成器中的旧状态枚举导入与 TypeScript 生成项。
10. 重新生成 Host TypeScript，删除旧枚举和五个退役字段。
11. `ProjectProgressQuery.project_kind` 改为领域 `ProjectKind`，删除查询分派中的字符串匹配和未知项目族 fallback。
12. `ProjectProgressQuery.status` 改为领域 `ProjectStatus`，文本进度复用唯一中文 Display 映射。
13. 从持久化项目构造进度查询时严格解析项目族，未知值显式失败。
14. 严格解析项目状态，删除“未知状态”伪摘要。
15. 严格校验 source mode，只接受 `self/derived/freeform`。
16. 严格校验项目族与 source mode 组合，只允许 `text/self`、非文本 `derived` 和 `video/freeform`。
17. 拒绝负 `current_chapter/target_chapters`，不再用 `.max(0)`伪造合法进度。
18. 批量进度查询拒绝重复 project ID，删除 HashMap 最后写入覆盖语义。
19. `ProgressCounts::add` 改为显式 `Result`，未知提示词或视频状态不再静默忽略。
20. 状态计数删除 `trim` 兼容；持久化状态必须精确等于 canonical 值。
21. 将 `interrupted` 显式归入失败计数，不再因未匹配而消失。
22. workflow_run 状态解析删除通配忽略；未知持久化状态直接失败。
23. workflow_run 明确识别 completed/superseded 为非活跃终态。
24. 漫画、章节视频和自由画布的视频状态均在同一共享计数边界严格校验。
25. 视频事实聚合改为返回 `Result`，非法提示词或视频记录不能生成假摘要。
26. 修正自由画布视频类型为 `canvas_video/trimmed_clip/canvas_assembly`。
27. 添加最小回归锁定自由画布持久化视频类型，防止再把 workflow mode 当 video type。
28. 删除只服务退役 `total` 字段的自由画布图节点聚合 SQL、查询 DTO和数据库往返。

33. `ProjectOverviewCard` 章节总数唯一读取 `project.target_chapters`。
34. 删除前端 `target_chapters → total_chapters → progress.total → blueprint.total_chapters → 0` 五级 fallback。
35. 删除测试中对退役字段和状态枚举的断言，只锁定真实展示合同。
36. 添加持久化项目族、source mode、章节值和 workflow 状态的最小严格性回归。

## 清理后唯一事实标准

```text
项目族与项目状态
→ a4n_domain::project::{ProjectKind, ProjectStatus}

Host 项目进度展示合同
→ a4n_domain::project::ProjectProgressSummary

项目进度查询与各项目族投影
→ a4n-db::project::progress

项目状态中文标签
→ ProjectStatus::Display

自由画布视频进度类型
→ generated_video.video_type 的 canvas_video / trimmed_clip / canvas_assembly

文本章节目标
→ novel_project.target_chapters
```

DB、Orchestrator 和 Runtime 只保留必要的查询、错误和传输边界，不再复制 Host DTO、状态枚举、项目状态文案或章节总数 fallback。

## 明确保留的活跃边界

- `detail` 保留为可选展示文本；它承载页面/视频完成数和流水线消息，不是结构化业务状态。
- 漫画与 Galgame 的 workflow_run 状态仍优先于静态产物计数，用于展示正在运行、失败或取消的活跃执行路径。
- 章节视频保留“当前提示词/最新视频”去重和陈旧失败记录识别；它们防止历史记录污染当前进度，不是兼容层。
- 视频提示词中的 pending、视频记录中的 running，以及漫画提示词中的 generating 是各自持久化合同的现行状态，统一投影但不改写源数据。
- 单查与批查仍分别服务详情和列表；二者共用同一 DB 批量实现，没有第二套业务规则。
- 前端 `Math.min(100, ...)` 仅限制进度条视觉宽度；持久化值的合法性由读取边界负责。
