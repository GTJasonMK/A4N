# 认证用户资料更新合同分叉清理记录

日期：2026-08-12
编号范围：R-1637～R-1657

## BFS 搜索覆盖范围

从“当前登录用户更新邮箱或头像”功能入口逐层广度优先展开：

1. 前端入口：`AccountPanels.tsx::ProfileEditor`、`api/auth.ts::updateUserProfile`、生成的 `UpdateProfileInput`、`apiInvoke` 的 Web/Tauri 传输选择以及 Tauri 通用 Host dispatcher。
2. CLI 入口：`auth update-profile` 的 Clap 参数、专用请求构造、通用 `a4n call` 的 command manifest 上下文字段注入及认证会话请求。
3. Host 注册：API command manifest、生成的 Host 命令清单、Tauri command registry、`invoke_host_command`、Server `/commands/{cmd}` 路由和字符串 dispatcher。
4. 应用链路：Server 从认证上下文取得用户 ID，Runtime 校验 Patch，Orchestrator 持有唯一资料更新方法，DB `auth::update_profile` 完成活跃用户检查、邮箱规范化/唯一性校验和头像三态写入。
5. 隐式依赖：Serde 缺失/null 解析、Schemars JSON Schema、Rust 到 TypeScript 生成器、Tauri command 宏、Clap 参数关系、Axum Bearer 认证、动态命令字符串和前端本地认证状态。
6. 生产分支：Web Bearer 用户、Tauri 当前本地用户、CLI 已登录用户；邮箱更新、头像设置、头像显式清空、空 Patch、重复邮箱、非法邮箱和禁用用户。

搜索未发现该功能使用 XML、反射注册、动态代理、AOP 切面或依赖注入容器配置。认证链没有接口/抽象类的第二实现；Web、Tauri 和 CLI 最终均进入同一个 Server dispatcher、Runtime、Orchestrator 和 DB 更新实现。

## 优化记录

- R-1637：完成 UI、CLI、Host、Runtime、Orchestrator、DB 及生成合同的全链 BFS，确认原实现存在双身份、双 Host 和 nullable 邮箱伪能力。
- R-1638：将唯一 Host DTO 的 `email` 从 `Option<Option<String>>` 收敛为 `Option<String>`，显式 `null` 直接拒绝。
- R-1639：邮箱字段复用 API Contract 的 non-null 更新解析器，不再由应用层二次转换 nullable 语义。
- R-1640：保留头像“缺失/清空/设置”三态，并在生成 Schema 中明确其唯一可空合同。
- R-1641：为资料 Patch 增加 `is_empty`，Runtime 在访问数据库前拒绝无效果请求，避免空 Patch 仍更新时间并写库。
- R-1642：删除 Orchestrator 的 `profile_email_update` 邮箱适配规则。
- R-1643：删除 Orchestrator 私有 nullable Serde 解析器及公共重导出，更新字段解析只由 API Contract 持有。
- R-1644：删除 `update_own_user_profile` 中间层；调用目标已固定为认证用户，不再保留 caller/target 双参数门禁。
- R-1645：删除 Orchestrator 第二个公开实现块中的 `user_sessions`、`revoke_user_session`、`update_user_profile`、`change_user_password` 四个无调用绕过包装器。
- R-1646：Runtime 将 `update_user_profile_for_user` 收敛为唯一 `update_user_profile`，只接收一个认证用户 ID。
- R-1647：Server 不再读取请求体 `userId`，资料更新目标只来自已认证上下文。
- R-1648：command manifest 将 `update_user_profile` 的上下文字段从 `userId` 改为空，CLI 通用调用不再注入第二身份。
- R-1649：删除 Tauri 专用 `update_user_profile` 命令及 registry 注册，桌面端统一进入通用 Host dispatcher。
- R-1650：前端 `runtimeInvoke` 不再把资料更新列为原生命令，Web/Tauri 共用同一业务分发路径。
- R-1651：前端 `updateUserProfile` 删除 `userId` 参数和请求字段，只发送唯一 `input`。
- R-1652：资料编辑 UI 邮箱始终发送 trim 后字符串，空邮箱由唯一业务校验显式失败，不再转成兼容性 `null`。
- R-1653：删除 CLI 必然失败的 `--clear-email` 伪功能及帮助文本。
- R-1654：删除 CLI 只为 nullable 更新构造存在的 `optional_update`、`insert_nullable_update` 辅助函数。
- R-1655：CLI 更新资料不再额外查询当前用户，也不再发送请求体 `userId`。
- R-1656：重新生成前端 `UpdateProfileInput`，邮箱类型从 `string | null` 收敛为 `string`。
- R-1657：合同、manifest 与前端传输测试固定“认证身份唯一、邮箱不可 null、头像可显式清空、专用 Tauri 路径不回归”。

## 唯一实现结论

- Host DTO：`a4n_api_contract::auth::UpdateProfileInput`。
- 身份来源：Server/Web 使用认证令牌用户；Tauri dispatcher 使用当前登录用户；业务请求体不再携带目标用户 ID。
- Host 路径：前端业务统一经 `invoke_host_command`/Server dispatcher，Tauri 不再有资料更新专用命令。
- 应用实现：`a4n_runtime::actions::auth_records::update_user_profile` → `OrchestratorContext::update_user_profile` → `a4n_db::auth::update_profile`。
- 更新语义：邮箱仅“缺失/值”两态；头像仅“缺失/显式清空/值”三态；空 Patch 明确失败。
