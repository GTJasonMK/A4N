日期：2026-08-12

## BFS 搜索覆盖范围

1. 前端入口：`ScenesDialog` 的场景列表、编辑、删除、上下移动、生成和请求预览，以及进度轮询、取消、刷新和编辑表单消费者。
2. 前端 Transport：`apiInvoke`、Web Bearer 请求、Tauri `invoke_host_command` 通用桥接、runtime config 快照注入和生成 Host 类型。
3. CLI：通用 `a4n call`、command manifest 上下文注入与 runtime config 透传；六个场景命令没有第二套专用 CLI 实现。
4. Server：总 dispatcher、章节场景路由、serde 输入解析、任务 ID 校验、任务注册、进度事件和完成清理。
5. Runtime：场景记录投影、生成 preflight、生成执行和请求预览适配。
6. Orchestrator：Editor 权限、章节读取、更新规则、重排权限作用域、提示词上下文、LLM 请求、workflow/checkpoint 和生成结果落库。
7. DB：场景查询、更新、删除、重排、生成保存，以及空排序、非法编号、跨章节、重复场景和重复序号的显式拒绝路径。
8. 隐式依赖：command manifest、TypeScript 生成器、DTO inventory、Tauri 通用 handler、Server 路由表、serde/schemars 注解、prompt registry、workflow kind/call key、测试与文档。未发现 XML 注册、反射调用、动态代理、AOP 切面或第二套依赖注入容器。

横向核对确认：场景资料档案同步、章节场景正文记录和拍摄脚本场景服务于不同业务对象，不是可合并实现；本专项只收敛章节场景记录与生成这一条业务链。生成任务的 `taskId`、workflow checkpoint、模型截断错误和注册任务前/真正执行前的双重权限与输入复核均有活跃职责，未作为伪安全冗余删除。


## 清理后调用拓扑

```text
ScenesDialog 六个动作
  -> generated ChapterSceneSummary / Generate / Update / Reorder contracts
  -> generated CHAPTER_SCENE_PROGRESS_TOTAL
  -> Web/Tauri 认证身份 + 可选 taskId + runtime_config_snapshot
  -> strict typed command manifest
  -> Server 直接解析 API Contract + to_value
  -> Runtime 仅做 Host 生命周期适配和模型投影
  -> Orchestrator 唯一权限、更新、重排与生成 owner
       -> DB 严格记录/重排边界
       -> prompt + workflow + checkpoint + LLM + 落库
```

## 唯一实现结论

- 场景 Host 输入、响应摘要、进度常量和前端类型只来自 `a4n-api-contract::chapter`。
- Runtime 不再拥有场景合同模块；Orchestrator 不再拥有 Host 镜像 DTO、固定 task scope 或更新 patch。
- 空重排只有 DB 的显式拒绝语义，不再存在 scope `None`、空结果数组或前置 no-op 三套分叉。
- 用户身份只来自认证 Transport；生成/预览的章节 ID 只来自严格 `input.chapter_id`。
- 场景生成只有一个 prompt/workflow/checkpoint/落库实现，场景管理只有一个更新规则和一个 DB 重排实现。
