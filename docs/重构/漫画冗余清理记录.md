日期：2026-08-10

## 搜索起点与覆盖范围

以“章节漫画页提示词生成、展示、优化和成图”为功能起点，按广度优先顺序检查：

1. Host 入口：API command manifest、Tauri command registry、Server dispatch、CLI 等价入口、前端 `apiInvoke`。
2. Runtime 与 application：漫画流水线启动/预览、页面提示词列表、状态、取消、编辑、优化、删除、页面图片生成。
3. Orchestrator：七阶段调用、Prompt 渲染、上下文组装、workflow run/checkpoint/progress、取消/恢复、输出持久化、生成 trace。
4. DB：SeaORM entity、页面记录查询/更新、同步事务、workflow 状态与断点、资产谱系、依赖图、项目进度、生成目标反链。
5. 隐式依赖：Serde/Schemars 生成合同、SeaORM schema、PostgreSQL baseline 与 migration 注册顺序、prompt registry `used_by`、前端生成类型和测试夹具。
6. 横向与历史检查：全仓 Rust/TypeScript/YAML/Markdown/脚本引用、Git 引入历史、旧图片生成路径和生产读取者。
7. 单页提示词优化专项：前端优化按钮、Host/Tauri/Server 路由、Runtime action、Orchestrator 请求与落库、动态 LLM 上下文规划、通用 workflow/checkpoint、LLM trace、prompt registry。
8. 流水线阶段启动专项：前端阶段选择与请求预览、Serde/Schemars 输入合同、Tauri/Web Host 参数链、Runtime action、Orchestrator fresh/resume workflow 选择、七阶段 checkpoint 恢复条件和进度阶段枚举。
9. 漫画页成图专项：前端成图/预览按钮与参考图面板、统一图片任务入口、Tauri/Web 预览、Runtime image action、Orchestrator page request preparation/provider request/post-commit、页面绑定 JSON、生成 trace、DB 页面提示词与旧成图清理。
10. 漫画角色参考图绑定专项：前端候选素材与绑定面板、生成 Host 合同、Tauri/Web 路由、Runtime action、Orchestrator 权限/下游冲突、DB 素材范围校验、页面 layout 更新、成图读取、生成 trace 与迁移数据。

排除 `target/` 和前端构建产物；仓库中没有与本功能相关的 XML、反射注册、动态代理或 AOP 切面。

## 活跃调用拓扑

```text
start/preview manga pipeline
  -> runtime manga actions
  -> OrchestratorContext manga application
  -> workflow_run(manga_pipeline) as status/progress/cancellation authority
  -> seven typed LLM stages
  -> workflow_checkpoint per completed LLM call
  -> MangaPagePlanV3 + MangaPageDrawingPromptV2
  -> one MangaPagePromptDraft per page
  -> sync_manga_page_prompts_by_chapter
  -> chapter_manga_prompt(page_generation)
  -> generation trace + canonical asset lineage

list_manga_page_prompts
  -> DB page_generation query
  -> runtime MangaPagePromptSummary projection
  -> frontend page prompt model/list
  -> direct page image preview/generation

edit/optimize/delete page prompt
  -> required page_generation lookup
  -> downstream image conflict rule
  -> one page prompt mutation path

get/cancel/resume manga pipeline
  -> latest manga_pipeline workflow_run for chapter
  -> workflow progress/current_step projection
  -> completed workflow_checkpoint fingerprint validation
  -> no chapter_manga_prompt pipeline_status pseudo row

fresh manga pipeline start/preview
  -> never bind an older workflow_run
  -> execute/preview all seven stages from the current source

resume manga pipeline start/preview
  -> require one fingerprint-matching resumable workflow_run
  -> restore every completed stage checkpoint in call order

optimize manga page prompt
  -> runtime manga record action
  -> permission/source/downstream-conflict validation
  -> one system+user ChatRequest with strict JSON response
  -> LLM usage/call trace (no dedicated workflow/checkpoint)
  -> update chapter_manga_prompt.image_prompt
  -> delete explicitly approved downstream image

generate/preview manga page image
  -> one page_generation record for current chapter source
  -> strict reference_bindings contract
  -> every required slot must own bound_asset
  -> shared image generation workflow/provider execution
  -> bind new generated image and remove the previous page image

bind manga character reference image
  -> one character_name in the page reference binding
  -> Tauri/Web Host command
  -> Runtime manga record action
  -> Orchestrator permission/source/downstream-conflict validation
  -> DB project-family asset scope validation
  -> typed MangaBoundReferenceAsset
  -> update the existing character binding only
  -> delete explicitly approved downstream image
```

已确认 `MangaPageV3.panels` 的唯一持久化来源是 `page_generation.layout.page_plan`；独立 `panel_plan` 行没有生产读取者。

## 数据库迁移

新增不可逆迁移 `manga_page_prompt_contract_cleanup`：

- 删除无成图、无 generation spec 的所有非 `page_generation` 旧记录，包括 `panel_plan` 与 `pipeline_status`。
- 对规范记录按“有成图优先、更新时间、ID”清理安全重复行。
- 删除三列格级遗留字段。
- 增加规范身份 CHECK：仅允许 `page_generation/page_number>0`。
- 增加 `(project_id, chapter_id, page_number)` 唯一索引。
- 如果旧记录仍绑定成图/生成意图，或重复页分别绑定不同成图/生成意图，迁移直接失败，要求人工解决，不静默丢数据。

新增不可逆迁移 `manga_reference_binding_contract_cleanup`：

- 要求所有规范页面的 `reference_bindings` 为数组、每项为对象。
- 要求旧 `status` 只能是 `missing/bound`，并与 `bound_asset` 的缺失/存在严格一致；不一致时迁移失败。
- 审计通过后按原顺序删除每个绑定对象的 `status`，不保留运行时兼容解析。

新增不可逆迁移 `manga_reference_binding_payload_cleanup`：

- 要求旧绑定仅包含已知角色绑定字段，且 target、required、purpose、slot/label 身份满足当前生产合同。
- 要求已绑定素材至少具有合法 kind、正整数资产 ID 和非空图片路径；未知字段或身份冲突时迁移失败。
- 将每项绑定收敛为 `character_name + bound_asset`，其中素材只保留 `asset_kind/asset_id/image_path`。

## 当前事实标准

同一章节漫画业务只保留一套实现：七阶段产出 typed page plan，数据库每页只保存一条 `page_generation`，页面计划中的 `panels` 是格信息唯一事实来源；流水线状态、进度、取消和恢复只由 `workflow_run/workflow_checkpoint` 持有，前端状态 API 仅做投影；新运行必定从头执行，只有显式续传可以读取当前有效 workflow 的 completed checkpoint；每个角色参考图只由 `character_name + bound_asset(asset_kind/asset_id/image_path)` 表达，任一角色未绑定时预览和成图均明确失败。
