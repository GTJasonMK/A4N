# 任务队列与工作流监控 BFS 冗余清理记录

日期：2026-08-12
编号范围：R-2070～R-2103

## BFS 搜索覆盖范围

本专项从以下活跃功能入口开始，按调用边逐层扩展，直到 Host、CLI、前端、运行时、编排、持久化和生成协议均闭合：

1. 前端入口：`QueueTab`、`QueueStatsGrid`、`TaskHistoryPanel`、`ActiveWorkflowsPanel`、`WorkflowRunsPanel`、`VideoStudioCanvas`、画布工作流面板、章节资料导入恢复、视频片段规划恢复，以及所有通过 `useProgressTask` 传入 Host workflow 取消函数的页面。
2. 前端 Transport：`frontend/src/api/task.ts`、`streaming.ts`、`progress.ts`、认证 token/session、`apiInvoke`、Web command body、Tauri 通用 Host bridge、生成类型和浏览器 harness。
3. CLI：`workflow list/show/events/watch/resume/cancel`、通用 `invoke_host`、命令 manifest 上下文注入、当前用户绑定路径和 CLI E2E 请求序列。
4. Server：command dispatcher、`workflow_task.rs`、输入解析 helper、空参数校验、统一响应序列化和认证 `user_id` 来源。
5. Runtime：`task_records` 的取消、队列统计、历史任务、活跃工作流、运行列表、运行详情、进度事件、恢复和取消工作流路径；内存 `TaskHandle`、持久化任务记录、工作流 run/checkpoint/generation run 查询。
6. Orchestrator/DB：工作流查询输入、摘要投影、权限源字段、进度事件持久化、任务快照合并、恢复分发、取消协调和 DB 查询默认值/边界校验。
7. 隐式依赖：`command_manifest.rs`、`generate_types.rs`、Host DTO inventory、serde/schemars 注解、路由 dispatcher、任务句柄注册/完成清理、workflow active task 关联、checkpoint 和生成调用记录。未发现 XML 注册、反射调用、动态代理、AOP 切面或第二套 DI 容器。

## 清理前调用拓扑

```text
QueueTab / useProgressTask / Canvas / WritingDesk / ImportsTab
  -> task.ts / streaming.ts / progress.ts
  -> Web/Tauri 通用桥接 + 手写 WorkflowRun* DTO
  -> 伪 userId + opaque manifest
  -> Server 手工拆 task/workflow 参数
  -> Runtime task_records/contracts.rs（9 个 Host DTO）
       -> Core/API/DB 三套进度与工作流摘要定义
       -> Runtime 多余 percent、updated_at、project_id、progress_events 等响应字段
  -> active workflow 先投影、再用响应字段做权限过滤
  -> Orchestrator DB workflow summaries / task records / checkpoints
  -> CLI workflow 同样手工获取用户并发送 userId
```

横向对比结论：普通队列任务取消与工作流协调取消具有不同状态语义，不能合并；内存 task handle 的 `stream_text` 是活体信号，持久化查询不能伪造；`list_active_workflows` 必须合并持久化运行任务与内存快照并按 `task_id` 去重；DB 内部可选查询输入服务大量内部流程，保留在 DB 层，不让 Host 合同反向污染 DB。

## 清理后调用拓扑

```text
QueueTab / useProgressTask / Canvas / WritingDesk / ImportsTab
  -> generated Host Task/Workflow contracts
  -> progress.ts 唯一进度请求 + cancelWorkflowTask 唯一 task 取消适配
  -> Web/Tauri 认证 token + strict typed command manifest
  -> Server 直接解析 API Contract + 显式边界校验 + to_value
  -> Runtime task_records
       -> API 最小任务/活跃工作流投影
       -> DB→API 唯一 workflow run/detail 投影
       -> 权限先于响应投影
  -> Orchestrator 唯一恢复/取消规则
  -> DB 内部查询/事件/checkpoint/生成调用记录
```

## 唯一实现结论

- 后台任务展示进度元数据只有 `a4n-domain::progress` 一套；`a4n-service-protocol` 保留其独立的生成事件协议。
- Host 任务/工作流输入输出只有 `a4n-api-contract` 一套；Runtime 不再拥有 task_records Host 合同文件。
- 前端不再维护工作流 DTO 镜像，CLI/前端均不发送可伪造的 `userId`。
- 活跃工作流权限、任务/快照合并和 task ID 去重只有一个 Runtime 查询入口。
- 工作流取消、普通任务取消、进度查询、恢复查询各自保持唯一且明确的业务语义，不用兼容分支合并不同能力。
