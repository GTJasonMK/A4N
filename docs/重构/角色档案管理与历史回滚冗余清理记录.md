# 角色档案管理与历史回滚 BFS 冗余清理记录

日期：2026-08-12
编号范围：R-2126～R-2169

## BFS 搜索覆盖范围

本专项从角色详情对话框中的“属性事件、行为记录、隐性属性复审、历史快照、删除保护、章节回滚”六类活跃功能出发，按调用边逐层扩展并闭合：

1. 前端入口：`CharacterDetailDialog`、`EventManager`、`ImplicitReviewManager`、`SnapshotManager`、`DeletionManager`、`ManageView` 及其状态刷新回调。
2. 前端 Transport：`frontend/src/api/character/**`、generated Host types、`apiInvoke`、Web dispatcher 与 Tauri 通用动态 Host bridge。
3. Host/CLI：18 个角色记录命令的 command manifest、Server command dispatcher、Tauri 通用命令入口与 CLI manifest/capability 消费路径。
4. Runtime：`character_records`、`character_implicit_review` 的访问控制、输入适配、Host DTO 投影与错误传播。
5. Orchestrator：角色 application context、属性生命周期、隐性复审、profile sync、快照冲突与回滚生命周期、RAG 写后同步。
6. DB：属性事件、行为记录、删除标记、隐性复审决策、快照引用、时间线投影/清理、同步持久化与 PostgreSQL entity/migration。
7. 隐式依赖：serde/schemars 注解、类型生成器、Host DTO inventory、路由表、动态 dispatcher、RAG 生命周期和数据库 schema。未发现 XML、反射注册、动态代理、AOP 切面或第二套依赖注入容器。

覆盖命令：`add_profile_attribute`、`modify_profile_attribute`、`attribute_history`、`list_behaviors`、`get_implicit_review`、`check_implicit_update`、`preview_check_implicit_update_request`、`apply_implicit_update_decision`、`list_snapshots`、`get_profile_state_at_chapter`、`get_snapshot`、`diff_profile_chapters`、`check_profile_sync_conflict`、`rollback_to_chapter`、`list_deletion_marks`、`request_attribute_deletion`、`execute_attribute_deletion`、`reset_deletion_marks`。

## 清理前调用拓扑

```text
CharacterDetailDialog / ManageView
  -> Event / Behavior / ImplicitReview / Snapshot / Deletion managers
  -> frontend handwritten character DTOs
  -> apiInvoke
  -> Web dispatcher / Tauri dynamic bridge / CLI manifest
  -> Runtime duplicated character contract files + projections
  -> Orchestrator duplicated implicit-review DTOs + normalization bridge
  -> DB character modules + duplicated deletion status/threshold names
  -> PostgreSQL / RAG lifecycle
```

生产库只读审计确认：`attribute_event` 29 条、`protagonist_behavior_record` 35 条，二者 `source_kind` 均无空值；删除标记为 0 条；11 条快照引用的 `reference_count` 均为 1。行为类型存在中英文及自由业务值，因此继续保留开放字符串，不建立伪封闭枚举。

Character managers

## 唯一实现结论

- 角色管理 Host DTO 只有 `a4n-api-contract::character` 一套；前端只使用生成类型。
- 属性分类、操作、时间线来源、删除状态、复审决策和删除阈值只有 domain 一套事实。
- 删除标记 Host 投影只有 Runtime 一处；Orchestrator 不再维护第二份 DTO 映射。
- 属性写入与删除持久化校验只有 DB 一处；Host schema 负责 transport 形状，不复制业务规则。
- 删除状态“不过滤”只有显式 `all`；不存在 `null/all` 双语义。
- 行为类型保留开放字符串，避免为真实生产值新增兼容层。
