# 项目复制 BFS 冗余清理记录

日期：2026-08-13

## 搜索起点与覆盖范围

本专项从首页项目卡片的“复制为新项目 / 创建分支”功能出发，按广度优先顺序追踪完整调用闭包：

```text
NovelList / projectActions
→ frontend project API
→ generated Host contract / command manifest
→ Web 字符串 dispatch / Tauri 通用 Host 调度 / CLI manifest 通用调用
→ a4n-runtime project_duplication
→ a4n-orchestrator project duplication application / HostPort / context 注入
→ a4n-db duplicate
   ├─ text：蓝图、分部大纲、章节大纲、章节
   ├─ derived：来源快照、生成意图、媒体、视频片段、装配时间线
   └─ freeform：画布、文本资产、生成意图、图片、视频、媒体图
```

横向覆盖同一业务目的的两条入口：

```text
duplicate_project：完整复制，支持 text / derived / freeform
branch_project：按状态裁剪复制，仅支持 text
```

显式依赖覆盖 TypeScript/Rust 函数调用、变量使用、模块导入、`pub use` 链、SeaORM 查询和事务。隐式依赖覆盖 Serde/JsonSchema、TypeScript 生成器、Host manifest context 注入、Server 字符串路由、Tauri `invoke_host_command`、CLI `command_descriptor`、`OrchestratorContext` 构造注入、项目权限 HostPort、媒体文件副作用与清理 outbox。

仓库不存在该功能相关的 XML DI、运行时反射注册、动态代理或 AOP 切面；框架入口均由 Host manifest、共用 dispatcher、生成合同和显式 context 注入覆盖。

## 唯一实现决策

退役整条 `branch_project` 链，保留 `duplicate_project` 作为唯一项目复制能力。

依据：

- 前端“创建分支”固定传入源项目当前状态，用户不能选择历史状态，实际行为与文本项目完整复制重叠。
- 分支没有持久化身份：新记录沿用原 `root_project_id / parent_project_id / source_snapshot_id`，不存在 branch ID、父分支字段或关系表。
- 分支只支持文本项目，完整复制同时支持 text、derived、freeform。
- 分支写入源项目 owner，协作者触发时新项目仍归原 owner；完整复制正确写入调用者。
- 分支按状态裁剪真实存在的数据，可能丢弃与状态字段不一致但仍属项目事实的产物。
- CLI 可手工传较低 `atStatus`，但该能力未被前端或用户文档暴露，属于旧实现遗留，不保留兼容命令或别名。

## 清理后唯一事实标准

```text
项目复制 Host 能力
→ duplicate_project

项目类型路由
→ a4n_orchestrator::project::resolve_project_duplicate_path

文本项目完整数据图复制
→ a4n_db::project::duplicate_text_project_record

派生项目完整数据图复制
→ a4n_db::project::duplicate_derived_project_record

自由画布完整数据图复制
→ a4n_db::project::duplicate_freeform_project_record

新项目公共字段写入
→ a4n_db::project::duplicate::shared::insert_project_copy_record

媒体文件复制与失败清理
→ ProjectMediaFileCopier / ProjectDuplicationHostPort
```

三种 DB 入口对应三种真实且不同的数据图，不是同一业务能力的分叉实现；外部入口、权限、标题校验、类型路由和返回合同均已收敛到唯一链路。

## 明确保留的活跃边界

- `ProjectDuplicatePath::{Text, Derived, Freeform}` 保留，因为三类项目的数据图和复制事务内容真实不同。
- `ProjectMediaFileCopier` / `ProjectDuplicationHostPort` 保留，因为媒体文件系统副作用和数据库事务分属 Host 与持久层边界，且存在 Runtime 与测试实现。
- 媒体复制失败后的 cleanup outbox 保留；这是防止文件泄漏的数据完整性补偿，不是业务成功回退或兼容路径。
- `raw_blueprint` 与正式蓝图图均被现有生成、导入和展示流程读取；本专项不伪造其中任一来源，而是在复制边界严格拒绝不一致。
- 历史记录 `docs/重构/项目状态推进回退冗余清理记录.md` 中的“创建分支”仅描述当时 BFS 覆盖，不是活跃功能文档，予以保留。
