# 向现有项目导入正文 BFS 冗余清理记录

日期：2026-08-12
编号范围：R-1930～R-1964

## BFS 搜索覆盖范围

从首页“导入正文”和项目详情“导入”页签两个入口出发，按广度优先顺序检查：

1. 前端入口：`ProjectTextImportDialog`、`ImportsTab`、文件选择、审核队列、审核详情、批量接受、导入项目分析、文本去重和资料归纳/反推。
2. 前端 API：上传解析、审核查询与变更、分析进度、取消、请求预览、独立去重与反推接口，以及生成 Host 类型和桶文件导出。
3. Host 合同：command manifest、严格输入/输出 schema、100MB 上传上限、生成 TypeScript、CLI capability 文件输入声明。
4. 动态 Host：Tauri 通用 dispatcher、Web Server dispatcher 与 handler；未发现第二套路由表、专用 Tauri 命令或活跃命令别名。
5. Runtime：文件名、扩展名、Base64、大小和编码边界，TXT/Markdown/EPUB/DOCX 解析适配，审核 DTO 投影和章节分析 HostPort。
6. Orchestrator：Editor 权限、审核批量创建、审核接受/拒绝/删除、导入项目分析、取消与派生资料同步恢复工作流。
7. DB/SeaORM：`import_review_queue`、审核事务、章节写入、行锁、项目章节候选，以及已退役的导入蓝图/卷纲/章纲专属写入模块。
8. PostgreSQL：baseline、migration 注册顺序、旧列、旧状态、旧 JSON 别名、非空约束和状态约束。
9. 解析器：TXT、Markdown、EPUB、DOCX 的章节拆分、文档标题、公开结果字段、归档元数据和测试。
10. 隐式依赖：全仓 Rust/TypeScript/命令字符串、生成文件、测试和文档；未发现 XML、反射注册、动态代理、AOP 切面或额外依赖注入容器配置。

搜索确认 `ImportToolsPanel` 的文本去重、资料归纳/反推及 `check_import_dedup` 是独立活跃能力；审核接受后的派生同步失败恢复工作流用于数据一致性，也继续保留。

## 清理前调用拓扑

```text
选择文件
  -> 前端选择 file_type
  -> import_uploaded_file（第一次 Host 往返）
  -> Runtime 解析并返回章节、编码、总字数、warning、offset、metadata
  -> 前端计算章节 hash、段落“去重”统计和预览
  -> start_import_analysis（第二次 Host 往返）
  -> Orchestrator 创建审核
  -> DB 保存 file_type / encoding / parsed / dedup 等无消费者列

审核页
  -> list_import_queue
  -> get_import_review 再取同一详情
  -> get_import_analysis_status 再取状态统计
  -> accept / modify / update_status / reject 多套变更入口
  -> DB 同时读取 canonical 字段与 modified_* / preview / hash 旧别名

导入项目分析
  -> 逐章分析
  -> 生成章纲
  -> 生成/应用蓝图候选
  -> 生成/应用卷纲候选
  -> 前端候选面板
```

## 清理后调用拓扑

```text
首页 ProjectTextImportDialog / 项目详情 ImportsTab
  -> readFileAsBase64（纯 Base64）
  -> import_project_text_upload（严格 typed input）
  -> Runtime：大小校验 + 扩展名规范化 + 唯一解析器
  -> Orchestrator：Editor 权限 + 章节合同校验
  -> DB：单事务创建 pending 审核
  -> typed ImportReviewSummary[]

审核队列
  -> list_import_queue（列表即详情事实源）
  -> accept_import_review(optional canonical analysis_result)
       -> Orchestrator Editor 权限
       -> DB 行锁 + pending 校验 + 章节写入 + 状态更新事务
       -> 既有派生同步/恢复工作流
  -> reject_import_review / delete_import_review

导入项目分析
  -> 逐章分析与资料同步
  -> 单阶段进度 / 取消

独立工具
  -> check_import_dedup
  -> reverse engineer blueprint / outline / part outline
```

## 唯一实现结论

- 正文上传只有一个命令、一个上传 DTO、一个大小常量、一个文件类型判定位置和一个解析结果合同。
- 审核详情只有队列对象一个事实源；状态只允许由接受、拒绝和修改后接受三个业务动作推进。
- 审核权限只在 Orchestrator，事务和约束只在 DB/PostgreSQL，Runtime 不再复制业务判断。
- 导入项目分析只负责逐章分析和资料同步，不再暗中生成另一套蓝图、卷纲或章纲。
- 不保留旧命令、旧状态、旧列、旧 JSON 别名、data URL 上传兼容或候选 UI 占位。
