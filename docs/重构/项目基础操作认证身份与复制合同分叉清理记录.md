# 项目基础操作认证身份与复制合同分叉清理记录

日期：2026-08-12
编号范围：R-1817～R-1838

## BFS 搜索覆盖范围

承接项目 REST 路径清理，从 11 个基础项目 Host commands 继续逐层广度优先检查身份和参数合同：

1. 前端 API：列表、读取、创建、派生、自由视频项目、源快照章节、更新、删除、生成数据重置、复制与分支。
2. Host manifest：args schema、`x-a4n-context-fields`、项目引用元数据和生成 TypeScript。
3. Web/Tauri：Server handler 的认证 `user_id`、Tauri Host dispatcher 的当前用户注入，以及 args 中额外 `userId` 的实际消费情况。
4. CLI：session context 注入、project 子命令和通用 command routing。
5. Runtime/Orchestrator/DB：项目权限、复制/分支应用输入、家族投影和项目记录写入。
6. 横向合同：`duplicate_project` 的 manifest、Runtime 手写 DTO、前端 inline input 与真实 Server `command_input`。

所有 Server handlers 都只使用认证 transport 提供的 `user_id`，没有读取 args `userId`。`list_source_snapshot_chapters` 实际只需要 `projectId`，原 manifest 却要求 user/chapter/snapshot context；`duplicate_project` 实际读取 `{ input }`，原 manifest 却错误复用删除项目的顶层 `projectId` schema。未发现 XML、反射、动态代理、AOP 或依赖注入容器配置。

## 唯一实现结论

- 用户身份只来自 Web Bearer/Tauri Host dispatcher/CLI session，不进入项目业务参数体。
- 需要目标项目的命令只保留 `projectId`；创建和复制类命令只保留严格 `input`。
- `DuplicateProjectInput` 只在 API Contract 定义一次，Runtime、Server 与生成 TypeScript 共同复用。
- 未增加身份比对 gate、兼容字段、默认补全或回退。
