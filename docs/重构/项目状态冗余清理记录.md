# 项目状态前进与回退 BFS 冗余清理记录

日期：2026-08-11
编号范围：R-1375～R-1408

## 搜索起点与覆盖范围

以“用户打开项目阶段窗口，查看当前阶段与历史，推进状态，预览回退影响并确认回退”为功能起点，按广度优先顺序检查：

1. 前端入口：`StatusMachineDialog`、`status-machine-dialog/*`、`frontend/src/api/project.ts`、生成 Host 类型与 `utils/projectStatus.ts`。
2. Host 动态入口：API command manifest、Tauri command registry 与 `commands/project/status.rs`、Server dispatch/macros/status handler、CLI capability 元数据。
3. Runtime：`actions/project_status` 的状态机、历史、预览、推进、回退、权限与 RAG 清理分支。
4. Orchestrator：`context/project_status.rs`、`project/status/*`、协作权限、项目读取 facade、内部事件总线和 RAG owner。
5. DB：`project/status/*`、`project/rollback_impact/*`、`project_reset/rollback.rs`、标准/Galgame 项目重置、蓝图生成同步和蓝图版本恢复。
6. Domain/Core：`a4n-domain::project::ProjectStatus`、状态历史/状态机/回退预览合同、Core forward/rollback 规则和持久化值解析。
7. 隐式生产者：蓝图生成完成、蓝图版本恢复、项目生成数据重置、项目族重置及全部 `InternalEvent::ProjectStatusChanged` 发布点。
8. 导入与复制边界：文本项目导入、项目分支/复制、项目族包与视频画布包校验，确认外部字符串只在信任边界解析一次。
9. 横向对比：全仓搜索 Runtime 镜像 DTO、字符串状态参数、临时 re-export、重复历史 summary、重复回退影响 summary、文本预览 summary/warning/count helper、旧 `StateValidator` 命名空间和 `draft -> draft` 历史。
10. 框架检查：未发现该功能相关 XML、反射调用、动态代理或 AOP 切面；隐式入口由 command manifest、Tauri registry、Server dispatch、Serde/Schemars 和内部事件覆盖。

## 活跃调用拓扑

```text
StatusMachineDialog
  -> generated Host API
  -> Tauri command / Web dispatch / CLI capability
  -> Runtime project_status transport
  -> Orchestrator user-validated application
       Viewer -> machine / rollback preview
       Editor -> forward
       Owner  -> rollback
  -> DB project row + typed history + artifact facts + rollback impact facts

forward
  -> canonical transition rule
  -> artifact readiness rule
  -> transactional status/history write
  -> typed ProjectStatusChanged event

rollback preview
  -> canonical rollback rule + cleanup action table
  -> DB impact facts
  -> domain ProjectRollbackPreview

rollback
  -> row lock + expected status check
  -> cleanup actions + status/history write
  -> cleanup outbox + typed event + RAG clear

implicit producers
  -> blueprint generation / blueprint restore
  -> text and Galgame generated-data reset
  -> project-family reset event
```

## 生产数据证据

- 使用现有 `a4n-postgres` 容器对开发库 `a4n` 执行只读事务审计；宿主机未安装额外数据库工具，也未修改数据库。
- `novel_project` 共 6 条：4 条 `draft`、2 条 `writing`；按项目类型分布为 comic 1、galgame 1、text 2、video 2。
- `project_status_history` 共 8 条，覆盖 `draft -> blueprint_ready -> part_outlines_ready -> chapter_outlines_ready -> writing` 两组完整前进链。
- 项目当前状态和历史端点均无空值、未知值、自循环；无孤儿历史，所有项目的最新历史目标与当前状态一致。
- 测试库 `a4n_test` 当前无项目和状态历史记录。
- 数据库字段均为非空 varchar，但没有项目状态值 CHECK；本专项不新增第二套数据库状态枚举或无数据迁移必要的兼容逻辑，canonical 值由 domain enum 和所有写入边界共同收敛。

## 当前事实标准

项目状态只保留一套实现：domain `ProjectStatus` 与 domain Host summaries 是合同事实；Core 提供唯一 forward/rollback 规则和持久化解析；Orchestrator 拥有权限、状态机、预览、推进、回退、事件和 RAG 后处理；DB 负责行锁、持久化、历史、回退清理事实和 cleanup outbox；Runtime 仅做 typed Host transport。所有外部字符串只在导入/包校验边界解析，不保留镜像 DTO、字符串业务参数、兼容别名、文本预览 summary、可空影响数量、重复权限、派生发布标记或无变化历史。
