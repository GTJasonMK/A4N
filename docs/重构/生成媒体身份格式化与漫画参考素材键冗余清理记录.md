# 生成媒体身份格式化与漫画参考素材键冗余清理记录

日期：2026-08-15

## 搜索起点与 BFS 覆盖范围

本专项从“生成媒体作为来源/参考素材被保存并展示”这一项业务能力出发，按 BFS 追踪：

```text
生成图片/视频产物
→ media provenance source_external_path
→ 项目依赖图 AssetLineageRecord / AssetLineageRef
→ 漫画参考素材候选与已绑定素材选择器
```

覆盖范围：

- `a4n-db::canvas::artifacts::media::provenance` 的画布图片/视频来源写入。
- Galgame 视觉资产写入 `media_provenance.source_external_path` 的生产入口。
- 项目依赖图中生成图片、生成视频、视频提示词、漫画提示词和角色立绘详情的媒体引用构造。
- 依赖图 builder、node/detail dispatch、`AssetLineageRecord`/`AssetLineageRef` 领域合同及前端依赖图展示消费者。
- 漫画页面的参考素材候选、已绑定素材、选择状态、绑定命令输入和 `MangaReferenceAssetKind` 生成合同。
- SeaORM `media_provenance.source_external_path`、生成媒体记录及 Manga Host API 的序列化边界。
- `rg` 扫描 Rust、TypeScript、Host 合同、脚本、迁移和配置；未发现 XML/YAML/TOML DI、反射、动态代理或 AOP 入口。

## 已完成优化

1. 画布媒体 provenance 写入统一使用 `a4n_domain::GeneratedMediaReference`，删除手工拼接 `generated_image:{id}` / `generated_video:{id}`。
2. Galgame 生成图片 provenance 写入复用同一领域值对象。
3. 项目依赖图所有生成图片/视频节点 ID 和媒体来源引用复用同一领域格式化 owner，删除详情模块内的重复字符串模板。
4. 漫画参考素材候选 key 与已绑定素材 key 统一使用 `mangaReferenceAssetKey`，删除两处独立的 `${asset_kind}:${asset_id}` 拼接。
5. `generated_image_prompt:`、`generated_video_prompt:` 等提示词节点 ID 保持独立合同，不误并入生成媒体身份格式。
6. 删除漫画候选构造中两个已由上下文类型约束保证的冗余 `MangaReferenceAssetKind` 类型断言。
