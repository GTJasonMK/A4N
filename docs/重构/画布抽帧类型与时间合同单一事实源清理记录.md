# 画布抽帧类型与时间合同单一事实源清理记录

日期：2026-08-16

## BFS 搜索覆盖范围

本批从视频画布 `ExtractFrameNode` 功能出发，按生产调用方向逐层覆盖：

```text
前端节点库 / 新节点默认配置 / Inspector / 保存投影
→ canvas_node.config_json 与存量迁移
→ Orchestrator 编辑节点输入构造、运行输入和 generation spec
→ CanvasEditingNodeHostPort 依赖注入及 Runtime 唯一实现
→ Runtime 队列、项目权限、文件路径与媒体落盘
→ Orchestrator 视频归属、源文件、时长、尺寸与记录计划
→ a4n-media 指定时间抽帧 / FFmpeg
→ generated_image 记录、metadata 与 Canvas checkpoint
```

横向检查了章节真实尾帧采集，以确认尾部偏移量只有一个事实源；同时覆盖 Canvas 节点 catalog、边合同、项目包导入导出、迁移注册、crate 依赖和相关测试代码。全仓未发现反射调用、动态代理、AOP、XML 配置或第二个生产 Host Port 实现；旧项目包不再由运行时兼容，导入后若仍含非法合同会显式失败。

## 已执行清理

1. 在 `a4n-domain` 新增唯一 `CanvasFrameKind::{First, Tail, Time}`，提供 canonical serde、`as_str`、`Display` 和严格 `FromStr`。
2. Canvas 节点输入、Host 输入、Orchestrator 计划和 Runtime action 全链改传 typed enum，删除 `String`、clone 和重复字符串解释。
3. `ExtractFrameNode` 只读取必填 `frame_kind`；删除旧键 `kind` 与缺失时默认 `first` 的运行时兼容。
4. 删除 `normalize_canvas_frame_kind` 及 `first_frame`、`last`、`last_frame`、`end`、`key`、`key_frame`、`at_secs` 等运行时别名。
5. 新增一次性 `canvas_extract_frame_contract` 迁移，将存量空配置和旧别名写回 canonical `first/tail/time`，随后删除旧键和非时间模式的遗留 `at_secs`。
6. 迁移对未知抽帧类型、非对象配置及 `time` 模式缺失/非法 `at_secs` 显式失败，不以新默认掩盖脏数据。
7. 新迁移已注册为最后一项 schema requirement；未运行迁移。
8. 前端创建 `ExtractFrameNode` 时显式保存 `{ frame_kind: "first" }`，默认事实只存在于创建阶段。
9. Inspector、节点摘要和拖拽预览删除各自的 `first` 显示回退与硬编码默认副本。
10. `at_secs` 改为严格数字解析；字符串、null 和超出 f32 有限范围的值不再被当成“未提供”。
11. 源视频时长必须为有限正数，删除负时长 `.max(0.0)`。
12. 首帧和尾帧模式携带 `at_secs` 时显式失败，不再静默忽略无关字段。
13. 指定时间模式必须提供有限非负时间，且时间必须严格早于视频结束点。
14. 删除“视频时长后 0.5 秒仍接受”的容差路径。
15. 尾帧偏移统一为 Domain 常量 `VIDEO_TAIL_FRAME_OFFSET_SECS`，Canvas 时间计算和 FFmpeg `-sseof` 共用同一值。
16. 删除任意 `0.12` 秒短视频阈值；时长不超过真实偏移量时明确从 `0` 秒抽取。
17. `a4n-media::extract_video_frame` 删除负时间归零，新增独立 `FfmpegFrameError`，避免缩略图和尾帧调用者出现不可达错误分支。
18. 抽帧执行前严格校验源视频宽高，图片记录删除 `.max(1)` 伪造尺寸。
19. 相关测试代码改用 canonical 类型和值，并保留严格时长、边界和媒体时间错误检查；未执行测试。

未新增运行时默认、兼容、回退或占位逻辑。

## 静态复核

- `rg` 已确认 `normalize_canvas_frame_kind`、旧 `kind` 读取、抽帧输入/计划中的 `frame_kind: String` 和 UI `|| "first"` 无剩余目标链引用。
- `rg` 已确认目标链中的 `duration + 0.5`、`0.12` 阈值、负时间 `.max(0.0)` 和抽帧记录宽高 `.max(1)` 已清零。
- `canvas_frame_timestamp` 只有 Orchestrator 计划入口一个生产调用者；`prepare_canvas_frame_validated` 只有 Runtime 抽帧 action 一个生产调用者。
- `extract_video_frame` 的生产调用仅剩 Runtime Canvas 媒体适配器；章节尾帧继续使用专用 `extract_video_tail_frame`，二者共享唯一尾部偏移常量。
- 存量别名仅存在于一次性迁移和“旧别名必须失败”的合同断言中，不存在于活跃运行路径。
