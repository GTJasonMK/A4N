# A4N 冗余治理

本文件只保留长期有效的治理规则。逐项代码差异、搜索输出和测试日志由 Git 历史、提交说明与测试结果承担，不在文档中维护第二份流水账。

## 目标

- 每项业务规则只有一个 owner。
- 删除无生产消费者的代码、合同、配置和测试夹具。
- 删除只做同名透传的 facade、service、DTO 和 Host 参数重组层。
- 不用兼容别名、隐藏 fallback、默认值或重复校验掩盖迁移未完成。
- 保留安全、权限、输入校验、数据完整性和显式失败路径。

## 事实来源

按以下顺序判断实现是否仍需要存在：

1. 活跃 Host 合同：`a4n-api-contract` command manifest、Tauri registry、Server dispatch 与 CLI capabilities。
2. 前端入口：`frontend/src/api/`、页面调用和浏览器流程。
3. Runtime、orchestrator、DB owner 的真实调用闭包。
4. Sidecar protocol、migration history、脚本和部署配置。
5. 仓库外消费者只有在有明确证据时才算依赖；不为假设消费者保留代码。

Git 历史是“改了什么”的唯一来源；源码和测试是“现在应如何工作”的唯一来源。

## 收敛规则

- 合同、权限、校验、状态机、缓存和 SQL 只能有一个实现位置。
- Host 只解析 transport 输入，不复制业务 DTO 或权限逻辑。
- Runtime 只保留进程生命周期适配；业务编排归 orchestrator owner。
- DB 约束优先由数据库表达，不在多个 application 层重复模拟。
- PostgreSQL baseline 可以复用已注册 migration 的 SQL 常量，不复制合同正文。
- 生成类型优先于手写镜像类型；生成器缺能力时修生成器。
- 测试验证行为和合同，不读取源码后用字符串断言文件形状。
- 只被测试调用的生产 helper 不自动算生产需求；先确认测试是否在验证退役结构。
- 模块文件按真实职责拆分；单纯文件短不构成冗余，只有无语义转发层才应删除。

## 审计入口

- Rust workspace：`cargo metadata --no-deps` 与各 crate `src` 根模块。
- Host parity：`frontend/src/api/`、command manifest、Tauri registry、Server dispatch、CLI capability export。
- 依赖：`cargo machete`，再人工复核 feature、build dependency 和动态入口。
- 文本引用：优先 `rg`，覆盖 Rust、TypeScript、脚本、配置、prompt 和文档。
- 数据库：migration 注册顺序、SeaORM entity、baseline 与 PostgreSQL 约束。

## 最小验证

按变更风险选择最小但真实的验证集：

1. `cargo fmt --all -- --check` 或目标 Rust 文件 `rustfmt`。
2. 受影响 crate 的单测；数据库测试加载 `.env` 中的 `A4N_TEST_DATABASE_URL` 并串行运行。
3. `./scripts/build.sh --check` 或受影响 crate 的 `cargo check`。
4. `cd frontend && npm run test:run`，涉及 Host 合同时追加 `npm run check:web-api-parity`。
5. `git diff --check` 和退役符号残留搜索。

编译被其他工作区改动阻断时，记录首个无关错误；不得写兼容重导出或假成功路径绕过。
