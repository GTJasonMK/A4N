# 认证用户会话列表与撤销合同分叉清理记录

日期：2026-08-12
编号范围：R-1675～R-1698

## BFS 搜索覆盖范围

从“当前登录用户列出和撤销登录会话”功能入口逐层广度优先展开：

1. 前端入口：设置页 `SessionManager`、`api/auth.ts::listSessions`、`apiInvoke` 的 Web/Tauri 传输以及 Tauri 通用 Host dispatcher。
2. CLI 入口：`auth sessions`、`auth revoke-session`、破坏性确认、当前会话撤销后的本地认证清理，以及通用 `a4n call` 对撤销命令的专用入口门禁。
3. Host 注册：API command manifest、生成的 Host 命令清单、Tauri command registry、Server `/commands/{cmd}` 动态 dispatcher 和 Web `/auth/logout` 路由。
4. 应用链路：Server 认证用户 ID、Runtime session actions、Orchestrator AuthApplication、DB `auth::{list_sessions,revoke_session}`。
5. 数据与失败路径：活跃用户检查、正数用户 ID、非空 session ID、用户/会话归属过滤、未撤销且未过期会话列表、已撤销时间写入、当前 CLI 会话撤销后的本地登出。
6. 隐式依赖：Serde/Schemars、Rust 到 TypeScript 生成器、Tauri command 宏、Clap 参数与确认门禁、Axum Bearer 认证、动态命令字符串和 manifest effect/result 元数据。

搜索未发现 XML、反射注册、动态代理、AOP 切面或依赖注入容器配置。BFS 发现 CLI 已按单身份发送空列表参数和仅 session ID 的撤销参数，而 Server 仍强制读取旧 `userId`，导致专用 CLI 路径不可执行；同时活跃的 `revoke_session` 未进入 command manifest。

## 唯一实现结论

- 撤销 DTO：`a4n_api_contract::auth::RevokeSessionInput`。
- 身份来源：只使用 Server/Tauri dispatcher 的认证用户；列表和撤销请求体均不再携带目标用户 ID。
- Host 路径：列表统一经通用 dispatcher；撤销命令由同一 manifest 描述并进入同一 Server dispatcher。
- 应用实现：Runtime `list_sessions`/`revoke_session` → Orchestrator 同名方法 → DB 同名方法。
- Web logout 在本批先复用同一 DTO；后续 R-1699～R-1718 已删除 `/auth/logout` 命令别名，统一直接调用 `revoke_session`。
