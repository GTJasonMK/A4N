# 章节视频请求预览覆盖合同分叉清理记录

日期：2026-08-12
编号范围：R-1616～R-1636

## BFS 搜索覆盖范围

从“预览当前章节视频 provider 请求”功能入口逐层广度优先展开：

1. 前端入口：`useVideoRecordActions.ts` 的脏草稿预览，`api/video/records.ts::previewChapterVideoRequest`，`api/video/types.ts`，生成的 Host TypeScript 合同，以及 `apiInvoke` 的 Web/Tauri 双传输。
2. Host 注册：API command manifest、Server `dispatch/video.rs` 和 `media/video_generation/{preview,input}.rs`；桌面端只通过 Tauri 通用 `invoke_host_command` 转入同一个 Server dispatcher，不存在第二套专用命令。
3. Runtime：`actions/video_generation/{chapter,contracts,provider_host,config_state}.rs`，覆盖 Runtime Host DTO 重导出、配置解析、图片输入预览、sidecar/embedded provider 请求体构造。
4. Orchestrator：`video/chapter_video_generation.rs` 与 `chapter_video_request_rules.rs`，覆盖权限、项目/章节归属、当前片段 recipe、草稿覆盖、参考图、首尾帧/首帧串联/分镜图、provider prompt 渲染和请求体描述。
5. DB 读取：项目协作权限、章节视频提示词、文本项目/视频项目源快照、当前共享片段规划、已生成视频、图片引用及视频配置。预览链只读取持久化记录；覆盖值仅修改内存中的提示词副本，没有更新或写回调用。
6. 隐式依赖：Serde 三态更新字段、Schemars/TypeScript 生成、命令字符串动态分发、Rust trait 实现关系、`A4N_VIDEO_IMAGE_INPUT_TRANSPORT`、runtime config snapshot、sidecar profile 和 embedded provider feature。
7. 生产分支：纯文本、关键帧、首帧串联、分镜图、首尾帧工作流；本地持久化配置、远程用户配置快照、系统默认配置模板；公开 URL 与远端临时媒体上传；New API、OpenAI-compatible、CLIProxy、Gemini Veo、Chat-Completions、Seedance 及 sidecar 请求体。

搜索未发现 XML、反射注册、动态代理或 AOP 切面；生产环境唯一 `ChapterVideoGenerationHostPort` 实现位于 Runtime，另一实现仅用于 Orchestrator 测试。预览专用占位媒体与提示词补全路径仍是活跃的“展示请求结构”业务，不参与真实生成，也未被误判为死代码。

## 优化记录

- R-1616：完成 UI、Host、Runtime、Orchestrator、DB 读取和 provider 分支的全链 BFS，确认该功能活跃且覆盖值不持久化。
- R-1617：在 `a4n-api-contract::video` 建立唯一 `PreviewChapterVideoPromptOverrideInput` Host DTO。
- R-1618：`visual_prompt` 改用统一 non-null 更新字段规则，显式 `null` 不再伪装成“未提供”。
- R-1619：`duration_secs` 改用统一 non-null 更新字段规则，显式 `null` 不再被宽松接受。
- R-1620：`motion_prompt`、`negative_prompt`、`reference_image_ids_json` 统一复用 API Contract 的 nullable 三态解析器，保留业务需要的显式清空语义。
- R-1621：唯一 DTO 启用 `deny_unknown_fields`，删除对未知旧字段的静默兼容。
- R-1622：唯一 DTO 提供 `is_empty`，Host 边界可拒绝无效果覆盖对象。
- R-1623：删除 Orchestrator 中重复的 `PreviewChapterVideoPromptOverrideInput` 定义。
- R-1624：删除 Orchestrator 私有 `deserialize_nullable_update_field` 副本。
- R-1625：删除 Orchestrator 因重复 DTO 遗留的 Serde derive/deserializer 导入。
- R-1626：删除 `video/mod.rs` 对旧 Orchestrator DTO 的公共重导出。
- R-1627：Runtime Host API 直接从 API Contract 重导出唯一 DTO，不再经 Orchestrator 伪装所有权。
- R-1628：Server 不再把顶层 `promptOverride: null` 当成缺失字段。
- R-1629：Server 显式拒绝空 `promptOverride`，避免执行无效果的草稿覆盖提示路径。
- R-1630：删除前端手写 `PreviewChapterVideoPromptOverrideInput` 接口。
- R-1631：前端无草稿覆盖时直接省略 `promptOverride`，不再固定发送兼容性 `null`。
- R-1632：Host TypeScript 生成器输出唯一覆盖 DTO，Rust/TypeScript 共用同一事实来源。
- R-1633：command manifest 从 `args_opaque` 收敛为引用唯一 DTO 的 typed-input schema。
- R-1634：将缺失/显式 null/非法字段的合同测试迁移到 API Contract 所有层，删除 Orchestrator 中错位的 wire 测试。
- R-1635：新增 Server 边界检查，固定拒绝顶层 null、空对象、non-null 字段 null 和未知字段。
- R-1636：新增前端传输检查，固定“缺失时省略、可空字段显式 null 时保留”的唯一 wire 行为。

## 唯一实现结论

- Host wire DTO：`a4n_api_contract::video::PreviewChapterVideoPromptOverrideInput`。
- Runtime/Server：只重导出或反序列化该 DTO，不再定义第二套字段结构。
- 前端：只使用 `frontend/src/api/generated/host.ts` 生成类型。
- nullable 三态解析：只由 `a4n-api-contract/src/serde_update.rs` 实现。
- 桌面、Web 与 CLI 命令描述：共同指向同一个 command manifest 和 Server dispatcher。
