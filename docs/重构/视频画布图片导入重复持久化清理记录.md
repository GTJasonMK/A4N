# 视频画布图片导入重复持久化清理记录

日期：2026-08-16

## BFS 覆盖范围

从视频画布图片导入入口横向追踪并比较普通图片上传能力：

```text
VideoStudioCanvas.importMedia(image)
→ import_canvas_media Host command
→ Runtime canvas image adapter
→ Orchestrator canvas image application
→ 图片解码、文件持久化、generated_image、MediaAsset

upload_image Host command
→ Runtime image_records/upload
→ 同一图片解码与 generated_image 创建服务
```

已搜索 `import_canvas_image_validated`、`prepare_imported_image_upload_for_user_validated`、
`create_imported_image_output`、`persist_created_media_file`、生成图片记录和所有调用者，覆盖
Server/Tauri 动态命令分派、CLI Host schema、文件路径规则和失败清理。未发现反射、DI、AOP、
动态代理或配置别名。

## 已执行清理

1. 新增最小 Host port，使 Orchestrator 只拥有画布业务编排，不再拥有 Runtime 文件写入。
2. 画布图片导入复用普通图片上传的唯一解码、目录创建、写入、相对路径和文件大小实现。
3. Runtime 图片上传内部路径直接返回 `generated_image::Model`，公开 `upload_image` 仅在边界
   转换为原有 summary。
4. 删除 Orchestrator 中整套重复 `persist_imported_canvas_image`。
5. 删除重复 `create_imported_image_output`，消除同一文件分别采用纳秒和微秒命名的分叉。
6. 删除重复 `data_dir_relative_path`。
7. 删除重复 `remove_data_file` 及其手写失败清理分支，统一使用既有持久化/cleanup outbox
   生命周期。

未新增兼容、默认值、回退或占位逻辑。
