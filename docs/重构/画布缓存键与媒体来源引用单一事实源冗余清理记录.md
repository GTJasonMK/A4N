# 画布缓存键与媒体来源引用单一事实源冗余清理记录

日期：2026-08-15

## 搜索起点与 BFS 覆盖范围

本专项从三个真实功能入口开始：

```text
画布成片预览写入
→ a4n-db::canvas::artifacts::assembly::timeline::upsert_canvas_assembly_timeline
→ assembly_timeline.preview_cache_key

视频画布项目包导入
→ Runtime package_io::read_media_payloads_from_entries
→ Orchestrator manifest 校验与媒体字节校验
→ DB canvas transfer remap

自由视频项目复制
→ DB freeform duplication workflow
→ 成片时间线缓存键与 media provenance source_external_path remap
```

随后按 BFS 追踪到：

- `a4n-domain::canvas` 的值对象与格式解析。
- `a4n-orchestrator` 的项目包导出、manifest 校验、媒体 owner/bytes 校验和 Host re-export。
- `a4n-runtime` 的 ZIP/媒体读取入口及其 `HashMap` 去重路径。
- `a4n-db` 的视频画布导入 remap、自由视频复制 remap、成片时间线持久化和媒体 provenance 持久化。
- SeaORM `assembly_timeline.preview_cache_key`、`media_provenance.source_external_path` 字段及其所有 ActiveModel 写入点。
- PostgreSQL migration/baseline、trigger、view、索引、XML/YAML/JSON/TOML 路由或 DI 配置、字符串 Host dispatch、Serde 和 ZIP manifest。

源码引用闭包确认如下：

- `canvas_graph:{graph_id}:node:{node_id}` 的生产、解析和重映射此前各有独立实现；没有仓库外 CLI、反射、动态代理或 AOP 调用者。
- `generated_video:{id}` / `generated_image:{id}` 的 source external path 此前在三处重复拆分与拼接；未知普通文件名仍按原合同原样保留，带已知前缀但 ID 非法的 manifest 路径仍由严格校验入口显式报错。
- 数据库层没有依赖这些字符串格式的 view、constraint 或 trigger；动态边界只有 ORM 字段、ZIP manifest 和 Rust/Serde 数据结构，均已纳入闭包。

## 已完成优化

1. 在 `a4n-domain::canvas` 建立 `canvas_cache_key`，统一画布缓存键生成。
2. 在同一领域模块建立无分配中间数组的 `parse_canvas_cache_key`，统一四段格式解析。
3. 删除 Orchestrator `project::package_rules` 中重复的缓存键解析实现。
4. 删除 DB 视频画布导入 remap 的私有 `parse_video_studio_canvas_cache_key`。
5. 删除 DB 自由视频复制 remap 内联的第二套缓存键解析。
6. 画布成片时间线写入改用领域格式生成器。
7. 视频画布导入 remap 改用领域解析器与格式生成器。
8. 自由视频复制 remap 改用同一领域解析器与格式生成器。
9. 视频画布 manifest 校验改用领域解析器检查缓存键引用。
10. 在 `a4n-domain::canvas` 建立 `GeneratedMediaReference`，收敛 generated image/video 外部引用身份。
11. 在领域层统一已知媒体引用前缀、ID、展示标签和重写格式。
12. Orchestrator provenance 校验删除 generated video/image 的两套分支解析，保留严格非法 ID 错误。
13. DB 视频画布导入 provenance remap 删除两套重复前缀解析。
14. DB 自由视频复制 provenance remap 删除两套重复前缀解析。
15. 删除 family package validation 自己维护的 ID 唯一性实现。
16. family package 的 ID 校验统一调用项目包规则 owner。
17. family package 的复合 key 校验统一调用项目包规则 owner。
18. 视频画布 manifest ID 校验与集合构造合并为一次扫描，删除重复遍历。
19. 项目包规则将三套唯一性循环收敛到一个内部泛型集合校验实现。
20. 删除视频画布 validation 模块的全局 `allow(unused_imports)`。
21. 删除生产校验子树的 `use super::*` / `use super::super::*` 隐式导入，改为逐模块显式依赖。
22. 测试子模块也改为显式导入，避免父模块导入变化造成隐藏耦合。
23. freeform 生成意图校验从 `unwrap_or("snapshot_backed")` 改为直接比较 `Some(SOURCE_CONTEXT_FREEFORM)`，缺失值继续显式失败。

## 清理后的唯一事实标准

```text
画布缓存键
→ a4n_domain::{canvas_cache_key, parse_canvas_cache_key}

生成媒体外部引用
→ a4n_domain::{GeneratedMediaReference, parse_generated_media_reference}

项目包 ID / 导入复合 key 唯一性
→ a4n_orchestrator::project::package_rules
```

未新增兼容别名、默认值、adapter、未知格式回退、占位字段或第二套格式实现。DB remap 对非 generated image/video 的普通外部文件名继续保留原字符串，这是既有外部文件路径合同，不是新增回退逻辑。
