# 管理员控制台合同 BFS 冗余清理记录

日期：2026-08-13

## 搜索起点与覆盖范围

本专项从“管理员在设置页查看系统概览、用户、项目、任务、用量趋势、生成分析、存储路径和日志诊断”这一组生产功能出发，按广度优先顺序追踪完整调用闭包：

```text
AdminTab
├─ OverviewSection / TrendsSection / GenerationCallAnalyticsPanel
├─ UsersSection / ProjectsSection / TasksSection
├─ ApiConfigSection
└─ AboutTab / StoragePathsPanel / LogsTab
   ↓
frontend/src/api/admin/*、generationAnalytics.ts、storagePaths.ts、logs.ts
   ↓
apiInvoke / runtimeInvoke / generated Host contract
   ↓
Host command manifest
├─ Web JWT command route
├─ Tauri invoke_host_command
├─ Tauri 原生日志命令
└─ a4n-cli manifest/context 注入
   ↓
a4n-server 字符串 dispatch 与严格参数解析
   ↓
a4n-runtime admin_records / storage_paths / logging / generation_analytics
   ↓
Runtime require_admin_permission
   ↓
a4n-orchestrator admin/auth context
   ↓
a4n-db admin/auth/project 查询与投影
   ↓
SeaORM entity / PostgreSQL 活跃数据
```

项目列表与入口路由的相邻生产闭包同时覆盖：

```text
NovelList / NovelDetail / ProjectLists / 管理员项目列表
→ ProjectSummary / AdminProjectSummary
→ projectRouting
→ 文本、漫画、视频、自由视频、GALGame 入口与工作台路由
→ project mutation 的 project_kind/project_type 校验
→ novel_project 持久化值
```

隐式依赖检查覆盖：Cargo crate 依赖和 `pub use` 导出链、serde/schemars DTO、Host command manifest、生成 TypeScript、Web/Tauri/CLI 字符串调度、JWT/Tauri 可信身份注入、Runtime 权限枚举、Orchestrator context 注入、React section loader key、前端路由表、SeaORM entity、PostgreSQL 活跃数据值，以及原生日志命令绕过通用 Host dispatcher 的特殊边界。

仓库内该功能没有 XML Bean、运行时反射注册、动态代理或 AOP 切面；依赖注入由 `ServerState/AppState → OrchestratorContext → DbHandle` 显式完成。框架级隐式入口由 command manifest、Web/Tauri dispatch、CLI catalog、生成合同和 React 路由覆盖。

## 单一事实来源

- 用户摘要：`a4n-domain::auth::UserSummary`
- 管理员概览、项目、邀请码、任务、用量与生成分析 DTO：`a4n-domain::admin`
- 项目族：`a4n-domain::project::ProjectKind`
- 项目状态：`a4n-domain::project::ProjectStatus`
- 用户和邀请码持久化查询：`a4n-db::auth`
- 管理员权限判定：`a4n-runtime::actions::admin_records::require_admin_permission`
- Host 命令参数与身份元数据：`a4n-api-contract::command_manifest`
- 前端项目路由与展示标签：`frontend/src/utils/projectRouting.ts`

## 已完成优化

1. 新增 domain 级 `UserSummary`，让普通身份功能和管理员用户列表消费同一响应合同。
2. 删除管理员专用 `AdminUserSummary` 镜像。
3. 删除 `UserSummary.display_name`；该字段始终复制用户名且无活跃消费者。
4. 将管理员概览、项目、邀请码、任务、用量和生成分析响应 DTO 收敛到 `a4n-domain::admin`。
5. `a4n-api-contract`、`a4n-db`、`a4n-orchestrator` 和 `a4n-runtime` 改为重导出 canonical DTO，不再各自维护结构镜像。
6. 管理员项目摘要删除无人消费的 `description`、`chapters_per_part`、`avatar_animal`、`created_at`、`updated_at`。
7. 新增 canonical `ProjectKind` 枚举，项目摘要和管理员项目摘要不再传递任意字符串项目族。
8. 管理员项目查询显式解析 `ProjectKind` 与 `ProjectStatus`，非法持久化值直接失败，不做默认映射。
9. 项目 mutation 校验复用 `ProjectKind::parse`，删除第二份项目族白名单。
10. 管理员用户列表直接复用 `a4n-db::auth::list_users`，删除管理员模块的重复 SeaORM 查询。
11. 管理员邀请码列表直接复用 `a4n-db::auth::list_invite_codes`，删除第二份排序查询。
12. 删除 DB 管理员用户投影和邀请码投影；API 投影只在 Runtime 边界保留一份。
13. 删除生成分析的 `types/contracts.rs`、`types/metrics.rs`、`types/recent.rs` 三套 DTO 镜像文件。
14. 删除生成分析 `DEFAULT_DAYS` 与 `DEFAULT_RECENT_LIMIT`；调用方必须显式提供查询窗口和最近记录上限。
15. 生成分析范围上限收敛到 domain 常量，DB 只复用并校验，不复制业务值。
16. `projectRouting` 将项目 ID 和 `project_kind` 改为必填，删除缺失 ID/项目族时的字符串归一化和延迟抛错分支。
17. 删除 `novel`、`text`、`video`、`comic`、`manga`、`galgame` 作为旧 `project_type` 的兼容标签映射。
18. 项目工作台 route/label 改为非空合同，删除所有 `||`、`??` 路由回退。
19. 管理员项目列表仅对文本项目展示 `project_type`，漫画、视频和 GALGame 统一按 `project_kind` 展示。
20. 前端管理员 API 删除全部 `callerUserId` 参数和载荷。
21. `AdminTab` 删除向概览、项目、任务、趋势分发身份 prop；`UsersSection` 仅保留 `currentUserId` 防止管理员禁用自己。
22. Host manifest 的 `ADMIN_IDENTITY.context_fields` 改为空；管理员身份只来自可信 Host 会话。
23. 删除 Server `require_admin_caller` 和“请求身份必须等于 JWT 身份”的重复校验。
24. Web JWT 与 Tauri Host dispatcher 直接把可信身份传给 Runtime，不再要求客户端回传同一 ID。
25. Runtime `require_admin_permission` 保留为管理员授权唯一 owner，所有管理员能力仍在业务边界校验具体权限。
26. CLI context 不再向管理员命令注入 `callerUserId`，只注入 manifest 明确声明的资源上下文。
27. 原生日志命令保持唯一特殊边界：仅 Tauri 直接调用前注入当前身份；通用 Host 命令不注入管理员 caller 字段。
28. 删除 `CleanupOrphanProjectDataDirsInput`；孤儿目录清理直接接收可信 caller 身份。
29. `get_storage_paths` 增加真实 `ManageSettings` 权限检查，关闭此前可绕过管理员授权的读取旁路。
30. Server 未知参数校验改为纯显式白名单；`input` 不再被全局隐式放行。
31. 无输入管理员命令严格拒绝旧 `callerUserId`、多余 `input` 和任意未知字段。
32. 管理员直接参数命令只允许自身字段；typed input 命令显式允许 `input`，runtime 命令显式允许 `runtime_config_snapshot`。
33. command manifest 将管理员命令从 opaque schema 收敛为 empty、typed input、`userId`、`taskId` 等实际合同。
34. 重新生成 Host TypeScript 合同，删除退役清理输入、用户展示名和管理员项目冗余字段，并生成 typed `ProjectKind`。
35. 删除 Rust 管理员用户动作和前端任务页中确认未使用的导入。
36. 配置、生成分析、日志和存储前端调用统一依赖 Host 认证上下文，不再维护管理员 caller 参数分叉。

## 删除与保留边界

- 删除的是客户端可伪造的管理员 caller 镜像；JWT/Tauri 会话身份和 Runtime 权限校验完整保留。
- `userId` 在用户用量、角色修改、禁用用户等命令中仍表示“目标用户”，不是调用者身份，必须保留。
- Tauri 原生日志命令不经过 `invoke_host_command`，因此只在该原生边界注入身份；没有为其他命令增加兼容分支。
- `project_type` 仍是文本项目的业务子类型；`project_kind` 是项目族，两者不再相互猜测或回退。
- 孤儿项目目录清理仍保留二次数据库引用检查和持久化媒体引用检查；这些是防止数据丢失的安全边界，不属于伪安全冗余。
- `get_storage_paths` 仍返回既有运维合同；本专项只补齐权限 owner，没有扩展或掩码另一份响应格式。
