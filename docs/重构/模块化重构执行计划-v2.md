## 1. 状态判定规则

本计划只使用两种状态：

- `完成`：当前代码已经满足该项全部关闭条件。
- `未完成`：当前代码至少缺少一项关闭条件，并在条目中明确列出缺失内容。

禁止使用以下表述作为状态：

- 基本完成
- 大部分完成
- 接近完成
- 有待验证
- 后续加强
- 主体完成
- 门禁已关闭但仍有残留

测试、CI、跨进程用例和跨平台脚本本身就是交付物。代码中没有对应测试或 CI job 时，直接判定为 `未完成`，不写成“有待验证”。

整体重构只有在本文件“完成定义”中的所有条目均为 `完成` 时才能宣布完成。

### 2.4 Runtime 与 orchestrator

当前 `a4n-runtime::actions` 为 crate 内模块，`a4n-runtime::host_api` 通过显式模块白名单暴露 Host 可调用领域：

```rust
pub(crate) mod actions;
pub mod host_api;
```

具体白名单位于 `a4n-runtime/src/host_api.rs`。新增 action 模块不会自动扩大公共 Host API；业务权限、不变量、workflow/checkpoint、事务和 capability 决策已经由 orchestrator application owner 持有，Runtime 只保留 Host DTO/错误/事件、权限入口以及队列、provider、文件、FFmpeg、缓存等基础设施适配。

`AppState` 的 Orchestrator、runtime profile 和 managed sidecar 进程句柄均为私有字段；`Deref<Target = OrchestratorContext>`、完整 `orchestrator()` getter 和公共基础设施字段已删除。Tauri/Server/Runtime 只通过用途方法和领域 facade 访问所需能力。

`OrchestratorContext` 的 config、event bus、task manager、snapshot、queue、engine 和领域 owner 均不再作为 service locator 公共字段；生产 Runtime actions 的直接 `.orchestrator()`、直接 `state.db`、本地纯 rules 和 Orchestrator 透传壳均为 0，并由 convergence/owner 门禁阻止回流。
