## 搜索起点与覆盖范围

以“管理员导出全部配置，并从 JSON 备份恢复全部配置”为功能起点，按广度优先顺序检查：

1. 前端入口：AdvancedTab、配置备份面板、导入确认、文件读取/下载、主题恢复后重载、用户切换和组件卸载路径。
2. 前端 API：`frontend/src/api/config.ts`、旧 theme API、生成 config 类型、生成 Host 命令表和 Web API parity 元数据。
3. Host 合同：`a4n-api-contract` command manifest、Tauri command registry、Web Server dispatch、CLI 通用 Host 调用与 admin identity 注入。
4. Runtime：settings-all action、管理员权限、prompt runtime registry、Host port、sidecar capability registry 和运行模式分支。
5. Orchestrator：settings-all application、格式解析、行规范化、跨表校验、默认项校验、提示词预检/导入/回滚和 context facade。
6. DB：LLM、Embedding、Image、Video、Theme、SystemSettings 的 SeaORM 导出投影、导入事务、同名覆盖、默认项约束和持久化边界。
7. Sidecar：import/export core 合同、HTTP client trait、service route、runtime client、service manager、test-support reexport、进程合同测试和 capability version catalog。
8. 隐式依赖：Serde/Schemars、生成 TypeScript、依赖注入的 `A4nCapabilities`、服务注册表、文件输入输出声明、prompt 模板编译和 rollback 数据安全路径。
9. 横向搜索：Rust、TypeScript、JSON、脚本和文档；确认本功能没有 XML、反射调用、动态代理、AOP 切面或额外路由表。

搜索排除仓库 `target/` 和前端依赖/构建产物；所有源码修改均发生在仓库内，构建复用 `/home/fufu/Code/A4N/target`。

## 活跃调用拓扑

```text
AdvancedTab / CLI Host invocation
  -> generated Host command contract
  -> frontend config API
  -> Tauri registry or Web dispatch
  -> Runtime settings_all action
  -> require ManageSettings admin permission
  -> Orchestrator settings-all application
  -> one DB SettingsAllConfigRows projection
  -> LLM / Embedding / Image / Video / Theme / SystemSettings owners
  -> prompt runtime registry

export_all_configs_json
  -> DB rows + modified prompt name/content
  -> strict AllConfigsExport v3
  -> serde_json::to_string_pretty
  -> browser/CLI text file output

import_all_configs
  -> strict ImportAllConfigsInput
  -> strict AllConfigsExport v3 parse
  -> provider normalization + one validation pass
  -> prompt existence/template compilation preflight
  -> DB final-default validation
  -> prompt batch update
  -> one transactional DB import
  -> rollback prompt snapshots only when DB import fails
  -> Vec<String> import counts

project family/video studio package transfer
  -> export render_json/render_zip sidecar
  -> import read_media_package_zip sidecar
  -> no settings-all JSON sidecar dependency
```

## 生产数据证据

开发 PostgreSQL 通过 `docker exec a4n-postgres psql` 只读审计：

- 行数：LLM 5、Embedding 2、Image 11、Video 4、Theme 0、SystemSettings 1。
- 默认项：LLM、Embedding、Image、Video 各 1。
- 空或 NULL `base_url`：Embedding 2、Image 0、Video 0。
- Embedding backend 仅 `fastembed`，NULL `base_url` 是本地模型的真实语义。
- Image backend：`cliproxy-image`、`openai-chat-image`、`openai-compatible-image`、`openai-compatible-image-edit`。
- Video backend：`cliproxy-openai-video`、`newapi-video`、`openai-compatible-video`。
- LLM/Embedding/Image/Video 的 trim 后空名称均为 0。

结论：Embedding 必须保留可空 `base_url`；Image/Video 的空值兜底没有生产数据依据，应在导出和导入边界显式失败。

## 当前事实标准

全量配置只保留一条实现：API 合同负责 transport 输入，Runtime 负责管理员门禁和 prompt registry 适配，Orchestrator 负责格式/业务编排，DB rows 合同负责六类持久化投影与事务导入。普通 JSON 不经过 sidecar；sidecar 只保留项目媒体包真正需要的 JSON/ZIP 渲染和 ZIP 读取能力。
