# 画布音频规则迁移后重复测试清理记录

日期：2026-08-16

## BFS 覆盖范围

从视频画布“导入音频”功能入口开始，按生产调用链追踪：

```text
VideoStudioCanvas.importMedia(audio)
→ frontend apiInvoke(import_canvas_media)
→ Server / Tauri Host command dispatch
→ Runtime canvas_workflow/media_import/audio/import.rs
→ OrchestratorContext::import_canvas_audio_validated
→ canvas/audio_rules.rs
→ 音频文件持久化与 MediaAsset 创建
```

同步搜索了 `import_canvas_media`、`CanvasAudioImportHostInput`、
`canvas_audio_extension`、`required_canvas_audio_file_name`、
`validate_canvas_audio_mime`、command manifest 和 CLI 文件输入配置。生产链没有 XML、依赖
注入容器、反射、动态代理或 AOP 入口；Host command 是唯一动态分派入口。

## 已执行清理

1. 删除 Runtime `media_import/audio/tests.rs` 中迁移后遗留的 7 个测试。
2. 删除 Runtime `audio.rs` 对该旧测试模块的声明。
3. 扩展名、文件名和 MIME 规则测试只保留在规则唯一 owner：
   `a4n-orchestrator/src/canvas/audio_rules.rs`。
4. 删除的两个文件持久化测试仅调用通用 `persist_created_media_file`，当前画布音频导入并不
   调用该助手，放在音频模块下会制造虚假的功能覆盖。
5. 删除 `canvas.rs` 对三条音频纯规则的 crate 级公开 re-export。
6. 三条规则收窄为 `pub(super)`，只对实际消费者 `audio_import.rs` 可见。

`mime_type` 缺失及 `application/octet-stream` 暂未删除：浏览器 `File.type` 可以为空，CLI
也允许直接提供 Base64 字段；在没有生产数据证明这些入口不可达前，不能把活跃输入场景
误判为死代码。
