# 蓝图身份合同与版本快照冗余清理记录

## 搜索覆盖范围

本专项从用户可见的“读取、生成、优化、保存、同步、比较和恢复故事蓝图”能力出发，按 BFS 覆盖以下公开命令：

1. `get_blueprint`
2. `sync_blueprint_materials`
3. `preview_generate_blueprint_request`
4. `preview_refine_blueprint_request`
5. `list_blueprint_versions`
6. `diff_blueprint_versions`
7. `restore_blueprint_version`
8. `save_blueprint`
9. `update_world_setting`
10. 相邻正式入口 `start_blueprint_generation`
11. 相邻正式入口 `start_blueprint_refinement`

BFS 主拓扑如下：

```text
蓝图页面 / hooks / frontend API wrapper
→ apiInvoke / generationClient.start
→ command manifest / generation route table
├─ Web：Axum command dispatch / generation fixed routes / JWT identity
├─ Tauri：通用 Host dispatcher / outer authenticated user_id
└─ CLI：command manifest / session token / canonical generation route
→ a4n-runtime::actions::blueprint_records
→ Orchestrator 权限、预览、生成、精炼、保存、版本比较与恢复
→ a4n-db 蓝图、角色、关系、版本、项目状态与 raw_blueprint
→ PostgreSQL migration / project family import-export / project duplication
```

版本快照写入与消费分支继续横向展开：

```text
正式蓝图写入
├─ 分阶段蓝图生成完成
├─ 蓝图精炼完成
├─ 用户手工保存
├─ 用户更新世界观
└─ 导入内容反向归纳蓝图
→ novel_blueprint + blueprint_character + blueprint_relationship
→ canonical blueprint_version snapshot
→ novel_project.raw_blueprint mirror

版本快照消费
├─ 版本列表 / diff
├─ 版本恢复
├─ 项目族导出 / 导入
├─ 文本项目复制
├─ 大纲、优化与 RAG 上下文
└─ 数据迁移与 schema readiness
```

显式引用覆盖：

- `frontend/src/api/blueprint.ts`、蓝图 API 测试、页面调用者和 generation task client。
- `a4n-api-contract` 输入、结果、Schemars schema、command manifest 与生成 TypeScript。
- Server command dispatch、严格 envelope parser、Runtime typed actions 与 Host 认证身份。
- Orchestrator 的蓝图预览、生成、精炼、手工写入、版本 diff/restore 和事件发布。
- DB 的正式蓝图、角色、关系、版本、项目镜像、状态历史、章节/分部覆盖校验。
- 反向归纳、项目族导入导出、文本项目复制、源快照、RAG/Prompt 上下文和迁移注册。

隐式依赖覆盖：

- `serde(deny_unknown_fields)`、Schemars 范围和 command manifest 宏生成合同。
- Axum 路由表、generation 固定路由、Tauri 通用 dispatcher 和 CLI manifest 路由。
- Runtime config snapshot 注入、Host authenticated `user_id`、项目权限与 task owner。
- Prompt registry 中的分阶段蓝图生成和 `reverse_blueprint` 结构化输出。
- SeaORM 模型关系、事务锁、版本恢复同步、项目状态推进和 migration readiness 常量。
- 项目族 JSON 包、当前版本引用、项目复制图以及 `raw_blueprint` 的下游上下文读取。

仓库扫描未发现蓝图能力存在 XML DI、反射字符串调用、动态代理或 AOP 切面旁路。动态入口仅为 command manifest、Host 路由表、Prompt registry、Tauri/CLI 通用分发和数据库迁移注册，均已纳入搜索闭包。

## 清理前分叉

```text
身份
├─ Host 已认证 user_id
└─ 前端蓝图 API 再发送业务 userId（无效第二身份源）

Host 合同
├─ get_blueprint 使用 opaque args
├─ preview / version / mutation envelope 允许额外字段
├─ preview 结果声明为 opaque
└─ save / restore / sync / world setting 复用含混结果 schema

模板变量
├─ 正式 generation：object map
└─ preview：任意 JSON Value，再由 Runtime 二次解析

版本快照
├─ generation 保存 LLM 原始 assembled JSON
├─ refinement 保存带 optimization_patch 的自建 JSON
├─ manual/world setting 自建另一份 JSON
└─ reverse import 再自建一份 JSON

章节策略
├─ Core 生成范围 5..=10000
├─ API schema 曾声明 >=1
├─ DB 保存范围 1..=10000
├─ Restore 曾错误使用 5..=10000
└─ Core 与 DB 各自维护 50 / 25 常量和派生函数

恢复与导入
├─ 缺少 characters / relationships 时静默保留旧记录
├─ 未知字段、DB identity 字段和退役 patch 字段被忽略
├─ Restore 未检查已有正文、大纲、分部覆盖范围
├─ 项目族导入信任包内 raw_blueprint 和版本快照
└─ reverse blueprint 将非法或缺失章节数过滤成 None 后继续写版本
```

## 优化记录

1. 删除蓝图前端 API 的重复业务 `userId`，身份只来自 Web JWT、Tauri 外层认证或 CLI session。
2. `get_blueprint` 从 opaque args 收敛为唯一 `{ projectId }` 严格合同。
3. `sync_blueprint_materials` 拒绝 `projectId` 与 runtime snapshot 之外的参数。
4. Preview、版本列表、版本 diff、恢复、保存和世界观更新统一使用严格 typed envelope。
5. Preview 命令结果从 opaque 收敛为正式 `ModelRequestPreview`。
6. 保存、恢复、同步和世界观更新统一使用 `BlueprintMutationResult`，删除含混结果 schema 别名。
7. `update_world_setting` manifest domain 从 `system` 修正为 `blueprint`。
8. Preview `variables` 从任意 `Value` 收紧为 `Option<BTreeMap<String, Value>>`。
9. Runtime 删除 Preview 模板变量的二次 JSON object parser，直接使用 typed map。
10. 蓝图生成输入 schema 与真实运行规则统一为 `5..=10000`。
11. 正式保存与恢复统一使用持久化范围 `1..=10000`。
12. 将持久化范围、生成范围、分部阈值 `50`、每部分 `25` 章和派生函数收敛到 `a4n-domain::project`。
13. 删除 Core 与 DB 中重复的章节常量、派生函数和重复阈值测试。
14. 删除 `ParsedBlueprint.raw` 死字段及 generation parser 赋值。
15. 新增唯一 `blueprint_version_snapshot()`，只从最终正式蓝图、角色和关系模型生成版本快照。
16. 分阶段生成写路径改用唯一快照，不再保存含 `chapter_outline` 等临时字段的 LLM 原始 JSON。
17. 精炼写路径改用唯一快照，不再把 `optimization_patch` 写入正式版本。
18. 手工保存与世界观更新删除各自的重复快照 builder。
19. 反向归纳删除第四套快照 builder，改用唯一快照。
20. 蓝图版本统一去除 `current_version`、临时 patch、导入分析字段和 DB identity/timestamp 字段。
21. `insert_blueprint_version_record` 成为版本写入边界：校验项目 ID、规范版本文本和完整可恢复快照。
22. Restore 顶层、角色和关系对象拒绝未知字段，不再吞掉退役字段或 DB 字段。
23. Restore 强制要求 `characters` 与 `relationships` 数组，不再以“缺失即保留旧记录”作为隐式回退。
24. Restore 校验章节总数、`needs_part_outlines` 和 `chapters_per_part` 的派生一致性。
25. Restore 在落库前检查现有正文、章节大纲和分部范围，拒绝缩短到正式资料覆盖范围以下。
26. 删除 Orchestrator 对 restore version 的重复 trim/空值校验，保留 DB owner 的唯一校验点。
27. 删除 Orchestrator 对 `world_setting = null` 的重复校验，保留事务写入口的唯一校验点。
28. Reverse blueprint 新增正式 `1..=10000` 范围校验。
29. Reverse blueprint 删除非法正数过滤和缺失章节数 fallback；无法解析唯一有效章节数时显式失败。
30. `ReverseBlueprintApplyRecord.total_chapters` 从 `Option<i32>` 收紧为 `i32`，删除后续条件更新和旧项目值回退分支。
31. Reverse blueprint 始终以同一章节计划同步正式蓝图、项目章节目标、分部派生值和版本快照。
32. 项目族导入逐个校验蓝图版本快照，拒绝未知、退役和数据库身份字段。
33. 项目族导入要求正式蓝图必须存在对应 current version，且当前版本必须与正式行重建结果完全一致。
34. 项目族导入不再信任包内 `raw_blueprint`，统一从导入的正式蓝图、角色和关系重建。
35. 无正式蓝图但携带版本、角色或关系的项目族包改为显式失败，不再产生半套蓝图图。
36. 新增 `blueprint_version_snapshot_contract` 数据迁移，修复旧写路径产生的分叉快照。
37. 迁移补齐规范可选 null 字段、删除退役字段和实体 DB 字段，并拒绝未知字段。
38. 迁移校验当前正式蓝图必须存在 current version，拒绝“有 raw、无正式蓝图”。
39. 迁移从正式蓝图、角色和关系重建当前版本，历史版本只保留各自历史业务值。
40. 迁移按统一 `50 / 25` 规则重算正式蓝图与全部历史版本的派生章节字段。
41. 迁移从 current version 重建所有正式蓝图项目的 `raw_blueprint`，并验证两者 JSON 等价。
42. 新增 PostgreSQL 数据级迁移回归，覆盖当前版本重建、历史派生字段修复和 raw mirror 同步。

## 清理后唯一事实标准

```text
认证身份
→ Host authenticated user_id
→ Orchestrator permission check
→ DB mutation / generation task owner

章节策略
→ a4n-domain::project
   ├─ persisted: 1..=10000
   ├─ generation: 5..=10000
   ├─ needs_part_outlines: total > 50
   └─ chapters_per_part: needs ? 25 : null

版本快照
→ 最终 novel_blueprint
 + ordered blueprint_character rows
 + ordered blueprint_relationship rows
→ blueprint_version_snapshot()
→ blueprint_version.blueprint_data
→ novel_project.raw_blueprint mirror

恢复 / 导入
→ validate_blueprint_version_snapshot()
→ 拒绝未知字段、退役字段、DB identity、缺失实体数组和派生章节漂移
→ 事务内替换正式蓝图图并同步项目镜像
```

未新增默认用户、旧字段别名、兼容转换、缺失数组保留、章节数 fallback、异常吞掉、备用快照 builder、占位 schema 或第二套章节策略。
