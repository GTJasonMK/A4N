# 章节拍摄脚本与转场合同冗余清理记录

日期：2026-08-14

## 搜索起点与 BFS 覆盖范围

本专项从章节详情页“剧本改编”与视频页消费拍摄脚本的功能入口出发，按广度优先顺序追踪显式调用、生成合同、持久化记录、工作流恢复和下游投影。

```text
ShootingScriptTab / VideoTab
→ StructuredScriptEditor / 前端 shootingScript API
→ generated Host TypeScript / command manifest
→ Tauri 通用 dispatch / Web command dispatch / CLI command descriptor
→ Runtime shooting_script_records actions
→ Orchestrator shooting_script context / generation / staged checkpoints
→ DB shooting_script query / insert / edit / invalidate
→ Domain ChapterShootingScriptV1 合同与校验
→ PostgreSQL migration / schema requirement
→ Prompt registry / skeleton / layout / adaptation / shooting design
→ Video execution contract / segment parser / frame prompt projection
→ Manga / Galgame / project family package / Source Sync 下游读取
```

显式依赖覆盖函数调用、变量使用、模块导入、`pub use`、Serde/JsonSchema 类型、SeaORM 查询、事务和测试夹具。隐式依赖覆盖 command manifest、生成 TypeScript、Server 字符串路由、Tauri 通用调度、CLI descriptor、认证身份注入、runtime config snapshot、Workflow run/checkpoint、Prompt registry、PostgreSQL migration 注册和 JSON CHECK。

仓库不存在该功能相关 XML DI、反射注册、动态代理或 AOP 切面；框架入口均由 manifest、dispatcher、trait/context 注入、Prompt registry 和 migration 列表覆盖。

## 现有数据证据

迁移前通过仓库 PostgreSQL 容器只读核验开发库：

- 正式拍摄剧本 2 条，均为 `chapter_shooting_script_v1`，共 50 个转场值。
- 拍摄脚本 Workflow 8 条，Checkpoint 317 条，共 644 个转场值。
- 正式剧本存在 15 种值；Checkpoint 存在 23 种值，证明自由文本转场合同仍在生产数据中分叉。
- 未发现空 scenes、非法来源 hash、非 object 剧本 JSON 或重复来源记录。
- 全部历史值均进入显式迁移映射；未知值会使迁移失败，不会被保留、默认化或静默替换。

代表性历史映射：

```text
cut / direct_cut / TIME_CUT / time_cut → hard_cut
continuity / action_continuity / 直接连戏 → continuous
match on action / cause_effect / cut_on_glance → match_cut
sound_cut → sound_bridge
time_ellipsis / time_jump / montage_to_scene / 意识闪回 → dissolve
意识回归 → focus_transition
```

迁移后只读复核：

- 正式剧本、Workflow 和 Checkpoint 数量仍为 2、8、317。
- 正式剧本仅剩 `continuous`、`dissolve`、`hard_cut`、`match_cut`、`sound_bridge`。
- Checkpoint 仅剩上述值及 `focus_transition`。
- 50 个正式转场和 644 个 Checkpoint 转场总数不变。
- `ck_chapter_shooting_script_transition_types_v1` 已安装且 `validated=true`。
- 新迁移成功解析全部正式剧本；未知转场值的隔离库写入被数据库拒绝。

## 唯一实现决策

```text
转场值域与序列化合同
→ a4n-domain::shooting_script::ShootingTransitionTypeV1

Host DTO 与 TypeScript
→ a4n-api-contract 直接复用 Domain 并生成 frontend/src/api/generated/host.ts

拍摄脚本生成和恢复
→ a4n-orchestrator::shooting_script

持久化与编辑失效
→ a4n-db::shooting_script

历史值一次性收敛
→ shooting_script_transition_type_canonicalization 的唯一规范化函数

数据库允许值域
→ shooting_script_transition_type_contract CHECK

Video 下游转场
→ VideoSegmentTransitionV1 直接复用同一 Domain 枚举
```

前端、Runtime、Video 和 Migration 不再维护可自由扩张的第二套转场字符串合同。

## 已完成优化

1. 新增严格 `ShootingTransitionTypeV1`，替代拍摄脚本转场自由文本 `String`。
2. `ShootingTransitionContractV1` 直接使用 Domain 枚举。
3. 删除 Domain 对 `transition_type` 的重复非空文本校验；反序列化边界已完整约束值域。
4. `VideoSegmentTransitionV1` 复用同一枚举，删除 Video 侧字符串分叉。
5. Video segment parser 直接复制 `Copy` 枚举，不再克隆字符串。
6. API contract 直接重导出枚举，并由类型生成器生成唯一 TypeScript 类型。
7. 前端转场编辑从自由文本框改为有限枚举下拉框。
8. 前端编辑器删除两次 `as unknown as`；路径更新使用 `Reflect`，非法路径显式失败。
9. 前端拍摄脚本 API 抽取唯一 `sourceInput` 构造。
10. 删除五个拍摄脚本调用中重复、无效的 `userId`；身份只由 Host 认证上下文提供。
11. Get、Progress、Edit command manifest 改为严格 typed envelope。
12. Full generate 与 Next unit generate 共用严格 optional-task/runtime envelope。
13. Server 五个命令拒绝未知参数，不再接受历史身份字段或任意 envelope 扩展。
14. 完整生成和逐单元生成共用唯一 Workflow 初始化与 revision 计算。
15. 删除 `next_chapter_shooting_script_revision` 转发 facade。
16. 删除 `begin_chapter_shooting_script_workflow_validated` 转发 facade。
17. 缩小完整生成内部函数可见性，外部只保留带权限校验的入口。
18. Prompt registry 删除已不存在的旧生成函数引用，统一指向真实准备入口。
19. 两份拍摄脚本 Prompt 明确唯一合法转场枚举，模型不得创造自由文本值。
20. 历史 migration 与新 migration 复用唯一递归规范化函数。
21. 规范化函数覆盖全部开发库历史别名，并对未知值立即报错。
22. 新增 PostgreSQL JSON CHECK，从数据库层拒绝自由文本转场。
23. 更新 migrator 注册顺序和 `REQUIRED_SCHEMA_MIGRATION`。
24. 重新生成 Host TypeScript，不保留手写兼容类型或别名。
25. 更新所有受影响测试夹具，使用强类型枚举而非字符串。
26. 修正既有弱测试：实现返回 `fact_index=2`，断言不再检查从未存在的 `fact 2` 文本。

## 明确保留的活跃边界

- 完整生成与逐单元生成保留不同终态处理：前者必须发布完整剧本，后者允许在场景边界进入 interrupted 状态。
- Workflow 失败、取消、暂停和恢复状态写入保留，它们是可观测与恢复合同，不是业务 fallback。
- 派生项目通过根项目共享拍摄脚本的投影保留，因为来源快照与根章节是活跃生产场景。
- Prompt 中重复列出枚举值保留，因为模型输出边界不能依赖 Rust/TypeScript 类型推断；数据库、业务和 Host 类型仍只有一个代码 owner。
- Migration 历史别名映射只存在于一次性数据升级路径，不进入运行时代码。
