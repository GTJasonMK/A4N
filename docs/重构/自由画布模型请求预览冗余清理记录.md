## 目标与功能入口

- 功能入口：视频工作室自由画布中，对 `GenerateImageNode`、`GenerateVideoNode`、`LlmTextNode` 执行“查看模型请求”。
- 用户路径：节点右键菜单或页面操作菜单打开请求预览；非 provider 节点继续打开节点内容预览。

- 搜索范围：`frontend/src`、`crates/a4n-api-contract`、`a4n-tauri`、`a4n-server`、`a4n-cli`、`a4n-runtime`、`a4n-orchestrator`、`a4n-db` 及生成合同；排除 `.git/`、`target/` 和 `frontend/node_modules/`。

## BFS 结论

1. 活跃前端只允许三种 provider 节点进入模型请求预览，未知节点通用占位预览没有生产入口。
2. API 输入事实源已经是 `PreviewCanvasNodeRequestInput`；Runtime 手写 DTO 多出无人消费的 `input_overrides`，属于合同分叉。
3. 图片和视频底层已经返回完整 `ModelRequestPreview`，画布层再次序列化进 `CanvasNodeRequestPreview.request` 没有新增业务语义。
4. LLM 旧预览手工拼装 `messages`，没有使用真实执行的 context ledger、动态 payload、fingerprint 和 trace 构造链。
5. `CanvasNodePreviewDialog` 与全站 `RequestPreviewModal` 服务同一业务目的，前者是字段更少的第二套实现。
6. 指定 `graph_id` 的画布读取不会创建替代记录；项目权限和图边合同校验是有效信任边界，必须保留。
7. 上游产物缺失、配置非法或 provider 请求无法构造时应显式失败，不能包装成成功响应中的 `status=blocked`。

3. 删除图片 provider 请求构造失败后返回成功 `blocked` 预览的路径。
4. 删除视频节点输入构造失败后返回成功 `blocked` 预览的路径。

27. 在既有文本生成规则测试中加入最小检查，确认预览复用执行请求构造器且不会写入虚假 `workflow_run_id`。

## 行为变化与唯一事实标准

- 三种 provider 节点统一返回 `ModelRequestPreview`；同一业务不再存在画布专用响应合同。
- 图片、视频和 LLM 请求无法真实构造时，Host 调用直接失败并保留原始错误，不再返回伪成功或建议性占位数据。
- LLM 预览与生产执行共用同一请求构造器；差异只在预览没有 workflow run 身份且不会调用 provider。
- 非 provider 节点仍由 `CanvasNodeContentPreviewDialog` 展示节点内容，不进入模型请求 Host 命令。
- 请求展示唯一实现为 `RequestPreviewModal`；请求合同唯一实现为 `ModelRequestPreview`。
- 输入合同唯一实现为 `a4n_api_contract::canvas::PreviewCanvasNodeRequestInput`。
- 图片请求事实源为 `preview_canvas_image_request`；视频请求事实源为 `preview_canvas_video_request`；LLM 请求事实源为 `build_canvas_llm_text_request`。

不存在为旧 `CanvasNodeRequestPreview`、`input_overrides`、未知节点占位、`status=blocked` 成功响应、手工 LLM 消息镜像或专用画布弹窗保留的兼容、别名、回退或隐藏 fallback。
