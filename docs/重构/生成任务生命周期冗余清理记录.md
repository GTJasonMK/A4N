# 生成任务生命周期冗余清理记录

## 搜索覆盖范围

本专项从章节、灵感、大纲、人物立绘、图片、视频、蓝图和内容优化的生成启动功能出发，按 BFS 逐层追踪：

```text
页面 / generationClient / CLI command
→ Web REST/SSE 或 Tauri Channel
→ Server/Tauri Host command
→ Runtime 十一个 start_*_generation_typed 入口与 GenerationExecutionOwner
→ Orchestrator 各业务 run_*_generation_task 执行器
→ GenerationApplication reservation / session / execution permit
→ GenerationTerminalCoordinator checkpoint / cancel / terminal
→ a4n-db generation_task_checkpoint lifecycle transaction
→ task_queue / workflow_run / generation_run 状态同步
→ MemoryTaskQueue 调度状态、取消令牌和并发 permit
→ startup recovery / destructive lifecycle / snapshot-only subscription
```

横向比较了章节、灵感、大纲、人物立绘、图片、视频生成、视频提示词、蓝图生成、蓝图优化、Optimize analysis/chat/patch 的执行器，并追踪以下隐式依赖：

- API command manifest、Axum 路由、Tauri command registry 和 CLI 命令映射。
- Runtime request scope、LLM/Image/Video slot 标记与 Host worker ownership。
- generation start-request 幂等映射、business-key attempt 锁、父子任务树和 retry lineage。
- generation session registry、sequence lease、checkpoint CAS、terminal transaction 和 SSE replay。
- PostgreSQL lifecycle transaction 对 `generation_task_checkpoint`、`task_queue`、`workflow_run`、`generation_run` 的同步写入。
- MemoryTaskQueue 的优先级等待队列、并发 semaphore、取消 token、permit RAII 和 snapshot-only 无内存 entry 场景。
- Host 重启恢复、用户取消、项目删除/重置、用户禁用和 cleanup outbox。

项目没有 XML DI、反射调用、动态代理或 AOP；动态分派由显式 Host command、operation enum 和 provider port 完成，均已纳入搜索闭包。

## 清理前拓扑

```text
Generation lifecycle transaction
  ├─ 写 generation checkpoint
  ├─ 写 task_queue running / terminal
  └─ 写关联 workflow / generation run

Generation execution wrapper
  ├─ 再写一次 task_queue running
  ├─ 再写一次 task_queue completed / failed
  └─ 再投影 MemoryTaskQueue terminal
```

数据库 lifecycle 已是权威状态 owner，执行 wrapper 的第二次数据库写入属于重复与伪安全逻辑。它会增加事务外失败点，并可能在 generation terminal 写失败后仍把通用 queue 写成另一个终态。

## 优化记录

1. 确认十一类 Runtime 启动入口最终统一汇入 `GenerationApplication::acquire_task_execution`。
2. 确认 PostgreSQL generation lifecycle transaction 是 checkpoint、queue、workflow 和 generation run 状态的唯一持久化 owner。
3. 删除 `acquire_generation_task_with_cancel` 中重复的 `task_queue=running` 数据库写入。
4. 删除该方法无实际调用语义的外部 `CancellationToken` 参数，改为最小 `acquire_generation_task`。
5. 删除 generation 专用 `complete_generation_task` 数据库二次写入。
6. 删除 generation 专用 `fail_generation_task` 数据库二次写入。
7. 删除 `GenerationTaskExecution.queue` 字段，执行上下文不再持有第二个持久状态 writer。
8. 将完成路径统一为 `GenerationTaskExecution::finish`，只结算内存 permit。
9. 将失败、取消和中断路径统一为 `settle_generation_permit`，按权威 session terminal 状态结算内存 permit。
10. 非终态执行退出不再被伪装成成功或取消，显式投影为内存失败并保留状态信息。
11. 已终态任务在取得 permit 后不再一律投影为 cancelled，而是按真实 Completed/Failed/Cancelled/Interrupted 状态结算。
12. 删除失败路径中“generation queue 终态数据库二次写入失败”的拼接分支。
13. 章节、灵感、大纲、视频、视频提示词、蓝图、蓝图优化和三类 Optimize 完成路径统一调用 `finish`。
14. 保留人物立绘和图片通过 `complete_with_result` 的共享完成路径，并使其同样只结算 permit。
15. `project_generation_queue_terminal` 对非终态输入改为显式 `InvalidState`，不再静默返回成功。
16. 新增 permit 终态映射回归断言，覆盖 completed、failed、cancelled、interrupted 和非法非终态。
17. 将章节、灵感、Optimize 重复的 session 错误映射收敛为 `generation_session_error`。
18. 将章节、灵感、Optimize 重复的 terminal 错误映射收敛为 `generation_terminal_error`。
19. 删除 Optimize 内部两层错误映射 re-export 和 chat 文件中的整套重复实现。
20. 删除章节生成零调用字符串错误包装 `start_chapter_generation`，只保留 typed Host 入口。
21. 扩充 PostgreSQL 集成测试，直接断言 lifecycle Running 后 `task_queue=running`。
22. 扩充同一测试，直接断言 lifecycle Interrupted 后 `task_queue=interrupted` 且保留 terminal summary。
23. 删除章节生成 `generation_error_from_text` 纯转发别名，直接调用共享协议错误构造。
24. 删除章节生成 finish-reason 纯转发别名，直接调用共享文本映射。
25. 删除蓝图生成与蓝图优化两套 `app_generation_error` 纯转发别名。

## 清理后拓扑与唯一事实标准

```text
GenerationApplication / GenerationTerminalCoordinator
  → a4n-db lifecycle transaction
     → generation_task_checkpoint（权威状态）
     → task_queue（持久查询投影）
     → workflow_run / generation_run（关联账本）

MemoryTaskQueue
  → 排队、并发槽位、取消 token、permit
  → 由已提交的 session terminal 状态结算内存 permit
```

- 持久化生命周期只有 a4n-db generation lifecycle transaction 一套实现。
- Runtime/Orchestrator execution wrapper 不再写第二遍 queue 数据库状态。
- MemoryTaskQueue 仅拥有调度状态，不再被误当作第二个业务生命周期事实源。
- snapshot-only、启动失败和 destructive lifecycle 没有执行 permit 时，仍保留显式内存 terminal projection；这是活跃恢复边界，不是重复实现。

## 明确保留的活跃分支

- Web SSE 与 Tauri Channel：两种宿主 Transport，不可合并。
- `GenerationExecutionOwner`：Host 退出时中止本进程 worker，属于资源所有权边界。
- LLM/Image/Video task-local slot：标记 generation worker 已持有 queue slot，避免嵌套 provider 调用等待自身。
- startup recovery、destructive drain、snapshot-only session 和 cleanup outbox：数据完整性与资源清理边界。
- 通用 `mark_done` / `mark_failed`：仍服务非 generation 的 tracked/provider queue 任务，不属于 generation lifecycle 分叉。
