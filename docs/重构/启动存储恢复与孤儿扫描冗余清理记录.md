# 启动存储恢复与孤儿扫描冗余清理记录

## 目标与入口

- 功能入口：Server 与 Tauri 共用的 `AppState::new_with_profile`。
- 用户路径：应用启动恢复、项目删除、媒体记录删除、上传/生成失败补偿、过期上传清理、过期成片缓存清理，以及管理员显式扫描和清理孤儿项目目录。
- 搜索策略：从启动入口按 BFS 逐层追踪 Runtime 调用、Orchestrator 转发、DB 引用复核、cleanup outbox、文件生产者、Host 命令和前端入口。
- 搜索范围：`crates/a4n-runtime`、`a4n-orchestrator`、`a4n-db`、`a4n-server`、`a4n-tauri`、`a4n-api-contract`、`frontend/src`、迁移、脚本和环境配置；排除 `target/`、`.git/` 与前端依赖目录。

## BFS 覆盖拓扑

```text
L0 Host 启动
   ├─ a4n-server::ServerState::new
   └─ a4n-tauri::setup::initialize
          └─ AppState::new_with_profile

L1 启动生命周期
   ├─ continue_pending：恢复已持久化 generation lifecycle operation
   ├─ recover_expired_uploaded_video_sources：按临时上传 TTL 清理
   ├─ recover_expired_assembly_caches：按缓存 manifest TTL 登记 cleanup intent
   ├─ recover_cleanup_outbox：处理已持久化 cleanup intent
   └─ spawn_cleanup_worker：继续轮询同一 outbox

L2 已删除的推断式分叉
   ├─ recover_unreferenced_managed_media_files
   │  ├─ 遍历 projects/*/{images,videos,portraits,audio,media,assets}
   │  ├─ 排除完整 assembly cache
   │  ├─ path/size/mtime 计算文件版本
   │  ├─ OrchestratorContext::unreferenced_media_paths
   │  └─ 为扫描结果补写 startup-orphan-media cleanup intent
   └─ recover_orphan_project_data_dirs
      └─ 在无管理员确认时复用孤儿项目目录删除实现

L3 保留的唯一清理事实源
   ├─ project_cleanup_outbox
   │  ├─ file artifact cleanup
   │  ├─ project deletion cleanup
   │  ├─ media workflow reset
   │  └─ generation cleanup
   ├─ DB 媒体引用复核
   │  ├─ generated_image.file_path
   │  ├─ generated_video.file_path / thumbnail_path
   │  ├─ character_portrait.image_path
   │  └─ media_asset.file_path / thumbnail_path
   └─ TTL 所有权
      ├─ tmp/video_uploads
      └─ assembled_*.mp4.cache.json

L4 显式管理员功能
   ├─ StoragePathsPanel
   ├─ frontend storagePaths API
   ├─ command manifest / generated Host command list
   ├─ Tauri invoke_host_command / Server command dispatch
   └─ list_orphan_project_data_dirs / cleanup_orphan_project_data_dirs
      ├─ ManageSettings 权限
      ├─ project_ids 与 incomplete cleanup 保护集合
      ├─ 删除前重新查询项目存在性
      └─ 删除前重新检查持久化媒体路径前缀

L5 文件生产与补偿路径
   ├─ 图片上传、图片生成、人物立绘
   ├─ 视频生成失败、尾帧、导入、裁剪、画布抽帧、成片
   ├─ 项目导入、复制、删除和重置
   └─ 记录删除与角色档案删除
      └─ 已知文件路径进入 cleanup outbox；失败显式返回，不由启动扫描猜测补齐
```

Rust 代码中未发现 XML 容器、AOP 切面、动态代理或反射注册。相关隐式依赖是字符串命令清单、Tauri 通用命令分发、Server 路由分发、生成 Host 合同、SeaORM 实体查询和数据库迁移。

主要检索词包括：`AppState::new_with_profile`、`recover_cleanup_outbox`、`recover_unreferenced_managed_media_files`、`recover_orphan_project_data_dirs`、`unreferenced_media_paths`、`filter_unreferenced_media_paths`、`enqueue_file_artifact_cleanup_by_project`、`cleanup_orphan_project_data_dirs`、`list_orphan_project_data_dirs`、`recover_expired_uploaded_video_sources` 与 `recover_expired_assembly_caches`。

## 事实边界结论

1. 已持久化的 cleanup intent 是文件和项目删除恢复的唯一事实源；Worker 仍会在删除前复核当前数据库引用。
2. 临时视频上传和成片预览缓存具有明确目录、命名和 TTL owner，保留其定向过期扫描。
3. 整个受管媒体目录扫描无法区分崩溃遗留、人工放置、外部工具输出和尚未登记的合法文件，不能作为删除事实源。
4. 孤儿项目目录清理保留为管理员显式操作；启动阶段不再无确认调用同一破坏性实现。
5. `unreferenced_media_paths` 仍被 file artifact 与 project deletion 两类 outbox claim 使用，不是死代码，继续保留 Orchestrator/DB 链。

## 优化记录

1. 从 `AppState` 启动顺序删除全盘受管媒体文件恢复调用。
2. 从 `AppState` 启动顺序删除自动孤儿项目目录恢复调用。
3. 删除两个启动恢复函数的 crate-private 重导出。
4. 删除 `recover_unreferenced_managed_media_files` 推断式恢复实现。
5. 删除 `recover_orphan_project_data_dirs` 隐式破坏性入口。
6. 删除六类受管媒体目录白名单常量。
7. 删除仅服务启动扫描的 `ManagedMediaFile` 类型。
8. 删除跨项目和媒体目录的全盘扫描入口。
9. 删除受管媒体目录递归收集器。
10. 删除扫描器对完整 assembly cache 的第二套识别逻辑；缓存所有权只由 assembly cache 模块负责。
11. 删除基于路径、大小和修改时间的媒体文件版本指纹。
12. 删除扫描器专用 SHA-256 计算和相关时间元数据处理。
13. 删除只验证已退休全盘扫描器的单元测试与夹具。
14. 将进程恢复测试收敛为“只恢复已登记或有明确 TTL 的清理对象”。
15. 在同一进程测试中固定六类未登记媒体与未登记项目目录均不会被启动推断删除。
16. 删除图片记录/cleanup intent 双故障测试中重复启动第二个 Server 的兜底验证。
17. 删除图片记录提交前强杀测试中重复启动第二个 Server 的兜底验证。
18. 保留两类上传故障各自唯一的生产边界检查：错误必须显式返回，数据库不得出现记录或 cleanup intent。

## 行为变化

- Host 启动不再遍历全部项目媒体文件，也不再为无持久化意图的文件推断创建 cleanup intent。
- Host 启动不再自动删除数据库中没有项目记录的项目目录。
- 已登记 cleanup intent、过期临时视频上传和过期成片缓存仍按原有路径恢复。
- 管理员仍可在设置页先扫描、确认，再显式删除孤儿项目目录。
- 文件已写入但记录与 cleanup intent 均未持久化时，错误保持显性，文件不会被后续启动静默推断删除。
