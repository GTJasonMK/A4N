# 派生项目来源同步单一合同冗余清理记录

日期：2026-08-14

## 搜索起点与 BFS 覆盖范围

本专项分别从 Comic、Video、Galgame 三类派生项目工作区的“来源同步”功能出发，按广度优先顺序追踪显式调用和框架隐式入口。搜索清单累计命中约 258 个文件，覆盖前端页面、Host 合同、三类 Host、Runtime、Orchestrator、DB、Migration、Prompt 和项目族包导入导出。

```text
ComicProjectWorkspace / VideoProjectWorkspace / GalgameProjectWorkspace
MangaTab / GalgameTab
→ SourceSyncDialog
→ frontend sourceSync / project API
→ generated Host TypeScript
→ a4n-api-contract source_sync DTO / command manifest
→ Tauri 通用 Host dispatcher
  Web command router
  CLI command descriptor / typed invocation
→ a4n-runtime source_sync actions / projections
→ a4n-orchestrator source_sync service / preparation / decisions / workflow rules
→ a4n-db source_sync
   ├─ snapshot diff / candidate discovery / preview / conflict persistence
   ├─ safe apply / explicit decisions / detach
   ├─ Comic、Video generation spec 与 anchor 更新
   └─ Galgame scene regeneration / cleanup / conflict resolution
→ PostgreSQL baseline / incremental migration
→ project family package validation / import remap / export records
→ Galgame prompt renderer / workflow runtime snapshot
```

显式依赖覆盖函数调用、变量使用、模块导入、`pub use`、Serde/JsonSchema 类型、SeaORM 查询与事务。隐式依赖覆盖 command manifest、生成 TypeScript、Server 字符串路由、Tauri 通用调度、CLI descriptor、Runtime 配置快照注入、Orchestrator context、PromptRenderer trait、Workflow 记录、PostgreSQL trigger、项目族包校验与导入 ID remap。

仓库不存在 Source Sync 相关 XML DI、运行时反射注册、动态代理或 AOP 切面；所有入口均由显式 manifest、dispatcher、trait 注入和数据库迁移注册覆盖。

## 活跃生产场景覆盖

- Comic、Video、Galgame 三类派生项目的 preview。
- 无冲突 safe apply 与显式 conflict decisions apply。

- Galgame 单场重生成所需 Prompt renderer、Workflow run 和 runtime config snapshot。
- 派生项目彻底 detach，及 detach 后项目状态和来源关系清理。
- 项目族包导出、校验、导入和 Source Sync 主键 remap。
- PostgreSQL 新库 baseline 安装与已有库增量升级。
- Web、Tauri、CLI 三类 Host 的 typed input、typed result 和命令描述。

## 唯一实现决策

来源同步的事实标准收敛为：

```text
值域与跨层业务类型
→ a4n-domain::source_sync

Host 输入输出合同
→ a4n-api-contract::source_sync

权威 preview/apply 计划
→ a4n-db::source_sync::SourceSyncPlanRecord

业务编排与 Galgame 预生成
→ a4n-orchestrator::source_sync

持久化、冲突和事务状态
→ a4n-db::source_sync

数据库允许策略值域
→ source_sync_regenerate_scene_strategy migration
   与 PostgreSQL baseline 复用的同一策略集合
```

Runtime 和前端只做 transport projection，不再复制业务枚举、计划结构、状态推断或时间字段。Preview 与 Apply 返回同一种完整权威计划；同一来源同步能力不存在第二套 DTO、转换器、detach 实现或前端伪造计划。

## 已完成优化

1. 新增 `a4n-domain::source_sync`，统一 run mode、run status、change kind、local state、severity、conflict status、resolution strategy 和 decision actor。
2. 删除无生产者的 `exported` local state，Domain、API、Runtime 和 UI 只保留真实值域。
3. API Source Sync DTO 改为复用 Domain 枚举，不再维护字符串镜像。
4. 所有要求 JSON object 的字段改为 `Map<String, Value>`，在反序列化边界拒绝数组和标量。
5. 新增严格 `SourceSyncProjectInput`，preview 与 detach 不再接收宽松散字段。
6. Orchestrator 直接复用 API `SourceSyncDecisionInput`，删除 Runtime 决策 DTO 转换器。
7. 删除 DB `SourceSyncPreviewRecord` 与 Orchestrator `SourceSyncPlan` 两套镜像，统一为 `SourceSyncPlanRecord`。
8. Preview 与 Apply 均返回完整权威计划，不再返回结构不同的半成品。
9. 前端删除对 run status、时间戳和 decision JSON 的伪造。
10. 前端删除 Source Sync 重复 `userId` 参数，用户身份只由 Host 认证上下文提供。
11. 前端标签改为穷举真实枚举值，并补齐 `reordered` 与 `split`。
12. `SourceSnapshotChapterSummary` 移至 Domain/API 生成链，删除前端手写镜像接口。
13. `create_derived_project` 补 typed result，不再依赖宽泛未知返回值。
14. `list_source_snapshot_chapters` 补 typed result，前端直接使用生成合同。
15. 合并两套 detach DB 实现，保留唯一事务 owner。
16. `detach_derived_project` Host 命令返回 unit/null，不再构造无业务含义对象。
17. 删除 Preview 与 Apply 中重复的权限校验，权限只在统一上下文加载边界执行一次。
18. 删除 dry-run 固定对象的不可达 fallback，缺失权威记录直接失败。
19. Server 三个命令全部改用严格 typed input，不再手工提取宽松 JSON 字段。
20. Apply 使用 `strict_runtime_typed_input_schema` 与 `strict_runtime_command_input`，同时明确允许唯一合法的 `runtime_config_snapshot` transport 字段。
21. Host command manifest 版本提升至 8，标记本次破坏性合同收敛。
22. Runtime projection 对持久化枚举逐项严格解析，未知值显式返回内部合同错误。
23. Source Sync 内部 snapshot change、local state、severity、decision actor、strategy 和 status 全部改为 Domain 枚举。
24. 删除未知 local state 默认降级为 `info` 的兜底，损坏数据不再伪装为低风险冲突。
25. DB insert/resolve 输入只在最终落库边界调用 `as_str()`，业务层不再来回转换字符串。
26. 删除重复 `detaches_project` 字符串判断，直接使用 resolution strategy 枚举语义。
27. 项目族包导入 decision remap 改为解析并穷举 Domain strategy，不再维护独立字符串分支。
28. 项目族包校验和 workflow mode 改为复用 Domain 值域。
29. 新增 PostgreSQL `source_sync_regenerate_scene_strategy` 增量迁移，使数据库约束接受活跃 `regenerate_scene` 策略。
30. PostgreSQL baseline 直接复用增量迁移的决策触发器 SQL 常量，删除新库与升级库两份相同合同正文。
31. 更新 `REQUIRED_SCHEMA_MIGRATION` 与 migrator 注册顺序，启动检查指向最新必需迁移。
32. Host TypeScript 由 manifest 重新生成，不保留手写兼容类型。
33. CLI descriptor 实际重建核对：preview、apply、detach 均为 typed contract；apply 包含 runtime snapshot，detach 返回 null。
34. media provenance 指向不存在的 media asset 时不再 `continue` 并误判为 clean/draft，改为明确 `NotFound`。
35. Galgame 查询已限定非空 `text_anchor_id` 后不再静默跳过模型空值，改为明确内部状态错误。
36. `regenerate_scene` 缺少 Galgame execution context 时不再返回空 prepared context，准备阶段立即返回 `InvalidState`。
37. 保留 unchanged anchor、非当前 snapshot anchor、其他项目 generation spec 和非同一 Galgame 场冲突的过滤；这些是活跃业务范围约束，不是异常兜底。
38. 删除退役转换器、旧计划类型、重复 detach owner 和前端镜像后重新执行全链路退役符号搜索，无活跃残留。
39. DB Source Sync 与 Canvas 导入不再复制 `current/root_updated/conflict/detached` 字符串，统一复用项目 mutation 合同中的唯一状态常量。
40. 删除 Orchestrator `rules.rs` 中 22 个只转发 Domain 的状态常量、值域数组和 `is_valid_*` facade，项目族包校验与测试直接使用 Domain 枚举。

## 清理后调用拓扑

```text

→ strict SourceSyncProjectInput
→ Runtime 权限上下文
→ Orchestrator preview
→ DB snapshot diff + candidates + conflicts
→ SourceSyncPlanRecord
→ typed Host result

apply_source_sync_decisions
→ strict runtime input + runtime_config_snapshot
→ Orchestrator workflow
→ 非 regenerate：直接准备 typed DB decision
→ regenerate_scene：PromptRenderer 生成并校验单场计划
→ DB 单事务应用全部 prepared decisions
→ SourceSyncPlanRecord
→ typed Host result

detach_derived_project
→ strict SourceSyncProjectInput
→ Runtime 权限上下文
→ DB 唯一 detach 事务
→ unit/null
```

## 明确保留的活跃边界

- Comic、Video、Galgame 的 candidate 与 apply 分支保留，因为三类项目的数据图、冲突对象和写入动作真实不同。
- `SourceSyncExecutionContext.galgame` 保留为可选项，因为只有 `regenerate_scene` 需要 PromptRenderer；一旦选择该策略，缺失上下文会立即失败。
- 缺少 Galgame script、旧 snapshot chapter、scene 或 profile 引用时返回空候选集合的路径保留，它们表示该派生项目没有对应本地对象，不是异常成功回退。
- unchanged anchor、非本次旧快照 anchor、其他派生项目 generation spec、非同一 Galgame scene 冲突的跳过保留，它们限定当前运行的合法作用域。
- Workflow 失败终态写入保留，因为它是可观测性和恢复边界，不是业务结果 fallback。
