# 跨系统模型请求预览真实请求单一合同 BFS 冗余清理记录

日期：2026-08-14

## 结论

本批从内容优化、人物三视图、图片 Provider、蓝图生成、分部/章节大纲和漫画七阶段流水线六类可见功能入口出发，按 BFS 追踪前端、Host 命令、Runtime、Orchestrator、Prompt、Checkpoint、Provider 和真实生成状态机。

清理后的统一规则是：请求预览只返回当前持久化状态下能够精确构造、且真实执行路径会实际发送或复用的步骤。依赖尚未发生的模型输出、工具观察、补丁结果、前序阶段 JSON 或写库后上下文的后续请求不再以 `blocked`、`preview_placeholder` 或空请求伪装成成功预览；Provider 请求体构造失败直接返回原始错误。

未新增兜底、兼容、回退、占位、模拟输出、旧状态别名或第二套请求构造器。活跃源码净删除约 349 行。

## BFS 调用拓扑

### 内容优化 Agent Loop

```text
OptimizeTab
-> preview create/prepare analysis | preview send message
-> Host command / authenticated user
-> Runtime optimize request_preview
-> Orchestrator validated preview builder
-> build_first_agent_loop_chat_request(observations=[], step=1)
-> 真实第 1 个 ChatRequest

真实执行第 N+1 步
-> 模型 decision
-> think / tool call / tool result / patch_set_id
-> observations + step
-> checkpoint fingerprint / call_key
-> build_agent_loop_chat_request
```

后续请求依赖运行时决策、工具成功或失败结果、补丁状态和 checkpoint，预览时不存在可用输入，因此原两个 follow-up 步骤只是空请求占位。

### 人物三视图

```text
SinglePortraitDialog / CharacterPortraitsPanel
-> preview_generate_portrait_request
-> prepare_generate_portrait_request_preview_validated
-> character_portrait_generation Prompt
-> 真实提示词生成 ChatRequest

真实生成
-> resolve_initial_portrait_prompt
-> 模型返回 image_prompt
-> generate_portrait_image
-> 图片 Provider 请求
```

图片请求必须使用模型真实返回的 `image_prompt`，不能在预览时用空请求和说明文字代替。

### 图片 Provider 请求

```text
图片生成 / 立绘重绘 / 年龄变体 / 缺失立绘 / 图片配置测试
-> Runtime preview helper
   ├─ sidecar profile -> image sidecar 生成真实 Provider 请求体
   └─ embedded profile -> image_provider_request_body_preview
-> sanitize_preview_value
-> ModelRequestPreviewStep
```

未知 backend、不支持参考图或构建未启用时，真实请求体不存在；现在直接失败，不再把错误包装成 `state=blocked` 的成功响应。

### 蓝图四阶段

```text
Blueprint 页面
-> preview_generate_blueprint_request
-> preview_generate_requests
-> story_core 真实请求

真实生成
-> stage_outputs=[]
-> story_core
-> blueprint_stage_previous_context(stage_outputs)
-> world
-> characters
-> relationships
```

第 2 至 4 阶段均依赖前序阶段 JSON，预览只保留可真实构造的 `story_core` 请求。

### 分部与章节大纲

```text
OutlinesTab
-> 单批分部 / 分部章纲 / 跨分部批量 / 按数量章纲预览
-> Orchestrator 读取当前大纲上下文
-> 前导已有记录标记 reused
-> 第一个缺失目标构造真实请求

真实分部生成
-> 每轮模型输出
-> 写入或加入 generated_context_parts
-> 下一轮 previous_parts

真实章节生成
-> 每轮模型输出并写库
-> reload chapter outline generation context
-> 下一章请求
```

预览现在在第一个真实待发送请求处停止；不会把后续分部、章节或下一批分部改写成空 `blocked` 步骤。

### 漫画七阶段与断点恢复

```text
MangaTab
-> preview_start_manga_pipeline_request | preview_resume_manga_pipeline_request
-> prepare_manga_pipeline_preview_validated
-> 每阶段 build_manga_preview_call
   ├─ 指纹匹配 checkpoint -> reused + parsed_output，继续 BFS
   └─ 无 checkpoint -> ready + 真实 ChatRequest，停止
```

预览仍会沿真实 checkpoint 输出继续构造下一请求；遇到首个尚未执行的阶段后停止。删除的只是其后依赖未知模型输出的占位目录，不影响真实七阶段执行、恢复或分页后的逐页绘图请求。

## 清理后唯一事实标准

```text
当前可构造请求
-> 正式生产请求 builder
-> ModelRequestPreviewStep(state=ready, request=Some)

匹配的真实 checkpoint / 已有记录
-> ModelRequestPreviewStep(state=reused, request=None)

请求无法构造
-> 原始错误
```

不存在“为了展示完整流程而虚构后续请求”的第三条路径。

## 明确保留的真实边界

- 保留 Outline 已有记录和 Manga checkpoint 的 `reused` 状态；它们来自真实持久化事实，不是兜底。
- 保留合法图片媒体的脱敏预览；只移除构造失败后的伪成功。
- 保留人物三视图参考图 ID 的生产级输入校验；只删除依赖未知 image prompt 的 Provider 占位步骤。
- 保留 Blueprint 四阶段、Manga 七阶段和 Optimize Agent Loop 的完整生产执行；只删除预览中的未知后续步骤。
- 保留空步骤列表；当角色已跳过、没有缺失目标或没有待发送请求时，零请求比占位请求更准确。
