# 项目成员与邀请认证身份分叉清理记录

日期：2026-08-12
编号范围：R-1839～R-1863

## BFS 搜索覆盖范围

从“项目成员列表、邀请、我的邀请、接受/拒绝/撤销邀请、角色修改、移除成员和离开项目”逐层广度优先展开：

1. 页面与前端 API：成员和邀请管理 UI、十个 typed API、当前用户存储。
2. Host manifest：默认 `USER_CONTEXT`、`USER_PROJECT_CONTEXT`、项目 context、args/result schema 和 effect 元数据。
3. Web/Tauri/CLI：认证 transport 的 caller ID、Tauri Host dispatcher、CLI session context 与目标 ID 注入。
4. Server handlers：每条命令的 `user_id`、`projectId`、`inviteId`、`memberUserId` 和 typed `input` 实际读取。
5. Runtime/Orchestrator/DB：项目角色门禁、邀请归属、成员目标校验、自移除/离开规则和事务写入。
6. 隐式入口：动态 command 字符串、生成 Host 清单、测试、脚本和配置。

十个 Server handlers 都只把认证 transport 的 `user_id` 当 caller；`inviteId` 与 `memberUserId` 是业务目标，不能与 caller 混为一谈。前端和 manifest 仍维护第二份 args `userId`，且接受/拒绝/撤销/移除等目标参数原本为 opaque。未发现 XML、反射、动态代理、AOP 或依赖注入容器配置。

## 唯一实现结论

- caller 身份只来自认证 transport。
- 项目作用域只由 `projectId` context 表达。
- 邀请和成员目标只由 `inviteId`、`memberUserId` 表达，并使用严格 schema。
- Runtime/Orchestrator 继续独占权限和归属判断；Host 不增加重复身份 gate。
