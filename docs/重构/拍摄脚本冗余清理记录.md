日期：2026-08-11

## 搜索起点与覆盖范围

以“用户在章节正文页查看、逐场景生成、完整生成、恢复、编辑并保存结构化拍摄脚本”为功能起点，按广度优先顺序检查：

1. 前端入口：`ChapterWorkspace -> ShootingScriptTab -> ScriptContent/StructuredScriptEditor`，以及生成、恢复、编辑、取消和下游失效提示。
2. Host 合同：`a4n-api-contract`、生成 Host TypeScript、command manifest、Tauri 命令注册、Web dispatch 与 CLI capability 元数据。
3. Runtime：`actions/shooting_script_records` 的读取、逐单元生成、完整生成、编辑和 Host read-model 投影。
4. Orchestrator：用户权限 application、章节来源解析、请求准备、workflow 身份、逐阶段 LLM 调用、结构化修复、checkpoint 恢复、装配、发布和编辑失效传播。
5. DB 与领域：拍摄脚本 entity、查询、codec、insert/update/edit、领域 schema、领域校验和 migration 注册。
6. Prompt 与隐式入口：prompt registry、四个拍摄脚本 prompt、workflow business key/fingerprint、Serde/Schemars、生成类型和结构化 repair checkpoint。
7. 下游消费者：Manga、Video、Galgame、source-sync、项目族导入校验、项目依赖图和章节来源快照解析。
8. 横向对比：全仓搜索重复 DTO、Runtime facade、JSON Value 往返、screenplay 双子树、布局/计划容器、整章重复校验、raw checkpoint fallback、临时别名、占位标题和旧 core 类型路径。
9. 框架检查：未发现该功能相关 XML、反射调用、动态代理、AOP 切面或额外依赖注入配置；动态入口由 command manifest、Tauri/Web registry、prompt registry 和 workflow key 覆盖。

## 活跃调用拓扑

```text
ChapterWorkspace / ShootingScriptTab
  -> generated Host API
  -> Tauri command / Web dispatch / CLI capability
  -> Runtime shooting_script_records action
  -> Orchestrator user-validated application
  -> chapter source + current shooting-script DB owner

generate / generate-next
  -> chapter_shooting_script workflow
  -> screenplay skeleton
  -> layout detail per unit
  -> performance-fact adaptation per unit
  -> shooting design per unit
  -> deterministic typed assembly
  -> domain ChapterShootingScriptV1 validation
  -> atomic insert/update

checkpoint recovery
  -> exact request fingerprint
  -> completed checkpoint parsed_output
  -> stage-boundary validation

downstream consumers
  -> Manga shooting projection
  -> Video execution/prompt projection
  -> Galgame shooting projection
  -> source-sync and project-family validation
  -> project dependency graph
```

## 生产数据证据

- 开发库 `a4n` 只读审计发现拍摄脚本 2 条，均为 `chapter_shooting_script_v1`。
- 两条记录的 source/input/script SHA-256 均为合法值。
- 264 个拍摄脚本主阶段 completed checkpoint 全部具有非空 `parsed_output`；没有任何活跃 checkpoint 依赖 raw response fallback 才能恢复。
- 相关 workflow 状态包含 2 个 completed、2 个 failed、1 个 interrupted，以及 cancelled 历史记录；恢复链必须保留 exact fingerprint 和 typed checkpoint，不能把失败或取消伪装成成功。
- `transition_type` 现有 15 种生产字符串，包括 `continuous`、`continuity`、`cut`、`sound_bridge`、`time_ellipsis`、`action_continuity`、`direct_cut`、`TIME_CUT`、`直接连戏` 等。
- 因生产数据尚未收敛为单一转场枚举，本专项只拒绝空值、自指和骨架外目标；未在没有数据迁移策略时破坏现有记录。

## 当前事实标准

拍摄脚本只保留一套实现：API/domain 提供 canonical DTO 与 schema；Runtime 只做 Host transport 和 typed projection；Orchestrator 拥有权限、workflow、逐单元 LLM 编排、阶段边界校验与发布；DB owner 负责持久化和下游失效；领域 `ChapterShootingScriptV1::validate()` 是最终结构不变量。恢复只接受 exact fingerprint 的 typed completed checkpoint，不保留 raw 重解析、repair artifact 兼容、默认值、占位标题、镜像 DTO、重复 screenplay 容器或第二套整章校验。
