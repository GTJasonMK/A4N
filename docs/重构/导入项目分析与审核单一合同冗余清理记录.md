# 导入项目分析与审核单一合同 BFS 冗余清理记录

日期：2026-08-14

## 结论

本专项从小说项目详情页的“导入文件、审核队列、项目分析、分析请求预览、取消分析、批量接受和段落去重”功能出发，按 BFS 覆盖前端、生成合同、Host 清单、Web/Tauri/CLI 分发、Runtime、Orchestrator、章节分析 Host Port、数据库事务、派生资料同步与项目状态消费者。

BFS 确认主要冗余不是完整功能，而是围绕同一导入能力长期并存的第二合同：后端以动态 `serde_json::Value` 维护单阶段进度，却保留多阶段 schema、恢复、汇总和 completion 模块；Runtime 与 Server 又把结构化错误压成字符串；Manifest 将同步执行伪装为 task，并为不读取文件的命令声明通用文件输入；前端再维护一套全可选进度镜像、动态阶段遍历、百分比钳制、空弹窗和缺省文案。

本批将进度、运行结果、预览、审核摘要和去重结果收敛到 `a4n-api-contract` 的唯一强类型合同；删除 7 个旧进度/汇总模块和全部动态阶段解释器；保留真实可恢复的章节正文同步工作流，不把已提交成功的审核误报为失败。

未新增兜底、兼容转换、回退、占位值、适配器、任务外壳或第二套校验。

## BFS 调用拓扑

```text
ImportsTab
  ├─ 导入文件
  │  -> importProjectTextUpload
  │  -> import_project_text_upload Host command
  │  -> Runtime 文件解码 / a4n-import-core 解析
  │  -> Orchestrator ingest 输入门禁
  │  -> DB import_review_queue 批量写入
  ├─ 审核队列
  │  -> list / accept / batch accept / reject / delete
  │  -> Server/Tauri/CLI Host dispatch
  │  -> Runtime import_review actions
  │  -> Orchestrator 权限与状态门禁
  │  -> DB 审核事务与章节 upsert
  │  -> chapter_content_sync 持久工作流
  │  -> 派生资料清理、当前章节 RAG、风格标签与项目状态同步
  ├─ 项目分析
  │  -> run / progress / cancel / preview
  │  -> Runtime ChapterAnalysisHostPort
  │  -> Orchestrator import_analysis workflow
  │  -> 逐章 run_chapter_analysis_validated
  │  -> 章节分析、角色/场景/伏笔/RAG 派生同步
  │  -> project.import_analysis_progress
  │  -> sync_project_status_from_artifacts
  └─ 段落去重
     -> check_import_dedup
     -> DB 当前项目章节正文
     -> a4n-import-core SimHash
     -> 唯一最近章节与距离结果
```

宿主路径：

```text
Web  -> a4n-server 显式 command dispatch
Tauri -> invoke_host_command -> 同一 a4n-server dispatch
CLI -> command_manifest -> HTTP Host command -> 同一 Server dispatch
```

## 入向引用闭包

- `ParsedChapterInput` 只用于把 `a4n-import-core::ParsedChapter` 复制成同形 DTO。
- `ValidatedParsedChapter` 只用于随后立即构造审核输入，形成第二中间对象。
- `contracts.rs` 只定义上述重复 DTO。
- `progress/schema.rs` 维护动态阶段对象、计数提取和百分比重算。
- `progress/updates.rs` 维护动态更新、失败和完成逻辑。
- `progress/resume.rs` 维护字符串阶段索引与恢复解释。
- `progress/persistence.rs` 加载时会静默重算并改写派生百分比。
- `summary.rs` 只从动态 JSON 再次提取已完成章节数。
- `workflow/completion.rs` 只包装完成、保存和项目状态同步。
- `PreparedImportAnalysisRun::Completed` 把已完成进度当作隐藏缓存，导致用户再次运行时不执行分析。
- Runtime 的结果映射只把同名字段复制到另一 DTO。
- `import_analysis_error`、Runtime `map_err(to_string)` 和 Server `bad_request` 构成三层错误类型丢失。
- 前端 `ImportAnalysisStage`、可选 `ProjectImportAnalysisProgress` 和 `ImportProjectAnalysisSummary` 与后端结果重复。
- `projectProgressPercent`、`importProgressTotals` 和 `importAnalysisStatus` 只服务宽松旧合同。
- `emptyImportAnalysisDialog` 和“正在启动”总数 1 只制造后端尚未确认的占位进度。
- `u32::MAX` 只用于表达“没有任何章节可比较”，属于对外泄露的哨兵值。
- `finish_import_review_acceptance` 只有一个调用点且只返回 `Ok(())`；真实的持久恢复语义保留并直接内联。

## 清理后唯一事实标准

```text
a4n-api-contract
  -> Rust API / Manifest schema / generated host.ts
  -> Runtime / Server / Tauri / CLI / Frontend
```

```text
ProjectImportAnalysisProgress
  -> Orchestrator progress 唯一状态机
  -> project.import_analysis_progress 唯一持久化槽位
  -> Runtime typed result
  -> Frontend generated type
```

- 同一导入分析状态只由强类型进度合同表达。
- 同一章节完成数只来自 `generating_analysis_data.completed`。
- 同一进度百分比只由后端从完成数和总数派生并校验。
- 同一去重匹配只来自一次最近距离计算。
- 同一文件解析章节 DTO 使用 `a4n-import-core::ParsedChapter`。
- 同一审核接受事务由 `a4n-db::import_review::accept_import_review` 持有。
- 同一章节正文派生同步由可恢复的 `chapter_content_sync` 工作流持有。

## 保留边界

- 保留导入文件、审核、分析、预览、取消和去重全部活跃功能。
- 保留项目编辑权限、审核状态行锁、章节 upsert 事务和批量接受的部分提交错误报告。
- 保留 `chapter_content_sync` 失败后的持久恢复语义；主审核事务已经提交时返回成功，避免客户端把成功接受误判为失败并重试单次审核。
- 保留大纲生成源快照中的 `import_analysis_progress`，因为分析变化必须使并发大纲保存失败。
- 保留真实文件上传命令 `import_project_text_upload` 的 CLI 文件输入提示。
- 保留当前单阶段持久化 JSON 外形；这是当前活动合同，不读取或转换已退役的多阶段格式。
- 保留项目资料反向归纳功能。本批确认它是独立兄弟能力，后续必须从其真实入口单独 BFS，重点处理 opaque 合同、重复 `userId` 和 warnings 软化路径。
