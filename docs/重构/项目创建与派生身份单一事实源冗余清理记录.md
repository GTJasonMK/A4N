# 项目创建与派生身份单一事实源冗余清理记录

日期：2026-08-15

## 搜索起点与 BFS 覆盖范围

本专项从三个真实功能入口同时出发：文本项目创建、自由画布视频项目创建、Comic/Video/Galgame 派生项目创建。按广度优先顺序追踪创建后的全部身份消费者，而不是只搜索创建函数。

```text
NovelList 创建文本/自由画布/派生项目
→ frontend/src/api/project.ts
→ generated Host TypeScript
→ a4n-api-contract DTO / command manifest / JsonSchema
→ Web Server 字符串 dispatch
  Tauri invoke_host_command 通用入口
  CLI project create / command descriptor
→ a4n-runtime project_records actions / ProjectSummary projection / permission
→ a4n-orchestrator project mutation application
→ a4n-db project mutation / source snapshot transaction
→ SeaORM novel_project / project_source_snapshot
→ PostgreSQL baseline / incremental migration / family integrity trigger
→ 创建后身份消费者
   ├─ Source Sync preview / apply / detach
   ├─ text / derived / freeform 项目复制
   ├─ 单项目与项目族删除
   ├─ 项目族 metadata / export / import / package validation
   ├─ 项目资产依赖图
   └─ media / canvas / generation 上下文
```

静态候选集按四组符号建立并取并集：

- 创建入口与 DTO：64 个文件。
- 旧派生身份：`project_derivation / parent_project_id / derived_project_status / creation_options_json`，清理前 79 个文件。
- 现行身份事实：`root_project_id / source_snapshot_id / chapter_scope_json / source_sync_status / project_kind`，607 个文件。
- 项目族包合同：74 个文件。
- 去重后的 BFS 候选集共 677 个文件；最终修改 99 个代码文件，并新增本记录与一项不可逆迁移。

显式依赖覆盖 Rust/TypeScript 调用、字段读写、模块导入与 `pub use`、SeaORM entity/query/transaction、Serde 和 JsonSchema 类型。隐式依赖覆盖 Host manifest、生成 TypeScript、Server 字符串路由、Tauri 通用命令注册、CLI descriptor、Orchestrator context 注入、项目族 ZIP manifest、PostgreSQL trigger/function、migration 注册顺序和 baseline 安装。

配置文件扩展名扫描未发现该功能相关的 XML、YAML、JSON、TOML 路由或 DI 注册；仓库也不存在该链路的反射调用、动态代理或 AOP 切面。实际动态入口只有 Host 字符串 dispatch、Tauri 通用 dispatcher、Serde 包反序列化和 PostgreSQL trigger，均已纳入闭包。

## 生产场景与数据核验

覆盖的活跃场景包括：

- Web/Tauri 创建文本项目和自由画布视频项目。
- Web 创建 Comic、Video、Galgame 三类派生项目。
- CLI 创建文本项目。
- 协作者创建派生项目时继承根项目 owner。
- 派生项目来源同步、复制、删除、项目族导入导出与资产图读取。
- PostgreSQL 新库 baseline 和已有库增量升级。

开发库只读核验结果：

- 项目 51 个，其中文本项目 47 个、派生项目 4 个。
- `project_derivation` 4 条，与 4 个派生项目一一对应。
- 4/4 的 `parent_project_id == root_project_id`。
- 4/4 的 `derived_project_status == draft`。
- 4/4 的 `creation_options_json == {}`。
- `project_derivation.chapter_scope_json` 与源快照范围不一致为 0。
- 派生关系的 root、kind、snapshot 与 `novel_project` 不一致为 0。

因此旧关系表和三个字段没有独立业务语义，属于同一派生身份的重复持久化。

## 唯一事实标准

```text
项目实体与派生类型
→ novel_project.project_kind

派生项目所属根项目
→ novel_project.root_project_id

派生项目当前源快照
→ novel_project.source_snapshot_id

派生章节范围
→ project_source_snapshot.chapter_scope_json

来源同步状态
→ novel_project.source_sync_status

文本/派生/自由画布来源模式
→ novel_project.source_mode
```

`project_derivation`、`parent_project_id`、`derived_project_status` 和 `creation_options_json` 不再是事实来源，也不保留别名、adapter、兼容读取或回填逻辑。

## 已完成优化

1. 删除完整 SeaORM `project_derivation` entity 文件和模块导出。
2. 删除 PostgreSQL baseline 中的 `project_derivation` 表、索引、函数和 trigger。
3. 删除 `novel_project.parent_project_id` 模型字段及所有生产读写。
4. 删除 `novel_project.derived_project_status` 模型字段及唯一固定值常量和校验器。
5. 删除派生创建参数 `creation_options_json` 与 Host `creation_options` 输入。
6. 派生创建只写 `novel_project` 和唯一 `project_source_snapshot`，不再插入重复关系行。
7. 派生项目复制直接从项目主体和源快照复制身份，不再查询、校验或重建关系行。
8. Source Sync 章节范围改从当前源快照读取，不再查询关系表。
9. Source Sync apply 只更新 `novel_project.source_snapshot_id`，不再同步第二张身份表。
10. 项目族 metadata 的章节范围改为直接投影源快照。
11. 项目族导出删除关系表查询、snapshot ID 汇总分支和导出字段。
12. 项目族包升级为 `project_family_v2`，manifest 删除 `project_derivations`。
13. 项目族 v1 明确版本不匹配，不增加旧包兼容读取。
14. 项目族校验改为直接核对派生项目的 root、snapshot 与快照归属。
15. 项目族导入删除关系行 ID remap 和插入流程。
16. 项目删除直接使用 `novel_project.source_snapshot_id` 删除当前源快照图。
17. 资产依赖图删除关系表查询和 `derivation_count` 镜像字段，派生节点只由实际项目生成。
18. freeform media、package 与 canvas 校验删除两个已退役字段分支。
19. 文本、派生、freeform 三类项目复制公共写入结构删除 `parent_project_id`。
20. 更新所有生产 ActiveModel 初始化、导入上下文和迁移夹具，移除旧字段写入。
21. 删除 Orchestrator 创建方法中的重复 trim/必填校验，保留 Runtime 外部边界和 DB 持久化不变量。
22. 删除仅服务于宽松 Option 合同的 `required_optional_text` helper 及测试。
23. `CreateProjectInput.project_type` 改为必填，合同与实际 Runtime 必填行为一致。
24. CLI `project create --project-type` 改为必填，不再发送必然被拒绝的缺失值。
25. `CreateDerivedProjectInput.description` 改为必填，合同与实际 Runtime 必填行为一致。
26. `create_project` 与 `create_freeform_video_project` 改用 strict typed input，拒绝未知顶层字段。
27. `create_freeform_video_project` 返回合同由 opaque 收敛为真实 `ProjectSummary`。
28. Host command manifest 版本从 8 提升至 9，标记本次破坏性创建合同变化。
29. 重新生成前端 Host 类型，删除手写或宽松镜像可能性。
30. 新增不可逆迁移 `project_derivation_identity_cleanup`，升级前拒绝任何拥有独立语义或不一致的旧数据。
31. 迁移删除旧关系表、旧列和旧校验函数后，重建仅依赖现行字段的项目族 trigger。
32. baseline 与增量迁移复用同一组项目族 trigger SQL 常量，删除两份合同正文。
33. 修改会在新 baseline 后执行的历史迁移 SQL，移除对已删除列的引用。
34. 更新 `REQUIRED_SCHEMA_MIGRATION` 和 migrator 注册顺序。
35. 全仓旧符号复核后，活跃代码、生成合同、脚本和框架配置中无旧身份消费者残留。

## 迁移与行为边界

- 迁移不会猜测或修复分叉数据：发现关系表、项目主体、源快照、父项目字段、固定状态或创建选项存在独立语义时立即失败。
- 迁移不可逆，不重建已删除的重复身份。
- 项目族旧 v1 包不兼容导入；新导出只生成 v2。
- Host 创建输入不再接受未知顶层字段，`project_type` 与派生项目 `description` 必须显式提供。
- 没有新增默认值、fallback、兼容别名、adapter 或占位字段。
