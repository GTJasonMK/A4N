# 项目包导入导出边界冗余清理记录

## 搜索覆盖范围

本专项从项目列表和视频画布的项目包导入、导出功能出发，按 BFS 逐层追踪：

```text
NovelList / ProjectImportDialog / VideoStudioCanvas
→ frontend project API / generated Host contract
→ command manifest
→ Web dispatch / Tauri 通用调度 / CLI generic call
→ Runtime family_api / video_studio_api
→ 项目包文件名与原始 Base64 边界
→ family package / video studio package ZIP Host
→ Orchestrator project family / video studio transfer
→ manifest、媒体索引与数据图完整性校验
→ a4n-db project_family_import / canvas transfer transaction
→ 媒体物理文件写入
→ 失败时 cleanup outbox
```

横向覆盖以下活跃分支：

```text
项目族根项目导出
单个派生项目导出
自由视频画布项目导出
三类 ZIP 上传恢复
embedded import/export core
import/export sidecar
Web、Tauri、CLI 三种 Host 入口
协作 Owner 权限
数据库事务、媒体 ID 重映射与物理文件回滚
```

显式依赖覆盖 Rust/TypeScript 调用、模块导入、trait 实现、Host command、Server 路由、Tauri 调度、CLI `--set-base64`、SeaORM 事务和文件写入；隐式依赖覆盖 Serde/JsonSchema、生成 TypeScript、包版本和 mode、ZIP manifest、sidecar capability、媒体 checksum/size、cleanup outbox 去重键与项目目录约束。项目未使用 XML DI、反射、动态代理或 AOP；动态分派只来自显式 Host command 和 sidecar capability，均已纳入闭包。

## 生产数据与合同证据

- 生产代码只接受 `.a4n-family.zip` 和 `.a4n-video-studio.zip`；仓库旧 JSON 项目恢复仅残留在操作文档。
- `frontend/src/utils/fileUpload.ts::readFileAsBase64` 会剥离 data URL 头；CLI `--set-base64` 直接写入原始 Base64，两个活跃入口都不发送 `data:*;base64,...`。
- `data/` 及排除 `target`、`node_modules` 后的仓库中均没有可作为旧格式生产样本的项目包文件。
- 通过 `a4n-postgres` 容器对开发库和隔离测试库执行只读查询：空白标题为 `0`，清洗后仅由控制字符、路径非法字符、空格或点组成的标题为 `0`。
- 项目创建和更新入口已有非空标题规则；两种不可信项目包现在同样复用该规则，禁止导入空标题绕过正常项目写入边界。
- 项目族包和视频画布包对应不同数据图，不能合并为单一 manifest：前者包含文本根项目、派生项目、快照、生成与媒体图；后者包含 freeform 项目、画布、节点、生成与媒体图。

## 优化记录

1. 新增 `project::package_transfer` 作为项目包传输共享 owner。
2. `ExportedProjectPackage` 取代两个字段完全相同的导出结果类型。
3. `ImportProjectPackageApplicationInput` 取代两个字段完全相同的导入 application 输入。
4. `ProjectPackageTransferError` 取代项目族和视频画布两套相同错误枚举。
5. `ProjectPackageFileHostPort` 成为媒体写入和失败回滚的唯一共享合同。
6. `import_result_with_file_rollback` 取代两份相同的错误合并与文件回滚实现。
7. 删除 `rollback_imported_media_files` 从未使用的 `label` 参数及所有伪调用文案。
8. 项目族完整 manifest 校验失败直接返回，不再执行尚未写入任何文件的空回滚。
9. 视频画布完整 manifest 校验前移到传输 application，非法版本不再执行空回滚。
10. Canvas 数据库 owner 删除重复校验职责，只接收已经校验的包落库。
11. 删除 Canvas 导入方法不再使用的 `media_payload` 参数。
12. Runtime 建立唯一 `RuntimeProjectPackageTransferHostPort`，同时承载两种包的类型化 ZIP 行为。
13. 删除项目族 Runtime Host 中重复的 `state`、`written_paths`、`cleanup_token`、构造、写文件和回滚实现。
14. 删除视频画布 Runtime Host 中同一套重复状态和文件副作用实现。
15. 删除两份包专用 Runtime Host 文件，由共享 Host 唯一记录已写入路径并投递 cleanup outbox。
16. `project_package_import_input` 统一执行文件名校验、Base64 解码和 application 输入构造。
17. 删除项目族和视频画布 API 中重复的“文件名校验 → Base64 解码 → 输入构造”流程。
18. 删除上传端对 `data:*;base64,...` 的兼容拆分，只接受 Host 合同规定的原始 Base64。
19. 删除 Base64 非空输入成功解码后再次判断空字节的不可达分支。
20. 删除导出文件名的 `project-{id}` fallback；标题无法生成安全文件名时显式失败。
21. 两类项目包 manifest 复用项目标题非空规则，禁止通过导入绕过项目写入不变量。
22. `project_package_media_zip_entries` 成为包内媒体物理文件读取和 ZIP entry 构造的唯一实现。
23. 删除项目族和视频画布两份结构相同的媒体 ZIP entry 循环。
24. ZIP 声明路径只由 `a4n-import-core` 在归档读取边界校验，删除 Orchestrator/Runtime 的重复包装和重复测试。
25. 删除两类 reader 的 manifest parse 别名函数，直接调用现有 `a4n-import-core` 泛型解析器。
26. `required_path_extension` 统一路径扩展名提取，删除项目族导出、项目族导入和视频画布导出的三份相同标准库链。
27. 更新操作流程，删除已经不存在的旧版文本 JSON 项目恢复说明。

## 清理后唯一事实标准

```text
项目包共享传输合同
→ a4n-orchestrator::project::package_transfer

Runtime 媒体文件副作用
→ RuntimeProjectPackageTransferHostPort

上传边界
→ project_package_import_input
→ 规范后缀 + 原始 Base64

ZIP 路径安全
→ a4n-import-core

ZIP 媒体文件读取
→ project_package_media_zip_entries
```

两种包继续保留唯一且独立的 manifest、校验和数据库导入实现：

- 项目族：`family_package` / `project_family_import`。
- 视频画布：`video_studio_package` / `canvas::transfer`。

未新增格式兼容、默认值、回退、占位 trait、泛型包框架或第二套业务规则。
