# 生成进度阶段语义冗余清理记录

## 搜索覆盖范围

本专项从章节、蓝图、灵感、内容优化、图片、立绘、视频和视频提示词的生成进度展示出发，按 BFS 逐层追踪：

```text
Orchestrator generation producer
→ GenerationEventPublisher / ProgressEvent
→ a4n-service-protocol schema、校验与 snapshot/replay
→ Web SSE / Tauri Channel / generation client
→ generation event reducer / generation task store
→ runGenerationProgressTask
→ ProgressDialog / workflow 与 queue 进度面板
```

横向覆盖以下活跃执行路径：

```text
LLM 连接、等待与流式输出
章节、蓝图、灵感与三类内容优化
图片、立绘、视频的步骤进度
视频提示词生成、草稿 checkpoint 与单项提交
任务快照恢复、事件重放与前端 E2E harness
通用 workflow/task 持久进度展示
```

显式依赖覆盖 Rust 调用、trait publisher、Serde/JsonSchema、生成 TypeScript、React hooks、store 和组件；隐式依赖覆盖 generation schema 生成脚本、snapshot/replay 合同、数据库持久进度中的 `a4n-domain::progress::ProgressMeta`，以及 Web/Tauri 两种传输入口。项目没有 XML DI、反射、动态代理或 AOP；动态分派只来自显式 generation event kind 与 Host transport，均已纳入闭包。

## 清理前分叉

```text
a4n-domain::progress::ProgressPhaseKind
  → model_connect / model_wait / model_stream / structured_output / save / asset_generation ...

a4n-service-protocol::ProgressPhaseKind
  → provider / stream / parse / persist ...

frontend generationProgressMeta
  → 再维护 stage_code → 展示 phase 映射
  → 未知 stage 再回退到粗粒度 phase

frontend progressDisplay
  → meta 缺失时按中文 message 正则猜测阶段
```

同一阶段语义由 domain、service protocol 和 frontend 三处维护；新增 stage 时可能出现协议接受、前端误判或 ETA 行为分叉。

## 优化记录

1. `a4n-service-protocol` 直接使用 `a4n-domain::progress::ProgressPhaseKind`。
2. 删除 service protocol 自有的粗粒度 `ProgressPhaseKind` 枚举。
3. `a4n-service-protocol` 直接使用 `a4n-domain::progress::ProgressSeverity`。
4. 删除 service protocol 自有的重复 `ProgressSeverity` 枚举。
5. 删除 `public_progress_phase` 的 stage→phase 第二映射。
6. 删除只验证上述重复映射的 phase mismatch 测试分支。
7. LLM 连接、等待和输出改为直接发布 `ModelConnect`、`ModelWait`、`ModelStream`。
8. 章节和蓝图流式生成直接发布 `ModelStream`，不再依赖前端 stage 解释。
9. 视频提示词持久化阶段统一使用 domain 的 `Save`。
10. 新增唯一 `step_progress_state`，合并通用生成步骤与视频提示词两套阶段/严重度判断。
11. 修复 `current=0,total=0` 被两套旧逻辑误判为成功完成的问题。
12. 重新生成 generation JSON Schema 与 TypeScript，传输枚举与 Host 枚举保持同源。
13. 删除前端 `STAGE_PHASE` 映射表。
14. 删除前端 `PHASE_FALLBACK` 回退表及默认 `prepare` 路径。
15. 删除前端 `STAGE_LABEL` 第二文案表，阶段文案直接使用生产者消息。
16. 删除 `generationProgressMeta` 的默认 `taskKind="generation"` 占位，改用 StartedEvent 的真实 `task_kind`。
17. StartedEvent 缺失时显式报错，不再伪造 task kind。
18. 删除 `progressDisplay` 按中文关键词猜测业务阶段的正则实现。
19. 删除按冒号拆分 message 并猜测 stage/detail 的分叉实现。
20. `progressDisplayModel` 删除对 typed meta 的运行时对象兜底，并避免阶段与详情重复显示。
21. 更新 generation store、hook 单测和视频模式 E2E harness，只接受新的唯一阶段枚举。
22. 删除 phase mismatch 测试退役后遗留的未使用 `progress` 测试 helper。
23. 图片、立绘和视频步骤显式使用 `AssetGeneration`，大纲与视频提示词使用 `ModelWait`；活跃阶段由生产者传入，不重建 stage→phase 映射。

## 清理后唯一事实标准

```text
阶段与严重度枚举
→ a4n-domain::progress

generation transport
→ ProgressEvent 直接携带 domain phase/severity

前端 generation 映射
→ 只转换 snake_case / camelCase 字段
→ phase_kind 原样传递

通用进度展示
→ 结构化 meta 优先
→ 无 meta 时只使用调用方显式 stageHint/fallbackStage
```

未新增兼容枚举、旧值别名、未知阶段回退、消息猜测规则或占位 task kind。
