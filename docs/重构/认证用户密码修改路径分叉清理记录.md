# 认证用户密码修改路径分叉清理记录

日期：2026-08-12
编号范围：R-1658～R-1674

## BFS 搜索覆盖范围

从“当前登录用户修改密码”功能入口逐层广度优先展开：

1. 前端入口：`AccountPanels.tsx::PasswordEditor`、`api/auth.ts::changeUserPassword`、Zustand `store/auth.ts`、生成的 `ChangePasswordInput` 以及 `apiInvoke` 的 Web/Tauri 双传输。
2. CLI 入口：`auth change-password` 的 stdin 密码读取、敏感值脱敏、专用请求构造，以及通用 `a4n call` 对敏感认证命令的禁用门禁。
3. Host 注册：API command manifest 的参数/结果/secret pointers、Tauri command registry、通用 `invoke_host_command`、Server `/commands/{cmd}` 路由和动态字符串 dispatcher。
4. 应用链路：Server 认证用户 ID、Runtime Host action、Orchestrator AuthApplication、DB `auth::change_password`。
5. 数据与失败路径：活跃用户检查、旧密码哈希验证、新密码非空校验、密码重哈希、更新时间写入、禁用用户、错误旧密码和空新密码。
6. 隐式依赖：Tauri command 宏、Clap stdin 参数、manifest secret pointers、前端本地认证状态、Axum Bearer 认证、动态命令字符串和 Rust/TypeScript 合同生成。

搜索未发现 XML、反射注册、动态代理、AOP 切面或依赖注入容器配置。UI 未使用 Zustand Store 的 `changePassword` 方法；Web、Tauri 和 CLI 的有效修改最终均进入同一个 DB 实现，原 caller/target 双身份仅用于重复自证。

## 优化记录

- R-1658：完成 UI、Store、CLI、Host、Runtime、Orchestrator、DB 和失败路径的全链 BFS。
- R-1659：command manifest 将 `change_user_password` 上下文字段从 `userId` 收敛为空，通用 CLI 不再注入第二身份。
- R-1660：command manifest 结果从 opaque 收敛为唯一 `unit` 合同，与 Server/Tauri 实际返回一致。
- R-1661：删除 Orchestrator 私有 `change_own_user_password` 中间层及重复同用户门禁。
- R-1662：Orchestrator 公共方法改为只接收认证用户 ID，直接调用唯一 AuthApplication 实现。
- R-1663：Runtime 将 `change_user_password_for_user` 重命名为唯一 `change_user_password`。
- R-1664：Runtime 删除 caller/target 双参数，只向下传递认证用户 ID。
- R-1665：Server 不再读取请求体 `userId`，修改目标只来自认证上下文。
- R-1666：删除 Tauri 专用 `change_user_password` 命令。
- R-1667：删除 Tauri command registry 中对应注册，桌面端统一进入 Host dispatcher。
- R-1668：前端 `runtimeInvoke` 不再把修改密码列为原生命令，Web/Tauri 使用同一业务分发路径。
- R-1669：前端 `changeUserPassword` 删除请求体 `userId`，只发送唯一 `input`。
- R-1670：CLI 修改密码不再为取得目标 ID 额外请求 `current_user`。
- R-1671：CLI 修改密码请求不再发送 `userId`，保留 stdin 与敏感值脱敏安全边界。
- R-1672：删除 Zustand AuthStore 从未被消费的 `changePassword` 公共类型成员和 API 导入。
- R-1673：删除 Zustand AuthStore 从未执行的 `changePassword` 状态包装实现。
- R-1674：补充 manifest、前端 API 和 Tauri dispatcher 防回归断言，固定唯一身份与唯一 Host 路径。

## 唯一实现结论

- Host DTO：`a4n_api_contract::auth::ChangePasswordInput`。
- 身份来源：只使用 Server/Tauri dispatcher 的认证用户，不再接受业务请求体目标用户 ID。
- Host 路径：前端业务统一经通用 dispatcher；Tauri 不再保留专用修改密码命令。
- 应用实现：`a4n_runtime::actions::auth_records::change_user_password` → `OrchestratorContext::change_user_password` → `a4n_db::auth::change_password`。
- 前端调用：设置页直接调用 `api/auth.ts`；Zustand 不再维护无人使用的第二包装。
