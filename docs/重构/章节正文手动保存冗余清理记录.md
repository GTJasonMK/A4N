# 章节正文手动保存 BFS 冗余清理记录

日期：2026-08-12
编号范围：R-1965～R-1996

## BFS 搜索覆盖范围

1. 前端入口：`WritingDesk.handleSaveContent` 的首次保存/已有章节保存、项目详情 `ChaptersTab` 导入，以及所有消费章节返回值的写作台、优化、故事事件和拍摄脚本组件。
2. CLI 入口：`a4n chapter import`、`a4n chapter update`、通用 `a4n call` 的 command manifest 上下文注入与文件输入元数据。
3. Transport：Web `apiInvoke`、Tauri runtime invoke、Server `/commands/{cmd}`、Bearer 身份解析、command dispatcher 和 `command_input` serde 边界。
4. 合同：`a4n-api-contract::chapter`、command manifest、TypeScript 生成器及 `frontend/src/api/generated/host.ts`。
5. Runtime：章节导入、编辑、列表、章节同步状态投影，以及章节分析 workflow 对 `ChapterSummary` 的消费。
6. Orchestrator：Editor 权限、文本项目门禁、章节同步锁、锁前/锁后复核、正文预检、正文与 sync plan 事务、派生清理/RAG 同步和可恢复 workflow。
7. DB：手动编辑、首次导入、AI 生成完成、导入审核接受、优化补丁应用五条正文写入路径；同时覆盖章纲关联、生成目标失效、审核事务和优化记录。
8. 下游依赖：角色快照回滚、伏笔/对象/角色/场景资料清理、章节 RAG、项目状态同步、generation target 清理和 workflow resume dispatch。
9. 隐式入口：全仓 Rust/TypeScript 命令字符串、路由表、serde 注解、生成文件、测试、脚本和文档。未发现 XML 注册、反射调用、动态代理、AOP 切面或第二套依赖注入容器配置；活跃注入点为显式 `ChapterDerivedCleanupHostPort`。

横向核对确认：AI 生成、审核接受、优化补丁与手动保存都修改章节正文，但其事务边界、状态推进和来源数据不同；它们不是可直接删除的重复业务流。真正相同的“正文变更后旧分析必失效”不变量已收敛为唯一 DB owner。

## 清理前调用拓扑

```text
WritingDesk / ChaptersTab / CLI
  -> 手写 input + caller userId + 无消费者 manual
  -> opaque command manifest
       import_chapter 被误标 task / task_id / client_request_id / 文件输入
       update_chapter_content 被误标顶层 chapterId context
  -> Runtime 手写 Import/Update DTO + ChapterSummary + material sync DTO
  -> Orchestrator import 返回 (chapter, word_count)
  -> Runtime debug_assert 重复比较模型内已有 word_count
  -> DB import 测试 facade / transaction facade 两套入口

正文写入横向分叉
  -> edit.rs / import/* / generation.rs / import_review/chapter.rs / optimize/context.rs
  -> 五处重复设置 content、word_count、status、summary、style_tags、analysis_data、updated_at
```

## 清理后调用拓扑

```text
WritingDesk / ChaptersTab / CLI
  -> generated ImportChapterInput / UpdateChapterContentInput
  -> Web/Tauri 认证身份
  -> Server strict command_input
  -> Runtime 复用 API Contract
  -> Orchestrator Editor + text-project + sync lock + preflight
  -> 单事务：正文写入 + derived cleanup plan + workflow run
  -> 可恢复的外部清理 / RAG / postprocess
  -> generated ChapterSummary

所有正文写入
  edit / import / generation / import review / optimize
    -> assign_chapter_content（唯一失效不变量）
    -> 各流程只保留自身必要的标题、章纲、审核、生成来源和优化记录语义
```

## 唯一实现结论

- Host 输入、返回摘要和前端类型只来自 `a4n-api-contract::chapter`。
- 首次保存与已有章节编辑各有一个命令和一个业务 owner，不再携带伪身份或无消费者模式字段。
- 导入 DB 只有一个可接受连接/事务的实现，不再存在“测试版”和“生产版” facade。
- 正文变更导致旧摘要、风格和分析失效的规则只有 `assign_chapter_content` 一个实现，五条生产路径全部复用。
- 权限复核、事务边界和可恢复 workflow 均有活跃生产职责，未作为伪安全冗余删除。
