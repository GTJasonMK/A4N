# 成片后处理操作与媒体参数单一事实源清理记录

日期：2026-08-16

## BFS 搜索覆盖范围

本批从成片后处理工作区的插入、删除、替换三项功能出发，按广度优先逐层追踪：

```text
VideoPostProcessWorkspace
→ frontend/src/api/video/records.ts
→ generated Host API / command manifest
→ Server command dispatch / Tauri 通用 invoke_host_command
→ Runtime apply_assembly_postprocess_edit
→ 来源视频选择、上传、路径约束与 FFprobe 属性探测
→ Orchestrator 最新推送/版本链、时间规则、记录创建与 metadata
→ a4n-db generated_video 持久化边界
→ a4n-media filter graph、音频补齐与 FFmpeg 命令
→ 后处理输出持久化、缩略图与完成状态
```

横向覆盖了：

- `insert/delete/replace` 三种操作；
- 已有生成视频与临时上传视频两类来源；
- 基底有声/无声、来源有声/无声四类音频组合；
- 片头、片中、片尾插入，局部删除/替换，以及删除整段的空结果边界；
- API enum、metadata JSON、Orchestrator plan、Runtime renderer 和 Media request 的全部类型传递；
- `a4n-media` 单元测试、FFmpeg smoke 测试、TypeScript 生成器与命令 schema；
- Rust/TOML/JSON/YAML/路由表中的显式与隐式入口。

静态搜索未发现该功能存在反射调用、动态代理、AOP、DI 容器、XML 路由、第二 Host handler 或第二媒体执行器；Tauri 与 Server 最终进入同一个 Runtime action。

## 已执行清理

1. `AssemblyPostprocessOperation` 下沉到 `a4n-domain`，成为前端合同、Orchestrator、Runtime 与 Media 共用的唯一操作类型。
2. API contract 改为直接 re-export Domain enum，删除 API 层第二份枚举和第二份 `as_str`。
3. Orchestrator plan 与 prepared record 不再保存 `&'static str` 操作名。
4. 删除 `validate_postprocess_operation` 字符串二次校验及其 trim/未知值分叉；未知操作已在 API 反序列化边界拒绝。
5. metadata 操作字段改用 canonical enum 的 serde 合同解析，不再维护手写字符串白名单。
6. Runtime 直接把 typed operation 传入 Orchestrator 与 Media，删除字符串转媒体枚举的三分支映射和不可达错误。
7. `a4n-media` 删除 `VideoPostprocessOperation` 第二枚举，直接使用 Domain enum。
8. 基底视频时长不再 `.max(0.1)`；非正数、NaN 和无穷值显式失败。
9. 插入/替换来源时长不再允许 `None` 或非法值进入结果时长计算；无论音频是否启用都必须是正有限数。
10. 插入操作拒绝夹带删除/替换范围；删除/替换拒绝夹带插入时间，删除拒绝夹带来源时长。
11. 删除/替换范围不再允许 `base + 0.05` 容差，也不再通过 `min(base)` 静默截断。
12. Media 层删除 `clamp`，非法 start/end 不再自动改写成另一段有效剪辑。
13. 删除整段会在创建数据库记录前显式失败，不再先写入伪造的 `0.1` 秒记录再等待 Media 报空结果。
14. 输出时长改由唯一纯规则一次计算，删除 `.max(0.0)`、`.max(0.1)`、`unwrap_or(0.0)` 和未知操作返回基底时长的分叉。
15. 基底宽高与 fps 在建记录前严格校验；Media 执行边界也显式返回 typed error，不再默认到 `1280x720@24`。
16. 删除操作若携带已有视频或上传字段会显式失败，不再静默忽略来源。
17. 上传来源判定改为按字段是否出现，而不是把空字符串当作“未上传”继续执行。
18. 后处理 filter 删除首尾 `0.01` 秒静默丢弃阈值，严格按请求时间边界保留非空片段。
19. 音频段时长删除 `.max(0.1)`，只格式化已经过严格校验的真实区间。
20. 删除后处理私有非法时间戳 `→ 0` formatter；后处理链中的 FFmpeg 时间字面量只格式化已验证值。
21. 删除公开 `ffmpeg_duration_literal` 及其非法值 `→ 0.1` 回退；程序集音频补齐改在严格 clip-duration 校验后格式化。
22. 成片拼接新增 clip 时长正有限校验，非法片段不再借助 formatter 伪装成 `0.1` 秒。

未新增兼容、默认、回退、占位或第二套业务实现。

## 保留的有效边界

- 奇数宽高仍向上调整一个像素成为偶数；这是 `libx264/yuv420p` 的实际编码约束，非非法输入默认值。非正尺寸和加一溢出均显式失败。
- Orchestrator 在建记录前验证业务时间合同，Media 在公共执行 API 边界验证 FFmpeg 输入不变量；两者分别保护持久化完整性和独立媒体调用，不是两套操作语义。
- 无来源时 `source_has_audio = false` 只是 `Option` 缺席的直接投影；删除操作若真实携带任何来源字段已改为失败。
- 前端生成类型无需变化：wire 值仍为 `insert | delete | replace`，仅 Rust owner 从 API 层收敛到 Domain 层。

## 静态复核

- `rg` 已确认 `VideoPostprocessOperation`、`validate_postprocess_operation`、`postprocess_edit_range_bounds`、`ffmpeg_duration_literal`、`VideoPostprocessError::EmptyResult` 及 Runtime 字符串操作映射无剩余引用。
- `rg` 已确认目标后处理链中的 base-duration `max`、时间 `clamp`、source-duration `unwrap_or(0.0)`、默认 `1280x720@24` 和音频段 `.max(0.1)` 均已清零。
- 相关既有测试代码已改为使用唯一 Domain enum，并补充严格媒体属性、空结果范围和程序集 clip 时长断言；本批未执行这些测试。
