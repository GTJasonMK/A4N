# 临时媒体来源身份双轨合同清理记录

日期：2026-08-15

续查日期：2026-08-16

## BFS 覆盖范围

从章节视频、自由画布视频和参考媒体视频的 Provider 临时上传开始，按 BFS 追踪：

```text
章节 / 画布参考图片
→ image_file_to_remote_temp_media_url

参考媒体图片 / 视频 / 音频
→ ReferenceMediaVideoGenerationHostPort::upload_reference_media_input

→ media_bytes_to_remote_temp_media_url
→ TempMediaUploadRequest
→ POST /api/temp-media
→ MIME、文件扩展名与内容魔数校验
→ 临时 artifact 文件与 TempMediaUploadResponse
→ Runtime 响应身份 / hash / TTL / URL 校验
→ GenerationArtifactRef
→ cleanup outbox 删除
```

已覆盖 API contract、Runtime 两类上传调用、ReferenceMedia Host Port、Server 路由与存储、
图片/视频/音频 MIME 和内容校验、响应验证、删除生命周期及进程级集成引用。所有生产调用
都提交 `source_media_kind/source_media_id`；旧 `source_image_id` 只是同一 ID 的必填副本，
而通用身份却被保留为可选兼容字段。仓库不存在对应 XML、DI、反射、动态代理或 AOP 入口。

## 优化记录

1. 从 `TempMediaUploadRequest` 删除图片专属旧字段 `source_image_id`。
2. 从 `TempMediaUploadResponse` 删除同名旧字段。
3. `source_media_kind/source_media_id` 从可选兼容字段收敛为必填唯一来源身份。
4. 删除 Server 对“旧图片 ID 必填、通用媒体身份可成对缺省”的双合同校验。
5. Server 日志和响应统一只使用通用媒体身份。
6. Runtime 不再把 `source_media_id` 复制到 `source_image_id`。
7. Runtime 将来源 kind/id 校验并入唯一响应身份校验，删除后置第二次比较。
8. 严格合同会拒绝仍发送 `source_image_id` 的旧请求，不保留兼容别名。
9. 将已支持图片、视频和音频的 `decode_base64_image` 重命名为 `decode_base64_media`。
10. 将 `normalize_image_mime` 重命名为 `normalize_temp_media_mime`。
11. 将 `validate_image_magic` 重命名为 `validate_media_magic`，删除图片专属认知分叉。
12. 将 MIME 规范化与存储扩展名映射合并为 `normalize_temp_media_type` 唯一映射，删除两份同构 `match`。
13. 删除 `extension_for_mime` 中理论不可达却会返回 `bin` 的默认回退。
14. 临时 artifact 可服务扩展名收敛为 `TEMP_MEDIA_ARTIFACT_EXTENSIONS`，文件名校验和按 artifact ID 删除共同复用。
15. 删除 uploader 永远不会产生、删除路径也不支持的 `.jpeg` artifact 兼容入口；JPEG 上传仍规范化存储为 `.jpg`。
16. 临时媒体相对存储目录收敛为 `TEMP_MEDIA_RELATIVE_DIR`，上传写入和读取/清理不再各自硬编码路径。

临时媒体的 owner、project、hash、大小、TTL、HTTPS URL、文件名扩展名、内容魔数和删除身份
校验保持不变。未新增 fallback、兼容、回退、别名或第二套来源合同。
