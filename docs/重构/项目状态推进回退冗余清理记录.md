# 项目状态推进回退 BFS 冗余清理记录

日期：2026-08-13

## 搜索起点与覆盖范围

本专项从“文本项目查看状态机、手工推进、预览回退并执行回退”这一项生产功能出发，按广度优先顺序追踪完整调用闭包：

```text
StatusMachineDialog / status-machine-dialog/* / ProjectsSection
→ frontend project API / generated Host contract
→ command manifest
→ Web / Tauri / CLI 共用 Host 调度
→ a4n-runtime project_status
→ a4n-orchestrator context/project_status
→ a4n-domain ProjectStatus / ProjectStatusArtifacts
→ a4n-core rollback / validator / blueprint lifecycle
→ a4n-db project status / rollback impact / project reset
→ project_status_history / 项目产物 / 蓝图版本
```

继续横向覆盖所有会读取、推进或回退同一状态的活跃路径：

```text
蓝图生成、优化、手工保存、世界观更新和版本恢复
分部大纲、章节大纲生成及重生成
章节正文同步、章节分析和导入分析
项目资料归纳候选确认与幂等重读
文本项目复制与按状态创建分支
文本项目生成数据重置、Galgame 重置和状态回退事务
蓝图版本列表、状态历史列表及前端状态标签展示
```

Host 状态命令覆盖：

```text
get_project_status_machine
forward_project_status
preview_rollback
rollback_project_status
```

权限边界保持为：

```text
读取状态机、预览回退：Viewer
推进状态：Editor
执行回退：Owner
```

显式依赖覆盖 Rust/TypeScript 函数调用、模块导入和 `pub use` 链、SeaORM 查询及事务。隐式依赖覆盖 Serde/JsonSchema、生成 TypeScript、Host command manifest、Web/Tauri/CLI 字符串路由、AppState/OrchestratorContext/DbHandle 注入、内部事件总线、workflow run/checkpoint 指纹与恢复路径。

仓库不存在该功能相关的 XML DI、运行时反射注册、动态代理或 AOP 切面；框架入口均由 Host manifest、共用 dispatcher、生成合同和显式 context 注入覆盖。CLI 没有独立状态机实现，直接复用同一 Runtime/Orchestrator 路径。

## 明确保留的活跃边界

- `Completed` 仍需章节正文产物才能手工推进，但 `furthest_status()` 只自动推进到 `Writing`；完成状态是显式业务决定，不由“存在正文”自动推断。
- 状态历史和蓝图版本的 SeaORM 实体继续反映当前物理 nullable 列；活跃读写边界已严格拒绝 null。物理 `NOT NULL/CHECK` 约束应在迁移注册文件的并行改动合并后单独落库，避免本专项覆盖正在进行的 migration 工作。
- 回退清理动作与回退影响摘要分别属于执行规则和只读预览；二者通过同一 `CleanupAction` 连接，不复制状态顺序。
- 内部事件在数据库提交后发布，失败显式返回；没有新增重试、补偿、吞错或伪成功逻辑。
- 蓝图/资料同步 warnings 仍用于真实的下游素材同步诊断，不承担项目状态写入失败的兜底。
