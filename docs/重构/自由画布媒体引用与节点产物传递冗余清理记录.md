# 自由画布媒体引用与节点产物传递冗余清理记录

## 搜索覆盖范围

本专项从自由视频项目的画布加载、保存、连线、媒体导入、节点执行、项目复制和项目包导入导出功能出发，按 BFS 逐层追踪：

```text
VideoStudioCanvas / NovelList
→ frontend canvas/project API
→ generated Host command contract / command manifest
→ Server command route / Tauri 与 CLI 通用分发
→ Runtime canvas workflow / project duplication action
→ Orchestrator canvas execution / project duplication / package validation
→ a4n-db canvas graph / references / artifacts / transfer / duplicate transaction
→ canvas_node / canvas_edge / generated_image / generated_video
→ generation_spec / prompt_artifact / media_asset / media_provenance
→ video_segment / assembly_timeline / assembly_clip
```

同时横向覆盖以下活跃路径：

```text
画布保存与引用完整性校验
画布节点输入、输出和生成产物回写
生成图片/视频删除与项目重置
自由视频项目复制及本地 ID 重映射
视频画布项目包导出、校验、导入及文件复制
生成视频 provider 任务恢复与终态判断
前端旧画布加载迁移、连线修复和保存映射
```

显式依赖覆盖 Rust/TypeScript 调用、模块导入、Host API、Server 路由、Runtime action、SeaORM 查询与事务；隐式依赖覆盖 Serde/JSON Schema、节点合同、React Flow 端口、JSON metadata、项目包 manifest、媒体 provenance、生成意图 hash、provider job 恢复身份和文件路径重映射。项目没有 XML DI、反射、动态代理或 AOP；动态分派由显式 Host command、节点合同和 provider job 状态完成，均已纳入搜索闭包。

## 生产数据证据

通过健康的 `a4n-postgres` 容器对当前运行数据库执行只读计数：

```text
canvas_node_total=0
canvas_edge_total=0
legacy_node_kind=0
legacy_ref_type=0
legacy_config_key=0
```

因此前端每次加载时执行的旧节点迁移和旧连线自动修复没有活跃数据依据。后端仍保留严格的 canonical 合同校验；不再自动转换、静默删除或兼容旧值。

## 优化记录

1. 将 `a4n_domain::CanvasNodeRefKind` 确立为画布引用类型的唯一事实标准。
2. 删除 a4n-db 内重复的 `CanvasRecordNodeRefKind` 枚举。
3. 删除 `legacy_generated_image`、`legacy_generated_video`、`legacy_chapter_video_prompt` 三类旧引用支持。
4. 删除引用类型的首尾空白和空字符串归一化；非 canonical 输入直接失败。
5. 画布保存的引用形状校验、实体存在性校验和项目归属校验统一匹配领域枚举。
6. 画布节点输入、输出、图片生成、视频生成和编辑节点删除散落的引用字符串判断。
7. `MissingCanvasRef.ref_type` 改为强类型枚举，删除重置链路的字符串分叉。
8. 图片/视频删除清理统一使用 canonical 引用值，不再识别 legacy 别名。
9. 项目复制和项目包导入的节点引用重映射统一解析 `CanvasNodeRefKind`。
10. 项目包 manifest 的节点引用校验统一解析同一领域枚举。
11. 画布配置引用扫描限定为现行单值键：`generated_image_id`、`generated_video_id`、`generation_spec_id`、`prompt_artifact_id`、`media_asset_id`。
12. 删除旧 `source_image_id`、复数 ID 数组和其他历史别名的 reset/delete 扫描与清理逻辑。
13. 删除配置引用辅助模块中数组、别名表和多形态递归匹配实现。
14. 重置路径只清除确认命中的 canonical 单值字段，不再尝试修补未知历史结构。
15. 引用检测、删除清理和重置检测复用同一组 canonical 配置键常量。
16. 删除画布持久化前对 `ref_type` 的二次 trim/复制，验证后的原值直接落库。
17. 更新 Runtime/DB 回归断言，移除只验证旧别名的测试数据。
18. 将自由画布 `source_material → source_version_hash` 唯一规则收敛到 `generation_spec::freeform_source_version_hash`。
19. `FreeformCanvasGenerationSpecUpsertInput` 删除外部传入的 `source_version_hash` 字段。
20. a4n-db 在生成意图写入边界直接从 `params_json.source_material` 派生 hash。
21. 画布视频生成删除独立序列化/hash 实现，并补齐 `last_frame_image_id` 到唯一 source material。
22. 项目复制、项目包导入和项目包导出均在 ID/运行身份变换后重新计算 hash。
23. 项目包校验显式拒绝 hash 与 `source_material` 不一致的生成意图。
24. `source_material` 非 JSON 对象时直接失败，不保留旧字符串格式转换。
25. 项目本地 ID 在 `canvas`、`source_material`、`params`、`node_config`、`metadata` 中递归重映射。
26. 节点配置中的文本资产、生成意图、提示词产物、图片、视频、媒体资产、片段和时间线 ID 全部按目标项目重映射。
27. 生成图片/视频节点在复制或导入后同步更新文件路径和缩略图路径。
28. 媒体 provenance 的 `source_external_path` 和时间线 cache key 继续按显式格式重映射，不复制源项目 ID。
29. 将跨项目运行身份清理收敛到领域函数 `clear_canvas_transfer_runtime_identity`。
30. `workflow_run_id`、`provider_job_id`、通用 `config_id` 在任意嵌套对象/数组中递归清除。
31. `llm_config_id`、`image_config_id`、`video_config_id` 作为用户业务配置继续保留，不被运行身份规则误删。
32. 项目包验证复用 `canvas_transfer_runtime_identity_key`，拒绝任何遗漏的嵌套运行身份。
33. 复制、导出和导入生成视频时统一清除顶层 `provider_job_id`。
34. 跨项目复制媒体 provenance 时统一清除 provider 身份和 request snapshot 中的运行身份。
35. 自由项目复制在写入任何视频前一次性读取并校验全部视频，避免复制中途才发现非终态记录。
36. 将生成视频状态字面量和终态判断收敛到 `generated_video` 模型模块。
37. 生成视频终态唯一规定为 `completed`、`failed`、`cancelled`。
38. `interrupted` 明确保留为可恢复非终态，不再被复制/导入/导出误认为稳定产物。
39. provider job 生命周期、DB 状态推进、项目复制和项目包传输复用同一终态规则。
40. 项目包导出在组包前拒绝非终态视频，避免导出不可恢复的半成品。
41. 项目包 manifest 校验和导入写入边界再次拒绝非终态视频，覆盖外部伪造包。
42. 删除前端 `migrateLegacyCanvasGraph` 整套旧节点、旧配置节点和旧引用迁移，约 160 行。
43. 删除前端 `normalizeLoadedCanvasEdges` 整套端口改写、顺序补齐和静默丢边逻辑，约 70 行。
44. 画布加载与保存统一调用 `canvasGraphSaveValidationError`，非 canonical 连线直接显示错误。
45. 缺少源/目标节点的连线不再被保存映射静默过滤。
46. 即使旧端口可以推断为新端口，也不再自动改写，要求用户按当前合同重新连接。
47. `toCanvasGraphInput` 删除节点合同参数、二次契约推断和端口/角色空字符串 fallback。
48. 保存映射直接持久化已经校验的 canonical `sourceHandle`、`targetHandle` 和 `role`。
49. 删除零调用的 `studioConfigKind`。
50. 新连线校验改为一次返回已验证契约，删除 onConnect 中第二次重复推断。
51. 删除角色计算中最终都返回 `context` 的重复 probe/text/input 条件。
52. 新增前端回归测试，锁定“可推断旧端口必须拒绝，不能自动修复”的行为。

## 清理后唯一事实标准

```text
节点引用类型
→ a4n_domain::CanvasNodeRefKind

生成意图版本
→ generation_spec::freeform_source_version_hash(source_material)

生成视频终态
→ generated_video::is_terminal_status

跨项目运行身份
→ clear_canvas_transfer_runtime_identity / canvas_transfer_runtime_identity_key

前端连线
→ node contract 推导新连线
→ canvasGraphSaveValidationError 校验已加载/待保存连线
→ toCanvasGraphInput 原样持久化已验证 canonical 字段
```

项目复制与项目包导入保留各自的事务、文件写入和错误类型边界；共享业务不变量已经收敛到领域/核心层。未为表面 DRY 新增泛型框架、适配器或兼容层。

## 明确保留的活跃分支

- 前端连线校验负责即时交互反馈，后端校验负责不可信输入和数据完整性边界，两者职责不同。
- `workflow_run_id`、`provider_job_id`、`config_id` 在源项目运行期间仍是活跃执行身份，仅在复制/传输边界清除。
- `llm_config_id`、`image_config_id`、`video_config_id` 是用户选择的业务配置，不属于运行身份。
- `interrupted` 视频仍可通过 provider job 恢复轮询，因此不能作为可复制、可导出的稳定终态。
- 项目复制与项目包导入使用不同事务和文件写入接口，保留薄适配器；canonical 引用、hash、终态和运行身份规则只有一套。
