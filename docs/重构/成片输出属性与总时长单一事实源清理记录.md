# 成片输出属性与总时长单一事实源清理记录

日期：2026-08-16

## BFS 搜索覆盖范围

本批从章节成片预览、成片分段推送和画布成片三项生产功能出发，逐层覆盖：

```text
Frontend 成片/画布功能
→ Host API 与 Runtime action
→ Orchestrator assembly clip 查询、推送切片与 Canvas source 计划
→ Runtime 路径规范化、cache manifest 与音频探测
→ a4n-media assembly filter / FFmpeg
→ 预览 DTO、推送记录、Canvas assembly 记录与缓存读取
```

重点横向比较了三处输出宽高、fps 和总时长计算，以及“无片段”在拼接、推送、缓存读取三种场景中的真实语义。搜索覆盖 Runtime/Orchestrator/Media、API DTO、前端入口、测试和 XML/YAML/JSON/TOML 配置；未发现反射、动态代理、AOP、DI 或第二套成片属性配置。

## 已执行清理

1. 新增唯一纯规则 `assembly_media_properties`，统一校验所有片段的时长、宽高和 fps，并一次计算目标输出属性及总时长。
2. 删除 `normalized_assembly_dimensions`、`normalized_assembly_fps` 和私有 `even_positive_dimension` 三个宽松 helper。
3. 章节成片不再在空列表时伪造 `1280x720@24` manifest。
4. `assembly_request_context` 对无片段显式返回 `None`：拼接/推送转换为业务错误，缓存读取保持 `Ok(None)` 的真实缺席语义。
5. 非空章节成片使用首片段的严格正尺寸/fps 作为目标，奇数目标尺寸只执行编码必需的偶数化。
6. 所有片段的非正尺寸、非正 fps、非正/非有限时长均在创建 manifest 或记录前显式失败。
7. 总时长不再把每个负时长 `.max(0.0)` 后求和；累加产生非有限值也显式失败。
8. 成片推送记录直接复用唯一属性 owner，删除自己的 first/default/max 计算分叉。
9. 画布成片计划直接复用同一 owner，删除宽高/fps `.max(1)` 和片段时长 `.max(0.0)`。
10. 章节预览上下文保存已经严格计算的 canonical 总时长，预览 DTO 不再二次宽松求和。
11. 旧默认值测试改为严格属性合同测试，覆盖奇数目标偶数化、空列表和零时长拒绝。

未新增默认、兼容、回退或第二套属性计算逻辑。

## 保留的有效边界

- 缓存读取在没有任何片段时返回 `None` 是“没有可加载缓存”的业务结果，不是错误回退。
- 拼接和推送没有片段时继续返回明确业务错误，因为这两项操作必须产生输出。
- 不同来源片段允许分辨率和 fps 不同；FFmpeg 会按首片段确定的目标属性统一缩放/重采样。所有元数据仍必须为正有效值。
- 奇数目标尺寸向上调整一个像素仍是 `yuv420p` 编码约束；溢出会显式失败。

## 静态复核

- `rg` 已确认 `normalized_assembly_dimensions`、`normalized_assembly_fps`、`even_positive_dimension` 无剩余引用。
- `rg` 已确认章节预览、推送和画布成片目标链中的 `duration_secs.max(0.0)`、首片段宽高/fps `.max(1)` 及 `1280x720@24` 默认已清零。
- `assembly_media_properties` 仅由章节上下文、推送记录和画布成片计划三处生产入口调用。
