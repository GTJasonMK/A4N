# 灵感对话身份与合同冗余清理记录

## 搜索覆盖范围

本专项从用户可见的“灵感对话”功能出发，按 BFS 追踪历史恢复、请求预览、正式生成、任务恢复和蓝图下游的完整生产链路：

```text
NovelList / NovelDetail / OverviewTab
→ /inspiration/:id
→ InspirationChat / useInspirationChatController
→ getInspirationHistory / previewInspirationRequest / startInspirationGeneration
→ apiInvoke / generationClient
→ generated Host contracts / generation contracts
→ Web Bearer token 与 /api/generation-tasks/inspiration
→ Tauri invoke_host_command / CLI command manifest
→ Server command dispatch / generation route
→ Runtime inspiration_records / runtime config request scope
→ Orchestrator generation reservation / inspiration application
→ PromptRenderer / inspiration prompt registry / context ledger
→ workflow business key / LLM checkpoint / generation terminal
→ DB novel_project / conversation / message / project context
→ GenerationResultRef(inspiration_message) / 前端正式结果恢复
→ 蓝图 inspiration_transcript / project dependency graph
```

横向覆盖 3 条公开 Host 命令及 1 条 Web generation 路由：

1. `get_inspiration_history`
2. `preview_inspiration_request`
3. `start_inspiration_generation`
4. `POST /api/generation-tasks/inspiration`

显式引用覆盖前端路由、页面 Controller、API 包装、Host manifest、Tauri/Web 分发、Runtime action、Orchestrator request/workflow/checkpoint、DB conversation/message、generation result 恢复和蓝图 transcript 消费。

隐式依赖覆盖 Host TypeScript 生成器、generation JSON schema、runtime config snapshot、命令动态分发表、prompt `_registry.yaml`、`inspiration` 与 `inspiration_project_context_guard` 模板、SeaORM 模型、workflow fingerprint、checkpoint fingerprint、项目权限、依赖图和生产进程 SSE 集成测试。仓库中不存在灵感对话相关 XML DI、反射调用、动态代理或 AOP 切面旁路；动态入口只有 Host 命令名分发、generation route、generation worker 和 PromptRenderer 注册表，均已纳入闭包。

## 清理前分叉

```text
用户身份
→ Web JWT / Tauri 外层 user_id
→ 前端三条灵感入口再次发送 userId

历史合同
→ 前端 projectId + limit
→ Server 手工字段解析
→ Runtime 位置参数
→ Runtime 私有 11 字段 MessageSummary

预览合同
→ opaque manifest
→ 前端 user_input + variables
→ Runtime 私有 DTO + variables 动态解析
→ Orchestrator 再包装 InspirationPreviewInput

正式生成合同
→ message + 从未有效使用的 variables
→ Orchestrator HashMap/Value 转换
→ workflow 与 generation fingerprint

对话生命周期
→ 读取空历史
→ 隐式创建 conversation
→ 独立 insert helper 再次 get-or-create
→ generation 写路径依赖隐式副作用
```

## 优化记录

1. 在 `a4n-api-contract` 新增唯一 `InspirationHistoryInput`，历史查询只接收 `project_id`。
2. 新增唯一 `PreviewInspirationRequestInput`，预览与正式生成统一使用 `message`。
3. 新增唯一 `InspirationMessageSummary`，历史输出只保留前端实际消费的 4 个字段。
4. 三个灵感输入 DTO 均拒绝未知字段，退役字段不再被静默忽略。
5. `get_inspiration_history` manifest 从 opaque args/result 改为严格 typed args/result，并显式使用认证 Host 身份的 `NO_CONTEXT`。
6. `preview_inspiration_request` manifest 从 opaque args/result 改为严格 runtime typed args 和 `ModelRequestPreview` typed result，并显式使用 `NO_CONTEXT`。
7. `start_inspiration_generation` manifest 改为严格 runtime typed input。
8. Host TypeScript 生成器输出三种正式灵感 DTO，前端不再维护镜像合同。
9. generation schema 和 TypeScript 合同删除 `StartInspirationGenerationInput.variables`。
10. 前端删除私有 `InspirationMessage` 接口，历史归一化直接消费生成类型。
11. 前端历史、预览、正式生成三条入口全部删除重复 `userId`。
12. 历史公开合同删除外部 `limit`，消除 UI 固定传 80 与后端动态校验的伪灵活性。
13. Runtime 将真实页面窗口固定为 `INSPIRATION_HISTORY_LIMIT = 80`。
14. 预览字段从 `user_input` 收敛为与正式生成一致的 `message`。
15. 删除预览路径从未传入有效值的 `variables` 输入、JSON 对象解析和错误常量。
16. 删除正式生成路径从未传入有效值的 `variables` 输入及 HashMap/Value 转换。
17. Orchestrator request builder 只向无模板变量的 `inspiration` 系统提示传空映射，不再暴露业务扩展入口。
18. generation v1 fingerprint 保留固定 `variables: null`，workflow v1 fingerprint 保留固定 `variables: {}`，仅维持已持久化任务、重试和 checkpoint 身份稳定；输入合同不再接受该字段。
19. 删除单调用者 `InspirationPreviewInput`，Runtime 直接向 Orchestrator 传真实参数。
20. 删除单调用者 `InspirationGenerationApplicationContext`，generation worker 直接传 `PromptRenderer`。
21. Server 历史入口改用 `strict_command_input`，删除 `projectId`/`limit` 手工解析。
22. Server 预览入口改用 `strict_runtime_command_input`，拒绝额外 Host 参数。
23. Runtime 直接复用 API contract DTO，删除私有 `contracts.rs`。
24. 历史投影内联为唯一 4 字段输出，删除只包装一次的 `projections.rs`。
25. 删除只验证已退役 limit/variables/私有 DTO 的 Runtime `tests.rs`，回归转移到正式 API contract。
26. 历史读取不再隐式创建 conversation；存在项目但无对话时返回真实空历史。
27. generation 写路径在执行开始时显式 `ensure_inspiration_conversation`，读写副作用分离。
28. `get_or_create_inspiration_conversation` 收敛为只表达写前置条件的 `ensure_inspiration_conversation`。
29. 删除无生产调用者的 `insert_inspiration_exchange` 非事务 helper，写入唯一经过 generation 完成事务。
30. `inspiration_project_by_id` 收回 DB 模块私有，删除无外部调用面的导出。
31. 删除只服务已退役 Host limit 的 `inspiration/rules.rs` 和重复校验测试。
32. DB 测试改为验证“缺失项目报错且不建对话”“空历史不建对话”“显式确保后事务写入”。
33. 两条生产进程 inspiration generation 集成测试删除已退役 `variables`；成功流通过 `runtime_config_snapshot` 传递测试 API Key，覆盖真实 Full runtime policy。
34. 新增 manifest/serde 回归，确保 `limit`、`user_input` 和 `variables` 均被拒绝。
35. 清理相关未使用导入、模块声明、公开 re-export 和位置参数转发。

## 清理后唯一事实标准

```text
认证身份
→ Web：Bearer token 认证出的 user_id
→ Tauri：invoke_host_command 外层 user_id
→ 灵感业务输入不携带 userId

Host 输入与输出
→ Rust：a4n_api_contract::inspiration
→ TypeScript：frontend/src/api/generated/{host,generationContracts}.ts

历史查询
→ { input: { project_id } }
→ Runtime 固定最近 80 条
→ 读取不创建 conversation

预览
→ { input: { project_id, message }, runtime_config_snapshot? }

正式生成
→ StartInspirationGenerationInput { meta, project_id, message }
→ generation worker 显式确保 conversation
→ 完成事务写入 user + assistant 两条消息

正式结果
→ InspirationMessageSummary { id, role, content, created_at }
→ GenerationResultRef.kind = inspiration_message
```

未新增旧字段别名、默认用户、默认 limit 输入、variables 兼容解析、空历史建对话、异常吞掉、回退实现、DTO 适配器或占位逻辑。
