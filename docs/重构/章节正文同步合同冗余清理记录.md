# 章节正文同步合同冗余清理记录

## 搜索覆盖范围

本专项从文本项目的单章正文保存、导入、生成完成、优化补丁应用和导入审核接受五类生产功能出发，按 BFS 追踪：

```text
Frontend chapter API / CLI / Tauri / Web command
→ Runtime chapter_content actions
→ Orchestrator ChapterContentApplication
→ a4n-db chapter content write owner
→ chapter row + workflow_run + cleanup checkpoint 同一事务
→ ChapterDerivedCleanupHostPort
→ 角色时间线 / 伏笔 / 场景 / 外部媒体清理
→ 当前章节 RAG 重建
→ 风格标签与项目状态后处理
→ Workflow 统一恢复路由
→ ChapterSummary 派生同步状态投影
```

额外横向覆盖：

```text
章节生成完成
优化补丁应用
导入审核接受
→ 同一 chapter_content_sync 工作流

chapter_analysis 替换写入
→ 共用派生资料清理 owner，但不清理正式伏笔
```

显式依赖覆盖函数调用、模块导入、DB DTO、Workflow fingerprint/checkpoint、Host trait 实现、API command manifest、Server dispatch、CLI 命令和前端 API。隐式依赖覆盖 PostgreSQL 事务与行锁、Workflow 统一恢复分发、Runtime RAG trace、文件删除校验、项目导入/导出与复制路径。项目未使用 XML DI、反射、动态代理或 AOP；项目包导入/导出不携带 `workflow_run` / `workflow_checkpoint`，因此不存在旧 fingerprint 的生产恢复来源。

## 优化记录

1. `chapter_content_sync_run_input_matches` 只接受当前 schema v3，删除裸 v1 与 v2 兼容解析。
2. 从 v3 fingerprint 删除恒定的 `sync_current_chapter_rag` 字段。
3. 删除 `chapter_content_sync_current_rag_intent` 旧意图解析函数。
4. 删除 `chapter_content_sync_should_sync_current_rag` 条件包装。
5. RAG 阶段固定执行当前章节同步，保持所有生产入口的唯一合同。
6. 从 Workflow 输入构造、事务 owner 和全部调用链删除 RAG 布尔参数。
7. 删除 `cleanup_foreshadowing` 在章节正文同步链路上的恒真开关，正文变化固定清理伏笔。
8. 从 `postprocess_chapter_derived_data_validated` 删除同名恒真参数及两个生产调用点的常量传参。
9. 删除无任何调用的 `cleanup_chapter_derived_data_record` 公开转发和私有事务实现。
10. 删除派生清理 owner 中始终为 false 的 `cleanup_generated_media` 开关及死分支。
11. 删除仅服务于上述死分支的 `ChapterDerivedCleanupArtifacts::extend_media_file_paths`。
12. 删除完整的 `chapter_media_cleanup` 旧模块；全局仅其自身测试引用，所有正文生产路径从未启用。
13. 删除旧模块对应的 122 行孤立测试，不保留无生产消费者的测试事实来源。
14. 删除 `PostProcessResult` 值对象及未被生产使用的字符数、中文数、段落数、对话比例和质量分字段。
15. 删除质量分计算与质量分范围测试，后处理只保留实际持久化的风格标签。
16. `process_chapter` 改为返回 `Result<()>`，不再构造随后被丢弃的结果。
17. 删除 `chapter_for_post_process` 重复查询入口。
18. 风格标签更新 owner 接收已读取章节模型，避免后处理阶段再次按 id 查询同一章节。
19. `begin_existing_chapter_content_sync` 只返回唯一被调用方使用的 Workflow run，不再返回被丢弃的章节。
20. 恢复入口从当前 v3 fingerprint 读取项目与章节号作为锁键，删除加锁前的重复章节查询。
21. 保留恢复前的当前运行与 `can_resume` 校验，避免过期运行先被改写为 RUNNING；该校验属于数据完整性边界而非冗余。
22. 将章节正文编辑错误映射收敛到 crate 级唯一函数，删除 chapter analysis 中的重复映射实现。
23. 删除更新正文上层重复的空正文与生成态校验；数据库写 owner 已在事务内执行相同规则。
24. 删除导入上层重复实现的正章节号与空正文规则；预检入口复用项目既有章节号规则防止减法溢出，数据库导入 owner 继续执行最终持久写入校验。
25. 导入 DTO 不再接收调用方预计算的 `normalized_title`、`word_count` 和 `now`。
26. 标题归一化、字数计算和写入时间统一由数据库导入 owner 派生，消除第二事实来源。
27. 为数据库导入 owner 补充一项合同测试，覆盖章节号、空正文、标题归一化和字数派生。
28. 保留更新/导入在锁前后的权限与文本项目校验：前置校验限制未授权锁竞争，锁后校验处理 TOCTOU。

## 清理后唯一事实标准

```text
正文更新 / 导入 / 生成完成 / 优化补丁 / 导入审核接受
→ ChapterContentApplication
→ a4n-db 正文写 owner（输入校验、标题归一化、字数/时间派生）
→ begin_chapter_content_sync_in_transaction
   ├─ 固定清理正文派生证据、自动章纲、角色时间线、伏笔和场景同步记录
   ├─ 固定登记 schema v3 Workflow + cleanup checkpoint
   └─ 固定后续执行外部清理、当前章节 RAG、风格标签与项目状态同步
```

- 同一业务目的只保留 `chapter_content_sync` 一套正文变化同步工作流。
- schema v3 是唯一活动 fingerprint 合同；不保留历史格式兼容或缺省行为。
- `a4n-db::chapter_content::import_chapter_content_record` 是导入持久写入校验、标题、字数与时间的唯一 owner；预检只复用既有章节号纯规则保护前置计算。
- `a4n-db::chapter_content::save_chapter_content_edit_record` 是编辑空正文与生成态校验的唯一事务 owner。
- 风格标签使用工作流已经读取并校验的章节模型，不再通过第二查询入口读取。
- chapter analysis 替换写入继续显式选择“不清理正式伏笔”，这是与正文变化不同的真实业务分支。
