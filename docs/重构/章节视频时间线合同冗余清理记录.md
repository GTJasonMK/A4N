## 搜索起点与覆盖范围

本专项从“章节视频页在原生片段之间生成、提交、移动、删除插入片段，并按同一顺序组装成片”功能做广度优先搜索，覆盖以下活跃调用闭包：

```text
VideoTab / VideoPromptSetupPanel / InsertedSegmentTimelinePanel
→ frontend/src/api/video/prompts.ts 与 generation.ts
→ generated Host contract / apiInvoke / runtime config snapshot
→ Web 字符串 dispatch / Tauri invoke_host_command / CLI command manifest
→ a4n-server 视频命令解析与 generation task 启动
→ a4n-runtime 权限上下文、视频提示词与生成动作
→ a4n-orchestrator 时间线、插入草稿 workflow、提示词、视频采用与成片
→ a4n-db 时间线事务、提示词/视频绑定、图片/视频引用清理
→ SeaORM entity / PostgreSQL migration / schema requirement
→ Prompt registry / chapter_video_inserted_segment 模板
```

相邻生产路径同时覆盖：

```text
共享片段规划生成或重生成
→ source_shot_id + segment_index_in_shot 稳定身份
→ native 时间线 reconcile
→ 插入项锚点保持或 needs_reanchor

插入片段生成
→ 时间线 revision 与相邻 gap
→ 章节正文、相邻视频/尾帧/参考图上下文指纹
→ workflow checkpoint
→ 提示词与时间线项原子提交
→ 单片段视频生成、完成绑定、删除引用清理

混合成片
→ 当前共享规划 adopted video
→ 当前时间线 position
→ 外部 assembly_insert
→ 预览、导出、推送与后处理
```

隐式依赖检查覆盖：Cargo 模块导出与 crate 依赖、serde/schemars DTO 和生成 TypeScript、command manifest、Web/Tauri/CLI 通用调度、generation reservation/session/worker、workflow run/checkpoint、项目权限与生命周期写锁、Prompt registry、SeaORM 外键、PostgreSQL 历史迁移和最终约束、视频执行 metadata、引用删除、成片排序和前端测试夹具。

已核对 Web、Tauri、CLI，时间线读取，插入草稿生成与重复提交，移动、删除、重定位，原生规划重生成，视频采用、生成、上传、删除，混合成片、外部成片插入、预览和推送路径。仓库不存在该功能对应的 XML、运行时反射、动态代理或 AOP 切面；框架隐式入口由 Host manifest、字符串 dispatch、生成合同、Prompt registry、workflow 配置和数据库 schema 覆盖。

历史核验覆盖 `chapter_video_timeline`、`chapter_video_timeline_cleanup`、`chapter_video_timeline_retirement` 及其已部署顺序。历史迁移保留；最终合同必须位于 retirement、import review 清理和伏笔合同之后，不能改写已部署历史。

## 保留边界

- `position` 是业务时间线唯一顺序；API 的 previous/next 只描述一次操作的相邻 gap，不是持久化镜像。
- `segment_number`、`shot_number` 和成片 `sort_order` 是展示或外部成片投影，不作为原生或插入片段身份。
- `needs_reanchor` 是可见业务状态，用于阻止失效邻接继续生成或进入成片，不是异常 fallback。
- 软删除项保留稳定身份和历史引用，但没有活动位置；这不是第二顺序来源。
- `assembly_insert` 表示生成完成后的外部成片插入，与生成前业务插入片段的时间线用途不同，二者不合并。
- 共享片段规划暂不存在时，读取可保留空时间线；已有 native 项不会在规划切换窗口被误删。混合成片要求当前规划存在并显式失败。
- workflow checkpoint 保留可重放的 LLM 草稿；提交后的 canonical 状态只在提示词、时间线项和视频外键中。
- 权限、revision、项目生命周期门禁、外键、唯一约束和引用清理属于数据完整性边界，全部保留。
