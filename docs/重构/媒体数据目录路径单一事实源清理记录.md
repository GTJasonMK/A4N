# 媒体数据目录路径单一事实源清理记录

日期：2026-08-16

## BFS 覆盖范围

从“媒体文件落盘后生成数据库相对路径”功能出发，横向覆盖：

```text
图片 / 立绘 / 视频生成与上传
→ Runtime file_utils
→ canonicalize_path_in_data_dir
→ canonicalize_data_file_path
→ data_dir_relative_file_path
→ DB file_path / cleanup outbox

素材图上传 / Canvas 音频导入 / Galgame 音频导入
→ Orchestrator 文件落盘
→ 各自 data_dir_relative_path 副本
→ media asset / generated image 记录

Server /media 与 Tauri a4n-media protocol
→ Runtime 公开路径校验入口
→ 数据目录边界和错误分类
```

已搜索全部函数声明、调用者、Runtime 内部模块引用、Server/Tauri Host 引用、项目目录构造、
清理队列和测试夹具。未发现 XML、反射、动态代理、AOP、DI 容器或隐藏路由入口。

## 已执行清理

1. `CanonicalDataPathError` 下沉到共同基础依赖 `a4n-core::files::paths`。
2. `canonicalize_path_in_data_dir` 下沉到 Core，数据目录 canonicalize 与越界判定只保留一份。
3. `canonicalize_data_file_path` 下沉到 Core，空路径、绝对路径、目录和越界规则只保留一份。
4. `data_dir_relative_file_path` 下沉到 Core，媒体数据库相对路径生成只保留一份。
5. Runtime 原 103 行路径实现删除，只保留对 Core owner 的活跃公共导出；现有 Runtime、
   Server 和 Tauri 调用不再维护第二套逻辑。
6. 素材图上传删除私有 `data_dir_relative_path` 副本，直接调用 Core owner。
7. Canvas 音频导入删除第二份相对路径实现。
8. Galgame 音频导入删除第三份相对路径实现。
9. `path_to_db_string` 删除 `to_string_lossy` 有损回退；非 UTF-8 路径现在显式失败，
   不再把替换字符写入数据库后制造无法回溯的第二身份。
10. 成片缓存过期扫描适配严格路径字符串结果，显式传播非 UTF-8 错误。
11. `ProjectPaths` 增加实际已有两个生产消费者的 `audio_dir()`，音频目录名只保留一个 owner。
12. Canvas 与 Galgame 音频落盘删除两处 `root().join("audio")`。
13. 素材图目录删除手写 `data/projects/{id}/images`，复用现有 `ProjectPaths::images_dir()`。
14. 静态搜索确认 Orchestrator 已无 `data_dir_relative_path` 私有实现、音频目录手写拼接或
    数据库路径 `to_string_lossy` 回退。

Runtime `file_utils` 的公开导出继续保留，因为 Server、Tauri 和 Runtime 内部大量活跃消费者
以该模块作为宿主文件能力入口；它只导出 Core 类型和函数，不包含第二份实现或兼容分支。
