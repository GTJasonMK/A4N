# 伏笔索引 CRUD BFS 冗余清理记录

日期：2026-08-13

## 搜索起点与覆盖范围

本专项从“故事事件页维护正式伏笔索引”功能做广度优先搜索，覆盖以下活跃调用闭包：

```text
StoryEventsTab
→ ForeshadowingIndexCard
→ frontend/src/api/foreshadowing.ts
→ generated Host contract / apiInvoke / runtime config snapshot
→ Web 字符串 dispatch / Tauri invoke_host_command / CLI command manifest
→ a4n-server profile record command adapter
→ a4n-runtime 权限校验与伏笔 CRUD
→ a4n-orchestrator ProjectChapterContext
→ a4n-db 伏笔记录、项目写锁、版本冲突与事务
→ PostgreSQL foreshadowing_index schema
→ 单条伏笔 RAG 同步与删除
```

相邻活跃路径同时覆盖：

```text
章节分析结构化输出
→ planted 伏笔提取
→ ForeshadowingAnalysisDraft
→ created / updated / existing / resolved 分类
→ workflow checkpoint / 前端分析结果
→ current 记录 RAG 同步与 stale_ids 删除

章节回滚或重分析清理
→ ForeshadowingCleanupResult
→ stale_ids / changed_ids
→ RAG 删除与重建
```

隐式依赖检查覆盖：Cargo crate 依赖与模块导出、serde/schemars DTO 和生成 TypeScript、Host manifest、Web/Tauri/CLI 通用调度、runtime request scope、项目访问与编辑权限、Prompt registry、章节分析校验、SeaORM entity、PostgreSQL baseline/migration、并发版本校验和 RAG 连续性记录。

已核对 Web、Tauri、CLI，列表、新增、编辑、删除，章节分析新增/回收，重分析与回滚清理，RAG 成功与失败告警路径。仓库不存在该功能对应的 XML、运行时反射、动态代理或 AOP 切面；框架隐式入口由 Host manifest、字符串 dispatch、serde schema、Prompt registry 和数据库 schema 覆盖。

## 已完成优化

1. 四个伏笔命令由 `args_opaque/result_opaque` 改为严格 typed contract。
2. List/create/update/delete 输入增加正数 ID schema 约束。
3. 埋设章节、回收章节和重要度增加 schema 范围约束。
4. 前端删除四处重复 `userId`，认证身份只由 Web/Tauri Host 上下文提供。
5. Server 列表命令改为严格顶层参数解析，拒绝身份等未知字段。
6. Server create/update 使用允许 runtime snapshot 的严格解析，delete 使用普通严格解析。
7. 四个重复 Web handler 删除，统一复用现有 `profile_record_web_commands!`。
8. Runtime list 参数从完整 DTO 收敛为 `project_id`，与对象/场景同类查询一致。
9. API Contract 与 DB 的两份 `ForeshadowingRecordInput` 合并为 `a4n-domain` 唯一类型。
10. 删除 Runtime 手写 `into_db_input` 字段搬运 mapper。
11. create/update/delete 返回值统一为只含活跃消费者 `warnings` 的 `ForeshadowingWriteResult`。
12. 删除 create/update 未消费的 `foreshadowing` 摘要生成和传输。
13. 删除旧 `ForeshadowingMutationResult` 与 `ForeshadowingDeleteResult` 两套分叉结果类型。
14. 状态值收敛为 `ForeshadowingStatus`，由 Rust 合同生成前端联合类型。
15. DB 手工 CRUD 使用同一状态枚举，不再重复维护合法状态字符串列表。
16. 章节回收、重开和解析路径复用同一状态枚举常量与状态规则。
17. 前端状态标签、选项和编辑草稿使用生成的 `ForeshadowingStatus` 类型。
18. 删除章节分析提取链中恒为 `pending` 的 `ForeshadowingEntry.status` 字段。
19. 删除 `ForeshadowingAnalysisDraft.status` 及其跨层透传，新增伏笔状态直接由持久化层写入唯一 `Pending` 规则。
20. RAG 分析投影使用同一 `Pending` 常量，不再依赖无意义状态字段。
21. 删除 Orchestrator 公开方法名中的伪 `validated` 后缀；真实校验仍由 DB 业务边界执行。
22. 共享 `NumberField` 增加原生 `max` 属性，删除伏笔页手写 `Math.min` 截断分叉。
23. Runtime 列表 projection 对非法数据库状态显式返回错误，不新增默认值或静默回退。
24. 生成合同删除旧结果接口并输出唯一状态枚举与写入结果。
25. 新增不可逆数据库完整性迁移，将合法状态、章节关系、重要度、描述规范和唯一性下沉为持久化约束。
26. 章节分析保存合同将 `related_entities` 收紧为非空字符串数组，删除只校验数组外壳的宽松分叉。
27. Runtime 列表 projection 删除 `filter_map` 静默丢弃，数据库关联角色元素非法时显式失败。
28. 数据库迁移拒绝关联角色数组中的对象、数字和空白字符串；生产数据只读核对 21 条记录全部符合唯一字符串数组合同。
29. 删除 RAG 连续性测试中遗留的对象形关联角色夹具，不保留旧格式兼容示例。
30. 删除章节分析 workflow 测试对已移除 `ForeshadowingAnalysisDraft.status` 的旧合同断言。

## 保留边界

- `ForeshadowingAnalysisSyncResult.current/created/updated/existing/resolved/stale_ids` 均有 workflow、checkpoint、前端结果或 RAG 消费者，保留。
- `ForeshadowingCleanupResult.changed_ids/stale_ids` 用于回滚后的 RAG 删除与重建，保留。
- CRUD 的 RAG warning 被界面提示消费，保留；没有将失败改成静默成功。
- DB 项目写锁、唯一性检查和 `expected_updated_at` 并发校验保护数据完整性，保留。
- SeaORM 实体继续使用数据库字符串列；跨层合法状态由 `ForeshadowingStatus` 统一解释，非法历史值显式报错。
