# 导演 Agent 原生时间线编辑

Agent 提交成功后，时间线按回执更新对象字段。正常编辑不会重新加载编辑器，也不会重置选区、播放头、缩放或撤销历史。定位、选择、播放和适配视图使用独立的 `control_editor_view` 工具，只有明确请求这些动作时才改变视图。

## 执行与审批

- 自主模式直接提交合法草稿操作。
- 写入前审阅模式对一个原子批次审批一次。
- 建议模式不能写入草稿。
- 正式确认可由用户点击，或要求导演 Agent 使用 `confirm_chapter_visual_plan`；Agent 确认在自主模式下也需审批。编辑已确认方案会建立或更新协作草稿，不修改确认记录。
- 关闭 Agent 面板不会断开工作区编辑桥接。关闭原窗口后，明确指向已保存版本的操作可以继续；读取或保存未提交视图不能改用另一个窗口。

## 保存与批次

`edit_chapter_visual_plan_draft` 的 `operation` 支持 `batch`，包含 1–100 个有序操作，不允许嵌套批次。单操作沿用同一入口。整个批次验证成功才保存；失败不会留下前半批修改，无变化不会增加方案修订或撤销步骤。

示例中的项目、来源章节、记录、版本及图片点 ID 必须替换成读取接口返回的值：

```json
{
  "project_id": 42,
  "source_chapter_id": 11,
  "record_id": 900,
  "expected_revision": 3,
  "operation_id": "a-unique-operation-id",
  "operation": {
    "kind": "batch",
    "operations": [
      { "kind": "set_frame", "frame": { "width": 1920, "height": 1080 } },
      { "kind": "move_point", "point_id": "point-from-read", "at_ms": 1500 }
    ]
  }
}
```

已保存版本的操作不需要 `editor_revision`。依赖未保存视图时，先读取原视图的编辑版本，再走编辑器工具。来源快照、状态或版本链失效时必须重新读取；即使省略 `expected_source_hash`，保存事务也会校验来源版本。

调用方重试同一请求时保留 `operation_id`。同一 ID、同一请求返回原回执；同一 ID 用于不同请求会失败。Agent Host 在工具没有提供该字段时使用持久执行 ID。幂等执行恢复可以复用该执行原有的已消费审批，不会生成第二次批准或改写消费时间。

## 校验与确认

完成草稿后，先调用 `validate_chapter_visual_plan`，使用 `mode: "confirmed"` 及最新保存的记录和版本。草稿校验允许未完成的场景绑定，不能据此宣布可以确认。确认标准校验返回 `validation.valid` 和首个错误的 `diagnostics.path/message`；修复后使用编辑回执中的新版本再验。

转场不连续时，错误会定位到 `segments[i].scene_binding`，给出镜头段 ID、错误的 `from_scene_profile_id`/`to_scene_profile_id`、实际值和相邻镜头要求的值。转场起始场景须等于前镜头的结束场景，结束场景须等于后镜头的开始场景；修正绑定应保留其余镜头与素材信息。

用户要求确认时，校验通过后可调用：

```json
{
  "input": {
    "project_id": 42,
    "source_chapter_id": 11,
    "record_id": 900,
    "expected_revision": 4
  }
}
```

确认与界面按钮复用同一业务入口，校验权限、来源、最新版本、场景和图片引用，并同步下游失效范围。确认失败保留草稿，错误反馈给 Agent 供修正；版本冲突需要重读，不能覆盖。工具不会保存窗口中的未提交输入。只有成功返回 `visual_plan.record.status: "confirmed"` 才算完成，等待审批不算已确认。

## 并发、撤销与恢复

保存记录与 `visual_plan_edit_receipt` 在同一事务提交。提交按目标项目串行化，模型推理不持有这个锁。回执包含提交前后版本和按稳定对象 ID 表达的字段变化。

不同对象或字段的修改自动合并；同字段、删除与编辑、相邻时间点或镜头边界依赖冲突时拒绝覆盖。保存回包抵达时若本地又产生冲突，已提交版本和本地输入都会保留，自动保存暂停，并暂停该工作区仍在执行的导演 Agent。界面展示双方值，由用户选择冲突字段；非冲突字段仍合并保留。

一次批次对应一次撤销，保留 40 步会话历史。撤销应用反向字段变化，不用整份旧方案覆盖后续人工编辑。

Web 和桌面 HTTP 模式通过 `/visual-plan-edits` SSE 接收回执；原生 invoke 模式使用相同持久游标读取回执。初始游标与加载的方案版本一致，重连补齐后续事件，重复事件不重复应用。编辑事件与生成任务事件分别按各自合同校验帧大小。

来源或保存记录被替换、删除，或者权限变化时，旧写入基线失效。用户可以保留本地备份后载入新版本。

## 会话兼容

章节会话键包含目标项目，多个视频引用同一来源章节不会共享导演会话。CLI、浏览器和委派入口统一资源绑定信息，复用会话不扩大显式工具白名单。

编辑器来源协议为版本 2，响应必须使用实际窗口实例 ID。迁移保留历史消息和结果；已有视频绑定升级到新键，无法明确归属视频的旧文本项目导演会话归档为只读，旧进行中操作不会自动重放。
