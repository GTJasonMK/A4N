# 正文事实反馈

章节分析完成后更新当前资料；低频资料默认累计 **5 个不同章节**后归纳。可在项目概览或写作台分析页的“正文事实反馈”面板调整周期。

| 资料 | 更新方式 |
| --- | --- |
| 角色属性、位置、目标和行为 | 每章同步，明确正文事实可以修正手工填写的当前值，保留事件历史 |
| 物体外观、状态、位置和场景事实 | 每章同步，沿用已有身份、别名、媒体和手工创作用途 |
| 伏笔内容与进展 | 每章同步，支持部分揭示、回收、明确否定，使用已有 ID 和原文证据 |
| 世界观、角色说话特征和已发生的成长 | 按周期归纳，局部修改有变化的字段 |
| 蓝图梗概和未来剧情规划 | 生成可查看的建议，由作者采用 |

核心规则、技术或魔法约束发生变化、已知世界事实出现矛盾，或完成分部末章时，提前归纳。周期未到时，新正文事实已进入后续写作上下文。

普通正文保存会撤回失效来源和派生状态，模型调用由章节分析或手动反馈操作触发。相同正文与事实的重复分析保留已有反馈；没有资料变化时保留当前蓝图版本。

资料变更记录保存来源章节、正文/分析修订、原文证据和修改前后值。修改旧章后撤回受影响的反馈，并允许后续章节重新同步。角色手工事件、身份和媒体保留；历史上下文按目标章节读取。

“立即归纳”处理已完成分析的事实，“全书重建”按章节重建并归纳末尾不足周期的部分。失败后通过“继续反馈”或已有工作流恢复入口继续；已写入的事实与检索索引分开重试。

旧项目通过后续章节分析逐步接入；用户可以主动全书重建。项目族包升级为 `project_family_v6`，保留反馈记录、角色时间线和周期，同时接受 `project_family_v5`。普通项目副本保留周期，以待分析状态重新建立反馈覆盖。

CLI 提供以下 Host 命令，可用 `a4n capabilities` 查看当前合同：

- `get_project_fact_feedback`：读取覆盖、运行状态和变更记录。
- `preview_project_fact_feedback_request`：预览归纳请求。
- `run_project_fact_feedback`：`mode` 为 `consolidate` 或 `rebuild`；恢复时传入 `workflow_run_id`。

归纳周期通过已有 `update_project` 的 `fact_feedback_interval_chapters` 更新。数据库新增迁移 `body_fact_feedback`，部署前需要运行项目的数据库迁移入口。

主要实现位于 `a4n-orchestrator/src/fact_feedback/`、`a4n-db/src/fact_feedback/` 和前端 `FactFeedbackPanel.tsx`。回归入口为 `scripts/tests/run_fact_feedback_cli_e2e.py`，覆盖周期、重复分析、错误证据、恢复、正文撤回、全书重建及项目传输。
