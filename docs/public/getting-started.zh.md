# 从源码开始第一次创作

[返回 README](../../README.md) · [English](getting-started.en.md) · [配置与本地数据](configuration.zh.md)

当前版本通过源码运行。本页先完成 Web 端的首次登录与章节分析，再介绍桌面启动方式。所有相对路径都以你的**开发工作树根目录**为准；采用项目的多工作树布局时，在 `work/debug`、`work/integration` 或自己的 `work/agent/<topic>` 中运行，不在 Git 协调根目录构建。

## 1. 准备环境

- Rust toolchain；当前 CI 使用 Rust 1.95.0。
- Node.js 22、npm，以及 Git。
- PostgreSQL 16+；下文使用项目的 Docker Compose 开发数据库，需要 Docker 与 Compose。
- Linux 桌面构建另需 WebKitGTK、GTK、Ayatana AppIndicator 等系统开发库；按 [Tauri 平台前置条件](https://v2.tauri.app/start/prerequisites/)安装。

先获取仓库访问权限并检出源码。进入工作树后：

```bash
cp .env.example .env
npm --prefix frontend ci
```

编辑 `.env`，取消相应条目的注释并填写真实值：

```dotenv
A4N_DATABASE_URL=postgres://a4n:a4n@127.0.0.1:5432/a4n
A4N_JWT_SECRET=replace-with-a-long-random-secret
A4N_BOOTSTRAP_ADMIN_USERNAME=writer
A4N_BOOTSTRAP_ADMIN_EMAIL=writer@example.invalid
A4N_BOOTSTRAP_ADMIN_PASSWORD=replace-with-a-strong-initial-password
```

`replace-with-…` 都是占位符，启动前必须替换。可用 `openssl rand -hex 32` 生成 JWT secret。数据库地址对应仓库自带的开发 Compose 配置；使用现有 PostgreSQL 时改成自己的连接串，并事先创建数据库。不要提交 `.env`。

并行工作树必须使用独立数据库、Web/Vite 端口、Qdrant collection 和数据目录。端口配置见[配置指南](configuration.zh.md#运行地址与隔离)。

## 2. 安装运行依赖并启动

```bash
./scripts/dev/dev-db.sh up
./scripts/dev/setup-onnxruntime.sh
./scripts/dev/setup-qdrant.sh
./scripts/run.sh --server
```

- ONNX Runtime 的版本由 `tools/onnxruntime/VERSION` 固定，默认安装在 `~/.local/share/a4n/onnxruntime/<version>`，不在 Cargo 缓存里。构建脚本检查版本，缺失时会明确停止。
- Qdrant 使用项目固定版本。启动脚本会复用配置地址上健康的服务，或在本机启动已安装的版本；并行环境需事先配置独立地址与存储。
- 首次编译可能较久。启动入口会检查数据库、JWT、前端和所需运行依赖；按明确错误修正后再运行，不绕过检查。
- 打开启动日志中给出的 Web 地址，默认 API/静态页面服务地址为 `http://127.0.0.1:8080`。如果你设置了其他地址，以实际日志为准。
- 空数据库会使用 `.env` 中的三个 `A4N_BOOTSTRAP_ADMIN_*` 值建立首个管理员。使用该账号登录；用户已存在时不会重新创建，也不会重置密码。

## 3. 配置创作模型

1. 打开**设置 → LLM 服务 → 新增 LLM 配置**，填写实际支持的模型、接口地址和访问密钥并保存，将这项本机配置设为默认。Agent 调用协议按模型能力选择；演示使用支持原生工具调用的兼容服务。
2. 打开**设置 → 嵌入模型**，创建支持的 Embedding 配置。使用远程服务时，模型和向量维度必须与服务一致；选中该配置并**设为默认**。管理员还可在**管理员 → 配置 → 嵌入**维护服务器默认配置；本机覆盖和服务器配置是不同作用域。
3. 确认 Qdrant 可用，再开始依赖资料索引的分析流程。已有项目更换 Embedding 模型或维度后，应按界面提示重建相应索引。
4. 图片和视频服务可以稍后配置；它们不是录入第一章的前提。

示例截图中的模型是确定性测试 Provider，不是可向外部服务提交的模型名称。自己的创作请填写服务真实支持的模型。

## 4. 完成第一章及其反馈

在项目列表点击**创建项目 → 自由创作**。将项目命名为《山海之间》，按需要手工填写或生成故事蓝图、人物与章纲。进入**已生成章节 → 导入章节**，填入序号 `1`、标题《未寄出的信》和以下虚构示例：

> 雨水沿着末班车的车窗斜斜滑下，林岚把那封没有邮戳的信翻到第三遍。信封正面写着她的名字，背面却标着十年后的日期。十二点前进入旧车站钟楼，否则整座城会失去七分钟——字迹和她一模一样。
>
> 列车驶入废弃站台旁的弯道时，车厢灯忽然熄灭。黑暗里先响起一声机械钟鸣，接着所有人的手机同时亮起，时间从二十三点四十二分跳回二十三点三十五分。乘客没有察觉，仍重复着熄灯前的动作；只有林岚掌心那只旧怀表，秒针逆着刻度走了整整一圈。
>
> 她在旧车站下车。雨幕后的钟楼四面表盘停在不同时间，最慢的一面恰好落后七分钟。站厅深处传来金属碰撞声，修表师周衡提着工具箱从封闭通道里走出。他看见信封角落的齿轮暗记，神色第一次失去从容。
>
> “这个记号十年前就该被烧掉了。”周衡说。
>
> 林岚没有把信交给他，只展开其中最后一页。纸上新浮出一行被雨水般的墨迹浸透的字：别相信替你校准时间的人。与此同时，钟楼顶端传来第二声钟鸣。站厅广告屏里的画面倒退七秒，周衡身后的影子却没有跟着移动。林岚合上怀表，沿着封闭通道向地下走去。她知道信中的第一个预告已经发生，而距离午夜只剩十八分钟。

保存后打开章节写作台，在**分析**页签发起分析。等待任务结束，查看“本章资料同步状态”，并检查提取到的事实、人物与伏笔是否符合正文。不同模型的提取结果可能不同。

继续创作时，用章纲或写作指令提出与怀表相关的下一场景，检查准备的上下文与生成内容。也可以在**正文**页签打开**写作助手 → 优化**，要求“优化表达与节奏，保留剧情事实”，审阅补丁后再确认写回。

完成检查：

- 第一章保存后重新打开仍能读到正文。
- 分析任务及资料同步显示实际完成；若失败，查看原因，并仅在界面允许时继续或重试。
- 档案与伏笔能追溯到对应内容；不要把模型提取结果直接当作正确事实。
- 优化建议在作者确认前没有改写正文；修改源内容后，过期建议应重新审阅。

## 5. 桌面、CLI 与更多创作

同一份环境准备完成后，桌面入口为：

```bash
./scripts/run.sh
```

需要固定的稳定调试进程、避免文件变化触发重启时：

```bash
./scripts/run.sh --no-hot
```

桌面默认使用本地 Server。未设置 `A4N_WEB_ADDR` 时优先选择 `127.0.0.1:8080`，占用时使用空闲端口；显式设置地址后端口占用会报错。Native 模式及其他参数以 `./scripts/run.sh --help` 为准。

图片、漫画、视频和互动叙事可从项目内工作台或派生项目入口继续；为所需模态配置服务，保留来源关联。章节派生视频从派生项目的章节工作流生成；自由视频画布单独编排素材，当前画布生成节点仅支持自由视频项目。CLI 用法见[无前端 CLI](configuration.zh.md#无前端-cli)。构建、测试与贡献见[贡献指南](../../CONTRIBUTING.md)。

## 遇到问题

| 现象 | 先检查 |
| --- | --- |
| 启动前就退出 | 首条明确错误；数据库、JWT、ONNX/Qdrant 与系统库是否满足入口检查 |
| 首次无法登录 | 三个 bootstrap 变量是否同时配置；数据库是否已有账号 |
| 文本请求失败 | Provider 的模型名、地址、个人密钥、额度与超时；不要在 Issue 中贴密钥 |
| 分析保存了但资料同步失败 | 失败步骤、Embedding 默认配置、维度与 Qdrant；保留错误信息后再判断能否继续 |
| 地址被占用 | 关闭自己的冲突实例或配置独立端口，不终止他人的服务 |
| Linux 视频显示异常 | 阅读[Linux 播放设置](configuration.zh.md#linux-桌面视频)；记录系统与驱动、实际行为 |

反馈时附当前提交、操作步骤及脱敏后的错误。安全问题使用[安全策略](../../SECURITY.md)中的私密渠道。
