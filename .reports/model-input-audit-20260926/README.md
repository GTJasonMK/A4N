## 缓存编排

按实际复用对象选择顺序。视频/拍摄先放固定公共约束和当前阶段规则，再放公共资料、当前来源段落和任务参数；裁剪后较短且变化的原文窗口不会挡住较长的阶段规则。角色/场景同步的完整章节在多实体、多阶段间相同，因此保持“公共 system → 共享章节 → 角色/场景状态 → 必需阶段依赖与指令”。视频优化则把固定资产合同置于变化的源提示词之前。

继续使用已有 project + model 缓存路由、协议适配和有界并发。模板版本、源身份和内容指纹保存在非模型元数据，仍参与断点判断；删除模型可见的 hash 包不等于删除失效机制。视频来源包在多个阶段使用同一名称和相同正文表示。

OpenAI/Responses 的显式缓存元数据只在配置 `extra_body_json.prompt_cache_options` 后发送；空对象沿用现有自动选择显式/隐式的规则。Anthropic 使用既有 cache_control 映射。没有给未选择这些选项的网关强行添加扩展字段；这类请求的改进是稳定文本本身，不能称为已启用指定缓存协议。

裁剪优先于缓存比例。不同镜头真正需要不同段落时，发送各自必要段落；同阶段规则和相同输入集合尽可能共享完整前缀。没有为了提高百分比扩大上下文、补无用填充或增加“预热”模型请求。跨镜头、跨角色和 Agent 状态变化的前缀稳定性由请求级测试验证；实际服务商命中率还受模型、路由、时序和缓存策略影响，不能由源码推导“全局最高”。

## 边界和仍需注意的事项

- 没有重新调用付费远端模型；实际生成质量与真实缓存命中率没有做 A/B。官方缓存文档抓取被 403 拒绝，因此未宣称已联网确认任何当前阈值或折扣。
- token 估算保留安全的 UTF-8 字节上界。历史样本回归不足以替代不同模型的 tokenizer；未把估算除以固定系数。
- 不同用途相同内容只有在业务语义也允许时才合并。权限、工具 schema、推理签名回放、有效历史、引用身份和媒体绑定没有作为“重复”删除。
- 依赖旧 source_spans/text_anchors 列表或布局 v1 输出的项目自定义模板，需要同步到本轮带标记原文和布局 v2 合同；不支持的旧输出会明确报错。
- 续接视频当前可复用的不可变文字证据是该视频实际使用的生成提示词；它不等同于实际尾帧的视觉观察。输入明确区分这一点，实际尾帧继续作为视频模型的画面依据。
- Galgame CG 的身份充分性、三视图设定图与单立绘用途、部分后端 fps/negative 原生能力仍需按实际模型与产品用途验证，见媒体报告。没有用文本压缩掩盖这些能力边界。
- `debug` 存在其他会话并行修改；本任务保留为工作区修改，不整体提交或回滚。
