  ### 5. [已解决 2026-07-30] 共享片段规划与模式级参数互相冲突

  当前共享规划参数只有章节级存储键 `chapterStorageKey:segment-plan-options`；不存在按
  `workflowMode` 分叉的生成参数或参考图本地状态。每个片段的模式、参考图、媒体和生成参数
  统一保存在其 `VideoSegmentExecutionRecipe` 中，切换模式只更新目标片段 recipe。

  片段生成时，后端以当前正式共享规划中的 recipe 覆盖客户端传入的 workflow mode、style、
  language、duration、aspect ratio 和引用图片 ID。recipe 写入数据库时也统一经过
  `metadata_with_video_segment_recipe` 与 `validate_for_plan`，任何与共享规划 style、duration
  或 aspect ratio 冲突的旧客户端/API 请求都会显式失败，不能再写入损坏状态。

  当前约束收敛为一个来源：共享规划拥有 style、duration 和 aspect ratio；片段 recipe 只保存
  模式及其媒体配置，并必须与共享规划一致。

  ### 6. [已解决 2026-07-30] 旧提示词、旧合同、旧规划和其他语言记录会混入卡片

  卡片列表与当前选中提示词现在共用 `currentFinalVideoPromptMatchesSegment`，统一检查：

  - 最终提示词类型和当前 workflow mode；
  - 当前模式的正式合同版本；
  - `source_prompt_type=frame_segment_plan`；
  - 当前共享规划、片段编号和 recipe fingerprint；
  - 当前正文、拍摄剧本和规划的 execution base identity；
  - metadata 与 execution identity 中一致的输出语言；
  - 完整的 frame set 和 generation asset execution identity。

  `VideoPromptSetupPanel` 接收的已是这组当前有效记录，因此旧合同、旧规划、旧正文、错误语言和
  identity 不完整的记录不会出现在 variants 中，也不会让生成按钮误判为“方案已存在”。持久化的
  旧 selected prompt ID 不在有效集合时会直接重置到当前片段最新有效提示词，不再先显示旧记录再
  回退到另一条记录。

  后端 target 预检同样复用正式合同映射、完整 execution identity 校验和片段 identity 匹配；
  只有当前规划、当前 recipe、当前合同和当前语言的完整最终提示词才算“已存在”。旧同编号记录
  不会再阻止当前片段生成或重新生成。

  ———

  ### 7. [已解决 2026-07-30] 旧规划视频可以被当前规划采用并进入混合成片

  前端候选视频现在由 `videoExecutionSegmentIdentityMatchesVideo` 过滤，必须同时匹配当前共享
  规划 execution base identity、规划 ID、片段编号和 recipe fingerprint；工作区不再按
  `shot_number` 展示全部历史视频。采用操作还会在请求前重复校验当前片段身份。

  后端采用入口要求客户端明确提交当前 `segment_plan_prompt_id + shot_number`，随后重新读取当前
  正式规划和 recipe，并校验视频的项目、章节、状态、文件、workflow mode、片段编号及完整
  execution identity。采用状态只写入当前规划片段 recipe 的 `adopted_video_id`；运行时代码已不再
  使用 `selected_for_segment` 双重状态。

  mixed 成片会逐片段读取当前规划 recipe，并再次校验每个 adopted video 的当前规划和 recipe
  identity；缺失、重复、旧规划或已失效视频都会显式阻止合成。迁移修复也会先清除弱匹配遗留的
  `adopted_video_id`，只保留或恢复完整 identity 精确匹配的视频。

  ———

  ### 8. [已解决 2026-07-30] 混合成片不验证当前规划，也不验证完整覆盖

  mixed 成片已不再依赖 `selected_for_segment`。前端从当前共享片段规划的全部卡片
  计算 adopted video 和缺失片段；任一片段未采用视频时，生成按钮禁用，处理函数也会明确拒绝。

  后端在成片列表、缓存加载、插入与推送路径统一调用
  `current_mixed_adopted_video_ids`，并验证：

  - 当前章节正文对应的当前共享片段规划。
  - 规划中每个 segment 都恰好有一个 recipe 和一个 adopted video。
  - adopted video ID 不重复，视频已完成且文件可用。
  - 视频的项目、章节、片段号、模式与完整 execution identity 均匹配当前规划和 recipe。

  本轮又修复了一个当前规划选择残口：原逻辑先选所有已完成规划中 ID 最大的记录，
  再校验正文 identity，会让较新但已失效的规划挡住与当前正文匹配的较早规划。
  现在通过唯一的 `current_shared_segment_plan` 先按当前正文 hash 过滤有效规划，再取其中 ID
  最大的一条；显式规划校验与 mixed 成片共用这一条规则。

  因此，缺失中间片段、重复采用、旧规划视频或失效 identity 都会明确阻止 mixed 成片。

  ———

  ### 9. [已解决 2026-07-30] 参考媒体草稿、目标片段和锚点都没有绑定稳定片段身份

  参考媒体目标已不再使用章节级共享指针。选中片段、选中提示词、选中视频和待恢复视频任务
  的存储 key 现在都包含当前规划身份：生成中草稿使用 workflow run ID，正式规划使用
  segment plan prompt ID。规划切换后不会复用上一份规划的目标指针。

  参考媒体草稿使用以下组合身份：

  - 当前规划身份（workflow run ID 或 segment plan prompt ID）。
  - `segment_number`。
  - `source_shot_id`。
  - `segment_index_in_shot`。

  切换片段会先保存当前身份下的草稿；规划或稳定片段身份变化时，界面从新 recipe
  重新加载，旧脏草稿不能写入新规划。生成中草稿缺少 workflow run ID 时会明确失败，
  不再 fallback 到旧正式规划。

  本地文件对象本身不能跨刷新序列化；现在 recipe 会保留文件 hash、文件名和 MIME 类型，
  界面明确标注“刷新后需重新选择该文件”，生成和导入也会拒绝缺失本地文件的不完整输入，
  不再伪装成已完整恢复。

  参考媒体预览、生成和外部视频导入都要求 `segment_plan_prompt_id` 对应当前共享规划，
  再从该规划读取目标片段 recipe，校验 reference_media 模式并写入完整 execution identity。
  前端提示词列表也只保留当前规划和当前 recipe fingerprint 匹配的记录，不存在旧提示词
  fallback。

  ### 10. [已解决 2026-07-30] 切换卡片模式会让 UI 解除 busy，但不会取消后端任务

  该问题描述对应的旧实现已不存在。当前 `videoActionScopeKey` 只使用稳定的章节数据 scope，
  不再包含当前卡片的 workflow mode；切换首尾帧、首帧续接、分镜、参考媒体或 Chat 模式
  不会改变正在运行任务的 action scope。

  busy 状态已收敛到 `VideoTab` 的单一 `actionBusyRef`。
  `useVideoPromptGenerationActions` 和 `useVideoRecordActions` 不再拥有“scope 变化就清空
  busy/task ID”的 effect，也不会因卡片模式变化调用 `setActing(null)`。

  卡片的模式和媒体引导控件统一使用：

  `acting != null || chapterGenerating || savingRecipe`

  作为 busy 条件。任何生成或记录操作进行中，卡片模式选项都会禁用，用户不能通过
  切换模式制造第二个前端任务。

  generation 进度统一由 `runGenerationProgressTaskThen` 保持真实 `GenerationTaskHandle`，
  `waitForTerminal` 持续更新进度和模型实时文本；点击停止时唯一调用
  `generationClient.cancel(handle)`。卡片视图变化不会关闭进度对话框或伪装成任务已结束。

  ### 11. [已解决 2026-07-30] “生成全部”实际上会提交所有模式、所有规划、包括已有视频的提示词

  该问题描述对应的“生成全部”入口已在当前版本中移除，现在没有批量提交本章所有视频提示词的 UI 或 handler。

  当前流程是“从片段卡片选中当前片段，再生成该片段的提示词”：

  - `VideoPromptSetupPanel` 只提供卡片级的帧提示词或最终提示词操作，不再显示“生成全部”。
  - `useVideoPromptGenerationActions` 接收的 `allFinalVideoPrompts` 只用于当前片段的运行中状态检查和变体汇总，并不作为批量提交集合。
  - 目标提示词按当前卡片的 `shot_number`、workflow mode 和 recipe 语言筛选，只能影响当前所选方案。
  - 已有视频的提示词在重新生成时会被明确拒绝，不会静默重复提交。

  前端目前只能生成当前片段的批次提示词，这与“生成全部片段”是两个不同的语义；后者已被移除，不再存在所述重复成本风险。

  ### 12. [已解决 2026-07-30] 选中提示词和选中视频仍按模式持久化，不按片段持久化

  - 项目与章节身份。
  - 当前片段规划身份（草稿 workflow run ID 或正式 segment plan prompt ID）。
  - 当前 `segment_number`。

  `chapter + workflowMode`。切换规划或片段后会加载对应身份的选中状态。

  候选列表与预览也已使用同一过滤链：

  - 最终提示词必须匹配当前规划、当前片段、当前 recipe fingerprint、模式和语言。

  ## 应该收敛成的唯一状态模型

  不要继续在现有全局 workflowMode 外面加 ref、fallback 或兼容判断。最小正确模型应该是：

  当前共享片段规划
  └── stable segment identity
      └── segment execution recipe
          ├── selected workflow mode
          ├── style / duration / aspect / language
          ├── reference images
          ├── frame prerequisites
          ├── final video prompt
          ├── media guidance
          ├── reference media bindings / draft
          ├── candidate videos
          ├── adopted video
          └── active generation task

  必须满足以下不变量：

  1. 卡片由当前片段规划的 segments 构建，不由 video_prompt 构建。
  2. 每个 segment 只有一个持久化的当前 execution recipe。
  3. workflowMode 不再是章节业务状态，最多只作为页面过滤器或新片段默认值。
  4. 所有目标操作使用稳定的 plan identity + segment identity，不能只用 shot_number。
  5. 帧提示词、帧图片、最终提示词、媒体引导和参考媒体都归属于同一 recipe。
  6. generation task 归属于 recipe，切换 UI 不得清除或脱离正在运行的任务。
  7. adopted video 必须验证当前 plan/segment identity。
  8. mixed assembly 必须验证当前规划每个 segment 恰好有一个 adopted result。
  9. 旧规划数据只能作为历史记录展示，不能自动参与当前生成、采用和成片。
  10. 删除旧的章节级“生成下一批”入口、隐藏 target ref、无效 reference-media 入口和未使
     用派生状态。
